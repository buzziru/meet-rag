# 서브에이전트 작업자 풀

항목 여러 개(질의, 검수 행 등)를 서브에이전트 여러 개에 나눠 맡길 때 쓴다(G2 오답 검토, G3 재판정 등). 근거는 ADR-0020·0024·0025다.

## 띄우기

- 에이전트는 백그라운드로 동시 3개(최대 4개)까지 띄운다. 로컬 자원과 메인의 결과 확인이 병목이라 그 이상은 빨라지지 않는다
- 메인이 남은 작업 큐를 들고, 작업 하나가 끝날 때마다 새 에이전트를 띄워 칸을 채운다. 끝난 에이전트를 다시 쓰지 않는다. 앞 작업의 입력이 맥락에 남아 다른 항목과 섞인다(S8 파일럿에서 6건 묶음 에이전트가 conf-0012를 conf-0017로 오판)
- 판정 기준의 일관성은 고정된 지시 파일과 코드 판정이 맡는다. 에이전트끼리 소통하게(팀) 하지 않는다
- 실행 단계마다 부르기 전에 항목 수와 예상 소요 시간을 보고하고 승인받는다(SPEC 자원 제약). API 과금이 없어도 승인 대상이다

## 프롬프트

- 정의된 작업자가 없으면 general-purpose를 쓴다. 훅이 없어 범위 밖 읽기를 막지 못하므로, 프롬프트에 읽기·쓰기 경로를 항목 목록으로 한정하고 "항목마다 지시를 처음부터 읽는다"를 넣는다(G3 재판정에서 다른 항목 입력을 읽었고, 두 번째 입력부터 지시를 건너뛰었다)
- 금지 경로를 이름으로 적는다: `data/processed/`의 질의 파일, `data/splits/`, `data/runs/`(검색 결과), 다른 작업의 출력. 평가 질의나 검색 결과를 읽은 작업자 출력은 결과를 그쪽으로 기울인다(SPEC 누수 방지)
- 일회성 작업은 이대로 두고, 반복해 쓰는 작업자만 F 흐름으로 정의(`.claude/agents/`)를 만든다(PR #43 코멘트). 정의에 frontmatter 훅을 달면 IDE 확장(Cursor·VS Code) 세션에서 Agent 도구로 부른 작업자에는 훅이 적용되지 않으니, 훅 동작은 CLI 세션에서 확인하고 그 작업자는 CLI 메인 세션에서 띄운다(ADR-0021)

## 결과 확인

- 에이전트가 끝나면 반환 메시지와 출력 파일 존재를 대조한다. 출력이 없는 항목은 큐로 되돌린다. 입력을 끝까지 읽지 못해 건너뛰었다고 보고한 항목은 같은 입력에서 또 실패하므로 다시 띄우지 않고, 진행 기록에 적고 사용자에게 보고해 처리를 정한다
- 판정형 작업자(통과·불통과 같은 분류)의 결과로 데이터를 빼거나 남길 때는, 같은 입력을 다시 판정하면 결과가 갈릴 수 있다는 점을 사용자에게 알린다. 판정을 두 번 한 항목이 있으면 실행 간 일치율을 결정 전에 함께 보고한다(G3 재판정은 106건 중 8건이 실행마다 갈렸다)

## 작업 큐 기록

작업 목록과 큐 기록은 `scripts/worker_queue.py`로 한다. 메인이 항목을 손으로 옮기다 항목을 빠뜨린 일이 있어(G3 작업 274·290) 스크립트에 맡긴다.

- `plan`: 대상 항목 id 전체에서 출력이 아직 없는 것만 작업 단위로 묶어 작업 목록 jsonl을 쓴다. 작업 목록 파일은 단계·회차마다 새로 둔다(있는 파일을 덮어쓰지 않는다)
- `start N`: 작업 N의 항목 중 출력이 없는 것만 출력하고 `running`을 기록한다. 에이전트 프롬프트의 항목 목록은 이 출력을 그대로 붙인다(건너뛰었다고 보고한 항목만 뺀다)
- `done N`: 출력 파일을 대조해 `done`이나 `partial`(빠진 항목)을 기록한다. 빠진 항목은 `start N`을 다시 해 새 에이전트로 띄운다
- 큐 파일은 `_workspace/{작업}_queue.jsonl`이다. 큐는 사람이 진행을 보고, 세션이 끊겼을 때 끝나지 않은 작업을 찾는 기록이다. 남은 작업의 기준은 출력 파일 상태(`worker_queue.py status`)이고, 큐와 다르면 파일 상태를 따른다(사용자 결정 2026-10-07). 세션이 끊겨 큐에 `running`이 남으면 출력 파일로 정리한다(있으면 `done`, 없으면 대기)

## 중단

사용자가 중단을 지시하면 새 작업을 띄우지 않고, 실행 중인 작업이 모두 끝날 때까지 기다린다. 에이전트를 강제로 멈추지 않는다(사용자 결정 2026-10-07). 끝난 작업을 큐에 기록하고 남은 수와 재개 절차를 진행 기록과 `docs/STATUS.md` "실행 중 작업"에 적는다.
