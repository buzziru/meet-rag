# EXP-009: 임베딩 모델을 snowflake-arctic-embed-l-v2.0-ko로 (H6)

## 가설
- 공개 한국어 검색 벤치마크에서 `dragonkue/snowflake-arctic-embed-l-v2.0-ko`는 KURE-v1과 같은 표 비교 세 곳 모두에서 앞선다(MTEB(kor, v2) Retrieval 평균 nDCG@10 0.7653 대 0.7616 등, `docs/research/embedding-candidates.md`). dense 목록이 나아지면 RRF 결과의 single-doc Recall@5가 오른다
- 벤치마크 차이(+0.4\~1.4%p)가 SPEC 채택 기준(+1.0%p)과 비슷하고 도메인(구어체 회의록)이 달라, 우리 데이터에서 차이가 없을 수도 있다

## 기준 실험
- EXP-008 (hybrid + 조건 목록 + 최다 일치 필터 + 안건 법률명 조건). D-27
- 기준 순위: single-doc `data/runs/kure-v1-fixed-512-64-hybrid-cond-filter-law-dev-full.csv`(SHA-256 `0a64961758eed7a78162e989c5f44d64d3a69453a5f9fd4f9ccf024908e375d2`, EXP-004와 같음), multi-doc `data/runs/kure-v1-fixed-512-64-hybrid-cond-filter-law-multidoc.csv`(SHA-256 `b686e3e77ecc0ea74e4be0eea2a1b9ff9a9eb4415e3147caa28cad0974914bf7`)
- 백로그 H6의 첫 EXP다(SPEC 가설 단위 중단의 셈에 넣지 않는다). 채택이 아니면 조사 문서의 후보로 다음 변형을 정한다(사용자 결정 2026-10-13)

## 바꾸는 것
- dense 임베딩 모델: `nlpai-lab/KURE-v1` → `dragonkue/snowflake-arctic-embed-l-v2.0-ko`(revision `55ec6e9`). 질의에만 `query: ` 접두를 붙인다(모델 카드 규약, `embedding.query_prompt`). 정규화·float16 임베딩은 같다
- 그 밖은 EXP-008과 같다
  - 청크: KURE-v1 인덱스의 `chunks.jsonl`을 그대로 쓴다. 두 모델의 토크나이저가 같다(XLM-R, 어휘 250,002개 일치, 청크 2,000개 토큰화 일치). 512/64 청크는 KURE-v1 기준으로 고른 값이다(S4)
  - BM25 색인(`bm25-kiwi-v1`)은 청크가 같아 복사해 쓴다. 조건 파일(`-law`)·RRF·필터는 그대로다
- 인덱스 `data/index/snowflake-ko-fixed-512-64/{scope}`, 질의 임베딩 `data/index/snowflake-ko/`, 순위 파일 `snowflake-ko-fixed-512-64-hybrid-cond-filter-law-{층}.csv`. KURE-v1 산출물을 덮어쓰지 않는다
- 파라미터는 위 값으로 고정하고 dev-full 결과를 보고 조정하지 않는다

## 함께 보고하는 것 (판정에 쓰지 않음)
- dense 단독 순위(`retriever.type=dense retriever.run_name=null`)를 KURE-v1 dense 단독(S5, `kure-v1-fixed-512-64-dev-full.csv`)과 비교한다. 임베딩 자체의 개선과 기존 결합(RRF·필터)과의 상호작용을 나눠 보려는 것이다(사용자 결정 2026-10-13). dense 단독은 오르는데 hybrid가 오르지 않으면 RRF 균형(H13)의 순서를 다시 정할 근거로 쓴다
- 운영 비용: 모델 크기·구조가 같아 질의 임베딩 비용(CPU)과 인덱스 크기는 KURE-v1과 같을 것으로 본다. Colab 임베딩 처리량과 인덱스 크기를 실측해 적는다(D-26)

## 고정 조건
- SPEC 평가 프로토콜 v1 / config: `configs/exp/exp009.yaml`(EXP-008 설정을 불러와 임베딩만 바꾼다)
- 코퍼스·질의 임베딩은 Colab GPU(E절, 승인 대상)에서 하고, 검색·채점은 로컬 CPU에서 한다. VM에는 청크 파일과 dev 질의만 담은 파일(summary_q dev, G3)만 올린다

## 판정 기준 (실행 전 확정)
H6은 [메타데이터] 가설이 아니므로 SPEC 판정 절을 그대로 옮긴다. 비교 기준은 EXP-008이다.

- dev-full Recall@5 차이를 회의 단위 paired bootstrap(10,000회, seed 20260929)으로 계산한다
- 채택: 95% 구간 하한 > 0 이고 점 추정 ≥ +1.0%p
- 기각: 95% 구간 상한 < 0
- 보류: 그 밖
- multi-doc은 관찰로 보고 판정에 쓰지 않는다(SPEC 보조 관찰)
- 단서(SPEC): 질의가 정답 문서를 보고 생성돼 어휘가 겹친다. 이 겹침은 BM25가 주로 잡으므로, dense 개선이 hybrid 결과에 작게 드러날 수 있다(추정)

## 실행
- (로컬) 인덱스 디렉터리 준비: `data/index/kure-v1-fixed-512-64/{dev-small,full}/chunks.jsonl`을 `data/index/snowflake-ko-fixed-512-64/{dev-small,full}/`로 복사하고, `full`의 `bm25-kiwi-v1/`도 복사한다
- (VM) `python -m rag.index +exp=exp009 index.scope=dev-small embedding.device=cuda embedding.dtype=float16` → 확인 뒤 `… index.scope=full …`, `python -m rag.search +exp=exp009 index.scope=full search.mode=embed-queries embedding.device=cuda embedding.dtype=float16`, `… search.queries=multidoc …`
- (로컬) dev-small: `uv run python -m rag.search +exp=exp009 index.scope=dev-small`(dev-small 질의 1,039개는 로컬 CPU로 임베딩한다)
- (로컬) `uv run python -m rag.search +exp=exp009 index.scope=full` → `uv run python -m rag.eval.compare --base data/runs/kure-v1-fixed-512-64-hybrid-cond-filter-law-dev-full.csv --cand data/runs/snowflake-ko-fixed-512-64-hybrid-cond-filter-law-dev-full.csv`
- (로컬) multi-doc: `… search.queries=multidoc` → `rag.eval_multi.compare`
- (로컬) dense 단독: `uv run python -m rag.search +exp=exp009 index.scope=full retriever.type=dense retriever.run_name=null` → `rag.eval.compare --base data/runs/kure-v1-fixed-512-64-dev-full.csv --cand data/runs/snowflake-ko-fixed-512-64-dev-full.csv`
