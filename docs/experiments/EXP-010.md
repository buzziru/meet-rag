# EXP-010: snowflake-ko 임베딩 + RRF dense 가중치 2 (H13)

## 가설
- EXP-009에서 snowflake-ko의 dense 단독 Recall@5는 KURE-v1보다 +2.25%p [+1.42, +3.15] 높았지만, RRF 결합 뒤에는 +0.50%p [−0.13, +1.14]로 줄었다. snowflake-ko hybrid가 놓친 질의 237개 중 29개(그중 13개는 dense 1위)는 dense 단독으로는 상위 5위였다. RRF에서 dense 목록의 가중치를 BM25·조건 목록의 두 배로 올리면 이 질의들이 살아나 hybrid Recall@5가 오른다
- 반대 방향의 위험: 지금 BM25 덕분에 맞히는 질의(dense가 놓친 정답)를 잃을 수 있다. dev-small에서 Recall@5 0.9856 → 0.9798(EXP-009 대비 5위 진입 0, 이탈 6)로 약간 떨어졌다. 포화된 층이라 판정 근거는 아니다(`notebooks/19_01_EXP010_devsmall확인.ipynb`)
- 살릴 수 있는 범위의 상한이 약 0.96%p라 SPEC 채택 기준(+1.0%p)에 닿으려면 잃는 질의가 거의 없어야 한다

### 판정과 별개로 미리 정한 결정: snowflake-ko 채택 (SPEC 규칙의 예외)
- EXP-009는 보류로 둔다. EXP-010의 판정이 채택이 아니어도 임베딩은 snowflake-ko로 바꾸고 SPEC 판정 규칙의 예외로 기록한다(사용자 결정 2026-10-13, 이 EXP 실행 전). RRF 가중치는 이 EXP의 판정을 따른다(채택이 아니면 [1, 1, 1] 유지)
- 이유(사용자)
  - 두 모델의 차이는 무엇을 먼저 골랐는가에 있다. snowflake-ko를 먼저 골랐다면 KURE-v1로 바꿀 근거가 약했을 것이다. 지금 KURE-v1을 유지하는 것은 판정의 일관성 측면에서는 의미가 있지만, dense 성능 차이(+2.25%p [+1.42, +3.15])를 보고도 KURE-v1을 고집할 이유는 없다
  - 앞으로 청크 변경 등 임베딩 위에서 하는 실험이 남아 있어, 더 나은 임베딩을 기준으로 두는 것이 맞다
  - 임베딩을 이미 마쳐 추가 비용이 없다(인덱스 크기·질의 임베딩 비용도 KURE-v1과 같다)
- 이 예외에서 감수하는 것: hybrid single-doc 개선은 확인되지 않았고(+0.50%p [−0.13, +1.14]), multi-doc 일부 지표는 작게 떨어졌다(EXP-009 `conf` Recall@5 −0.68%p [−1.43, −0.11], Recall@10 −0.40%p [−0.75, −0.11], Complete@10 −1.00%p [−1.83, −0.33])
- 기록: EXP-010 판정 뒤 DECISIONS에 적는다
