# EXP-006: KURE-Reranker-nano로 상위 후보 재정렬, GPU (H2)

## 가설
- EXP-004의 dev-full Recall@10(0.9450)이 Recall@5(0.9164)보다 2.9%p 높고, RRF 상위 20개 안에 정답이 있는 질의는 96.6%다. 한국어로 학습된 cross-encoder가 질의와 후보를 함께 읽으면 6\~20위의 정답(약 150개 질의)을 5위 안으로 올려 single-doc Recall@5가 오른다
- 같은 계산을 GPU에서 하면 질의당 지연이 배포에 쓸 수 있는 수준(EXP-005 Jev p95 0.83초와 비교할 수 있는 수준)으로 내려간다

## 기준 실험
- EXP-004 (hybrid + 조건 목록 + 최다 일치 필터). D-24. 기준 순위 파일은 EXP-005와 같다
- 백로그 H2의 두 번째 EXP, 첫 EXP(EXP-005, 기각) 뒤 첫 변형이다(SPEC 가설 단위 중단 셈 1회째). H2는 EXP-005 뒤 멈췄으나 사용자 지시(2026-10-13)로 cross-encoder를 GPU에서 다시 시험한다

## 바꾸는 것
- 재정렬 모델: Jev → `nlpai-lab/KURE-Reranker-nano`(revision `f3b3eff`, cross-encoder). EXP-005 첫 초안에서 CPU 지연 때문에 실행하지 않은 모델이다
- 실행 장치: Colab GPU, float16(`retriever.rerank.device=cuda`, `dtype=float16`)
- 그 밖(후보 RRF 상위 20개, 문서마다 dense 최고점 청크 하나, 재정렬 뒤 필터, 상위 10개)은 EXP-005와 같다. EXP-005가 만든 후보 쌍 파일을 그대로 쓴다
- 점수 파일 `…-cross-encoder.scores.jsonl`, 순위 파일 `…-hybrid-cond-filter-ce-{층}.csv`(`configs/exp/exp006.yaml`)
- 파라미터(모델, 깊이 20, 청크 입력, `max_length` 1024)는 위 값으로 고정하고 dev-full 결과를 보고 조정하지 않는다

## 고정 조건
- SPEC 평가 프로토콜 v1 / 인덱스·질의 임베딩 캐시·조건 파일·EXP-005 후보 쌍 재사용 / config: `configs/exp/exp006.yaml`(EXP-005 설정을 불러와 위 항목만 바꾼다)
- Colab에는 dev 질의만 담긴 후보 쌍 파일을 올린다(summary_q dev 3,016질의, G3 multi-doc 600질의). 외부 API 호출은 없다

## 지연 측정
- 질의 100개(seed 20260929, 첫 질의는 준비 실행으로 뺌)를 하나씩 재정렬해 질의당 시간을 잰다. 한 질의의 20쌍은 배치 하나로 계산한다(`rag.rerank` `mode=latency`). EXP-005 CPU 측정(2스레드, 질의 20개, 평균 37.1초)과 같은 방식이고 장치만 다르다
- 이 값은 GPU 계산 시간이다. 배포에서 전용 추론 서버를 쓰면 네트워크 왕복과 기동 지연(scale-to-zero)이 더해진다

## 판정 기준 (실행 전 확정)
H2는 [메타데이터] 가설이 아니므로 SPEC 판정 절을 그대로 옮긴다. 비교 기준은 EXP-004다.

- dev-full Recall@5 차이를 회의 단위 paired bootstrap(10,000회, seed 20260929)으로 계산한다
- 채택: 95% 구간 하한 > 0 이고 점 추정 ≥ +1.0%p
- 기각: 95% 구간 상한 < 0
- 보류: 그 밖
- multi-doc은 관찰로 보고 판정에 쓰지 않는다(SPEC 보조 관찰). 점수는 같은 VM 세션에서 함께 계산하고, 순위·채점은 기각이 아닐 때만 한다(EXP-005와 같은 처리)
- 지연은 판정에 쓰지 않고 보고한다. 배포 지연 상한(SPEC 미결 3)은 채택일 때 지연과 성능 변동을 함께 보고 정한다
- 단서(SPEC): 질의가 정답 문서를 보고 생성돼 어휘가 겹친다. 문서마다 청크 하나만 넣으므로 답이 다른 청크에 있으면 리랭커가 근거를 보지 못한다

## 실행
- (VM) dev-small 동작 확인: `python -m rag.rerank +exp=exp006 index.scope=dev-small`
- (VM) 채점: `python -m rag.rerank +exp=exp006 index.scope=full`, `… search.queries=multidoc`
- (VM) 지연: `python -m rag.rerank +exp=exp006 index.scope=full retriever.rerank.mode=latency`
- (로컬) 순위·판정: `uv run python -m rag.search +exp=exp006 index.scope=full` → `uv run python -m rag.eval.compare --base data/runs/kure-v1-fixed-512-64-hybrid-cond-filter-dev-full.csv --cand data/runs/kure-v1-fixed-512-64-hybrid-cond-filter-ce-dev-full.csv`
