# EXP-019: 근거에 질의자·답변자 머리 줄을 넣는 기준 전환 (H20 head, 생성)

## 가설

이 실행은 켤지를 정하는 실험이 아니다. 발언자 정보는 날짜·위원회·회의 차수처럼 회의록 챗봇의 생성 모델이 알아야 하는 메타데이터이고, `speakers.mode=head`를 기준으로 삼는 것은 사용자가 지표와 무관하게 정했다(D-63). 이 실행은 전환이 지표를 어떻게 움직이는지 재고 새 기준 결과를 만든다.

- 머리 줄을 넣으면 judge의 발언자 구분 불가 표시(진술·항목)가 줄어든다. 지금 평가 규칙에서는 구분할 수 없는 발언을 근거로 인정하므로, 질의자 발언이 분명해진 진술은 1에서 0으로 바뀌어 종합 지표가 떨어질 수 있다(추론, 재지 않음)
- 지표가 떨어지면 이후 실험에서 개선할 항목으로 기록하고 전환은 되돌리지 않는다(D-63)
- 발언 구간 표지(`marks`)는 메타데이터가 아니라서 이 실행에 넣지 않고 가설로 남긴다(PLAN H20)

## 기준 실험

- 기준 설정: EXP-018(프롬프트 v3, 발언자 표시 없음, 검색 EXP-017, OpenRouter `google/gemma-4-31b-it` CoreWeave fp4)
- 기준 결과: EXP-018 생성 기록 `data/gen_eval/runs/hybrid-cond-filter-law-ms256-k20-ce-v3-dev-full.jsonl`을 j_v11으로 다시 채점한 `data/gen_eval/judge/hybrid-cond-filter-law-ms256-k20-ce-v3-dev-full-deepseek_go_mixed-j_v11.jsonl`. 지시가 다른 결과는 `rag.gen_eval.compare`가 비교하지 않고, 표시가 붙은 기록은 j_v8로 채점할 수 없어(D-60 결정 6) 기준도 j_v11으로 채점한다
- 이 재채점이 j_v11 재검증을 겸한다(D-60 결정 4, D-63). 같은 생성 기록의 j_v8 결과(D-61)와 질의마다 비교해 차이가 D-50의 judge 변동 폭 안인지 본다. 규칙이 바뀐 것은 화자를 적은 진술뿐이라, 화자 이름이 없는 답변과 있는 답변을 나눠 본다
- 백로그 H20의 첫 EXP다(SPEC 가설 단위 중단에서 세지 않는다)

## 바꾸는 것

- `speakers.mode`: `off` → `head`. 근거 메타 줄 다음에 `질의자: 홍길동 위원 / 답변자: 김철수 국토교통부 장관` 형식의 줄이 붙는다(S29 렌더링). 화자 목록이 빈 문서는 `알 수 없음`이다
- 생성 프롬프트 v3 → v4(`configs/prompt/v4.yaml`). 머리 줄을 읽는 법 한 줄만 더했다. 질의자와 답변자가 적혀 있고, 본문에는 두 사람의 발언이 섞여 있거나 한 사람의 발언만 있을 수 있으니 구분해서 읽으라는 내용이다. 답변에 발언자를 밝히라는 지시는 넣지 않는다(뒤 실험에서 시험, D-63)
- judge 지시 j_v8 → j_v11(`configs/judge/prompt/j_v11.yaml`). 기준과 후보에 같이 쓴다. j_v9에서 진술에 답변이 적은 발언자를 남기고(`statements` 규칙 3), 지목한 화자가 근거와 맞는지 판정하며(`verdicts` 규칙 2, D-63 결정 7), 발언 경계를 형식과 내용으로 판단하게 바꿨다(`verdicts` 규칙 5, D-63 결정 8). 표지 설명은 `head`에서 쓰이지 않는다
- 검색, 근거 구성, 생성 모델, judge 실행 설정은 바꾸지 않는다. 임베딩도 바꾸지 않는다(D-56)

## 판정 기준 (실행 전 확정)

기준 전환은 아래 판정과 무관하다. 채택·보류·기각 어느 쪽이어도 EXP-019를 생성 기준으로 올린다(D-63). 판정은 전환의 영향을 SPEC 규칙으로 기록하려고 낸다.

SPEC "생성 단계 평가 > 판정"(D-53)을 그대로 옮긴다. 기준값은 `configs/eval/gen_v1.yaml`(D-55)이다. 비교는 `rag.gen_eval.compare --base <기준 결과> --cand <후보 결과>`로 한다.

- 종합 지표는 질의마다 충실성과 답변 관련성의 단순 평균이다. 두 기준 모두 두 실행에서 계산된 질의만 쓴다
- 기준과의 차이를 회의 단위 paired bootstrap(10,000회, seed 20260929) 95% 구간으로 낸다. 기준마다 두 실행 중 하나라도 계산에서 빠진 질의는 양쪽에서 함께 뺀다
- 채택: 종합 지표 차이의 95% 구간 하한 > 0, 점 추정 ≥ δ 0.02, 기준별 하락 안전 조건과 과잉 거부 안전 조건을 모두 통과
- 기각: 종합 지표 차이의 95% 구간 상한 < 0
- 보류: 그 밖
- 기준별 하락 안전 조건: 충실성 차이 95% 구간 하한 ≥ −0.05, 답변 관련성 ≥ −0.035
- 과잉 거부 안전 조건: 과잉 거부율 차이 95% 구간 상한 ≤ δ_r 0.02
- 기준별 값(충실성, 답변 관련성, 핵심 답변 포함도)과 구간을 판정과 함께 보고한다. 근거 내용은 바꾸지 않아 포함도는 보조 지표로만 보고한다(D-53 결정 1). multi-doc 보조 관찰은 보지 않는다(D-53 결정 7)
- 함께 보고할 관찰(report): 발언자 구분 불가 표시 진술·항목 수, 전체·부분 거부 수, 거부 교차 집계, judge 형식 오류·끝나지 않은 응답 수. 형식 오류가 기준보다 많으면 판정 전에 사용자에게 알린다(`.claude/skills/meet-rag/references/gen-exp.md` "형식 오류율")

## 잘못 귀속 확인

답변이 어떤 발언을 실제로 말한 사람이 아닌 다른 사람의 말로 적는 경우다. j_v11은 이를 0으로 판정하지만 judge도 머리 줄만 보고 발언 경계를 판단하므로, gen-full 뒤 메인이 읽어 답변과 judge 판정을 함께 확인한다.

- 대상: 후보 답변 중 인용한 근거의 머리 줄 화자 이름이 나오는 답변. 그 수를 세고, 그중 최대 30개를 seed 20260929로 뽑아 근거와 대조한다. judge가 이유에 "발언자 불일치"를 쓴 진술은 그 수를 세고 최대 30개를 읽어 맞았는지 본다. 라벨 발언과 겹치는 구간은 라벨로 대조한다. 라벨 밖 구간은 형식에 실질 내용을 더해 판단하고 근거를 적는다. 형식과 내용을 다 봐도 갈리지 않을 때만 판단 보류로 센다(사용자 2026-11-02)
- 기록: 저장소에는 대상 수, 읽은 수, 잘못 귀속 수와 유형, judge 불일치 판정의 맞은 수만 남긴다. 답변·근거 원문은 대화 보고에서만 쓴다
- 기준선을 다시 잡을지 이후 실험 과제로 둘지는 이 사례를 보고 사용자가 정한다(D-63 결정 6). 이 실행에서 장치를 만들지 않는다

## 결정 사항

1. 유료 호출 승인 범위: 머리 줄과 새 지시가 의도대로 들어가는지 아직 실행으로 보지 않았다. gen-small만 먼저 승인받고, 작동을 확인한 뒤 재채점과 gen-full을 승인받는 것을 추천한다(gen-exp B2)
2. j_v11 재검증에서 차이가 D-50 변동 폭을 넘을 때: 후보 gen-full 전에 멈추고 차이가 난 단계와 사례를 보고해 사용자가 정한다. D-49의 변경 절차가 재검증과 사용자 결정을 요구하므로 메인이 넘어가지 않는다(메인이 정함, D-49)
