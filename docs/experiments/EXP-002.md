# EXP-002: BM25 문서에 메타데이터 추가 (H5 BM25 변형)

## 가설
- multi-doc 질의는 회의를 날짜·위원회·회의 종류·회차로 지목하는데, 그 표현은 정답 본문에 드물고 메타데이터에만 있다(날짜 본문 2%, 연도 16%, 위원회 18%. `notebooks/10_03_EXP001_multidoc진단.ipynb`, D-18). BM25 문서에 메타데이터를 더하면 BM25가 이 표현으로 회의를 찾아 multi-doc Recall@5가 오른다
- single-doc 질의는 이런 표현을 거의 쓰지 않아(하나라도 언급 10.4%) 변화가 작을 것으로 예상한다. 안건(`agenda`)은 주제어를 담아 single-doc에도 영향을 줄 수 있다(방향 미상)

## 기준 실험
- EXP-001 (hybrid: dense + BM25 Kiwi, RRF k 60, 깊이 100). D-17
- 기준 순위: single-doc `data/runs/kure-v1-fixed-512-64-hybrid-dev-full.csv`(SHA-256 `0260382f1e6afe6233528fc3b653167a9fe6c4bd255ec923fb60a34998cb3678`), multi-doc `data/runs/kure-v1-fixed-512-64-hybrid-multidoc.csv`(SHA-256 `28918a409dbc9765561e6706f443e565906596068f2ee663590f223a3a0f89ce`)
- multi-doc 회복 여부 참고(D-17): dense `data/runs/kure-v1-fixed-512-64-multidoc.csv`
- 백로그 H5 [메타데이터]의 첫 EXP다(SPEC 가설 단위 중단의 셈에 넣지 않는다)

## 바꾸는 것
- BM25 문서 텍스트: 청크마다 그 문서의 메타데이터 `date`, `committee_name`, `meeting_name`, `meeting_number`, `session_number`, `agenda` 값을 공백으로 이어 청크 텍스트 앞에 붙인다. 같은 문서의 청크는 같은 메타데이터를 받는다. 토큰화(Kiwi 태그 집합)와 BM25 점수(Lucene, k1 1.5, b 0.75)는 EXP-001과 같다
  - 필드 선택: multi-doc 질의의 언급 비율로 골랐다(연도·날짜 100%, 회의 종류 99%, 위원회 98%, `제N회` 41%, `제N차` 42%). `generation_number`(대수)는 질의에 나오지 않아(0%) 뺐다. `agenda`는 질의가 다루는 안건·법안 이름을 담는다
- BM25 인덱스 이름 `kiwi-meta-v1`, 순위 파일 이름 `…-hybrid-meta-{층}.csv`(`retriever.run_name`). EXP-001 인덱스·순위 파일을 덮어쓰지 않는다
- dense 검색, 결합(RRF k 60, 깊이 100, 동점은 dense 우선), 상위 10개는 EXP-001과 같다
- 화자 이름(H12)은 넣지 않는다. 코퍼스에 화자 필드가 없어 적재 단계를 바꿔야 하므로 별도 항목으로 둔다
- 파라미터는 위 값으로 고정하고 dev-full·multi-doc 결과를 보고 조정하지 않는다

## 고정 조건
- SPEC 평가 프로토콜 v1 / 임베딩·청킹·dense 인덱스·질의 임베딩 캐시 재사용(재임베딩 없음) / config: `configs/exp/exp002.yaml`(EXP-001 설정을 불러와 위 항목만 바꾼다)
- BM25 인덱스는 로컬 CPU에서 만든다(EXP-001 실측 약 10분). Colab·유료 API를 쓰지 않는다

## 판정 기준 (실행 전 확정)
SPEC "메타데이터 가설의 판정"(D-18)을 그대로 옮긴다.

1. single-doc: dev-full Recall@5 차이를 회의 단위 paired bootstrap(10,000회, seed 20260929)으로 계산한다. 95% 구간 하한 > 0 이고 점 추정 ≥ +1.0%p이면 채택, 95% 구간 상한 < 0이면 기각한다
2. 1이 보류이면 multi-doc 동결 세트(600건)로 정한다. 재표본 단위 `pool_id`, 반복 10,000회, seed 20260929
   - 채택: Recall@5 차이의 95% 구간 하한 > 0, 점 추정 ≥ +1.0%p, Complete@5 차이의 95% 구간 상한 ≥ 0
   - 기각: Recall@5 차이의 95% 구간 상한 < 0
   - 보류: 그 밖
- 단서: multi-doc 세트는 메타데이터로 묶음을 만들고 질의도 메타데이터로 회의를 지목해 이 가설에 유리하다. multi-doc 세트에는 test가 없어 multi-doc 단계 채택은 검색 단계 종료 시 test로 다시 확인할 수 없다

## 실행
- dev-small 확인(노트북): `uv run python -m rag.search +exp=exp002`
- single-doc: `uv run python -m rag.search +exp=exp002 index.scope=full` → `uv run python -m rag.eval.compare --base data/runs/kure-v1-fixed-512-64-hybrid-dev-full.csv --cand data/runs/kure-v1-fixed-512-64-hybrid-meta-dev-full.csv`
- multi-doc: `uv run python -m rag.search +exp=exp002 index.scope=full search.queries=multidoc` → `uv run python -m rag.eval_multi.compare --base data/runs/kure-v1-fixed-512-64-hybrid-multidoc.csv --cand data/runs/kure-v1-fixed-512-64-hybrid-meta-multidoc.csv`

## 결과
- dev-full Recall@5: 후보 0.8906 / 기준 0.9168 / 차이 −2.62%p (95% 구간 [−4.02, −1.39]%p, 회의 단위 paired bootstrap 10,000회, seed 20260929)
- Recall@1 / @10 / MRR@10: 후보 0.7523 / 0.9274 / 0.8131, 기준 0.7964 / 0.9450 / 0.8495
- 층별 Recall@5: 소위원회(1,214건) 0.9267 → 0.8575(−6.92%p)에 하락이 몰렸다. 본회의(112건) −2.68%p, 국정감사(1,225건) +0.41%p, 특별위원회(307건) +0.98%p, 예산결산특별위원회(158건) 0. 단답형 −2.76%p, 추출형 −2.61%p. 층별 구간은 계산하지 않았다
- 상위 5위: 이탈 99건(소위원회 92건), 진입 20건
- multi-doc(관찰, single-doc에서 판정이 정해져 판정에 쓰지 않음, `pool_id` 단위 95% 구간): Recall@5 0.4336 → 0.5868, +15.32%p [+13.19, +17.49]. Complete@5 0.2967 → 0.4317, +13.50%p [+10.67, +16.50]. 유형별 Recall@5 conf +9.58%p [+6.16, +12.85], law +27.75%p [+23.05, +32.57], questioner +12.74%p [+9.69, +15.81]. dense 기준 대비 Recall@5 +12.11%p [+10.21, +14.12]로 EXP-001의 하락(−3.21%p)을 넘어섰다(D-17)
- 하락 원인(`notebooks/11_02_EXP002_하락원인.ipynb`): BM25 단독 Recall@5가 0.9174 → 0.8597로 떨어졌고, 소위원회에서 0.9086 → 0.7661로 크게 떨어졌다. 이탈 질의 99건의 정답 문서는 93%가 소위원회 문서이고, 메타데이터 접두가 형태소 중앙값 1,106개였다(청크 본문은 약 500개). 법안 수십 개를 나열한 긴 안건 때문이다. 이 접두가 청크마다 붙어 청크 길이가 세 배 가까이 되고, BM25 길이 정규화(b 0.75)로 본문 단어 점수가 깎인 것으로 본다. 새로 올라온 문서는 정답과 같은 회의 문서가 0건이고 접두가 짧았다(중앙값 28). 판정 때 추정한 "같은 회의 문서가 함께 올라온다"는 데이터와 맞지 않았다. 질의 형태소가 올라온 문서의 안건에 걸리는 비율(3.8%)은 정답 문서(6.5%)보다 낮아, 안건 단어가 경쟁 문서를 끌어올린 것도 아니다
- 해석의 한계: multi-doc 세트는 메타데이터로 묶음을 만들고 회의를 메타데이터로 지목해 이 변형에 유리하다(SPEC 단서)
- 근거 노트북: `notebooks/11_01_EXP002_메타BM25확인.ipynb`(dev-small), `notebooks/11_02_EXP002_하락원인.ipynb`
- 순위 파일 SHA-256: single-doc `5e26e9ec127786d2241dab86cf60d503be99083e439027b1916310fa635ae7e7`, multi-doc `5eb23dab5eb36e80979c6e5d7c0ee42992210a4cd31d56b3edc83a8314a27601`
- 실행: `uv run python -m rag.search +exp=exp002 index.scope=full` 후 `... search.queries=multidoc` 합계 19분 32초(BM25 인덱스 생성 포함, 로컬 CPU) / 코드 커밋 bb0f739, 실행 시점 HEAD ece7d83

## 결론
- 기각(single-doc 단계). dev-full Recall@5 차이 −2.62%p, 95% 구간 상한 −1.39%p < 0으로 SPEC "메타데이터 가설의 판정" 1항에 따라 기각한다
- multi-doc은 Recall@5 +15.32%p, Complete@5 +13.50%p로 크게 올랐다. single-doc 하락은 긴 안건 접두가 본문 BM25 점수를 깎은 데서 왔다. 메타데이터가 본문 점수에 섞이지 않는 방식(안건 제외·길이 제한, 메타데이터를 별도 검색 목록으로 결합)이 H5의 다음 변형 후보다
