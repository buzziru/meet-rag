# EXP-018: 지정 거부 문구를 그대로 쓰고 거부를 별도 문장으로 (H24+H19, 생성)

## 가설

- H24: S25 베이스라인 330질의 중 23개에서 생성 모델이 지정 거부 문구 사이에 대상을 넣어("제공된 회의록에서 청장의 대응 계획에 대한 답을 찾지 못했습니다.") 코드가 거부로 판별하지 못했다. 4개는 충실성 진술 없음으로 빠지고 19개는 일반 답변으로 채점됐다(PR #158 report 표). 생성 프롬프트에서 문구를 바꾸지 말고 그대로 쓰라고 지시하면 이 수가 줄어든다. 감점은 그대로 둔다(지정 방식대로 답하지 않은 것, 사용자 결정 2026-10-27, 이슈 #156)
- H19: 한 문장에 내용과 거부 문구를 함께 쓰면("A 위원은 B를 제안했으나 C의 시행 시기는 제공된 회의록에서 답을 찾지 못했습니다[1].") 평가가 문장 전체를 거부로 보아 내용이 채점되지 않는다(S14b `refusal_split`). 거부는 답하지 못한 내용만 담은 별도 문장으로 쓰게 지시한다(사용자 결정 2026-10-20, PR #118)
- 두 가설은 같은 거부 형식 지시라 한 실험으로 본다(D-56). 종합 지표 상한은 H24 +0.001(23질의), H19 0(해당 1문장)이라 판정은 보류가 될 가능성이 크다(D-56, `notebooks/38_01_생성실험순서.ipynb`). H22 지시가 질의자 주장만 있는 항목을 거부로 돌릴 수 있어, 거부 판별을 먼저 맞추려고 생성 실험의 첫 번째로 둔다(D-56)

## 바꾸는 것

- 생성 프롬프트 v2 → v3(`configs/prompt/v3.yaml`). 바뀐 것은 거부 지시 두 줄이다
  - 일부만 답할 수 있으면 답할 수 있는 내용을 먼저 쓰고, 답하지 못한 부분은 따로 한 문장으로 "(답하지 못한 내용)은 제공된 회의록에서 답을 찾지 못했습니다."라고 쓴다. 이 문장에 답한 내용을 섞지 않는다(H19)
  - 지정 문구는 글자를 바꾸거나 사이에 다른 말을 넣지 않는다(H24)
- 거부 문구(`refusal`)와 나머지 지시, 근거 서식은 v2와 같다. 코드 판정은 거부 문구를 담은 문장을 거부 문장으로 본다(`src/rag/gen_eval/checks.py:13-25`). "C의 시행 시기는 제공된 회의록에서 답을 찾지 못했습니다."는 문구를 그대로 담아 거부 문장으로 판별되고, 앞 내용 문장은 채점된다
- 검색, 근거 구성, 생성 모델, judge는 바꾸지 않는다. judge 설정은 동결이라 바꾸는 것에 넣지 않는다(D-49·D-50)

## 판정 기준 (실행 전 확정)

SPEC "생성 단계 평가 > 판정"(D-53)을 그대로 옮긴다. 기준값은 `configs/eval/gen_v1.yaml`(D-55)이다. 비교는 `rag.gen_eval.compare --base <기준 결과> --cand <후보 결과>`로 한다.

- 종합 지표는 질의마다 충실성과 답변 관련성의 단순 평균이다. 두 기준 모두 두 실행에서 계산된 질의만 쓴다
- 기준과의 차이를 회의 단위 paired bootstrap(10,000회, seed 20260929) 95% 구간으로 낸다. 기준마다 두 실행 중 하나라도 계산에서 빠진 질의는 양쪽에서 함께 뺀다
- 채택: 종합 지표 차이의 95% 구간 하한 > 0, 점 추정 ≥ δ 0.02, 기준별 하락 안전 조건과 과잉 거부 안전 조건을 모두 통과
- 기각: 종합 지표 차이의 95% 구간 상한 < 0
- 보류: 그 밖
- 기준별 하락 안전 조건: 충실성 차이 95% 구간 하한 ≥ −0.05, 답변 관련성 ≥ −0.035
- 과잉 거부 안전 조건: 과잉 거부율 차이 95% 구간 상한 ≤ δ_r 0.02
- 기준별 값(충실성, 답변 관련성, 핵심 답변 포함도)과 구간을 판정과 함께 보고한다. 근거를 바꾸지 않아 포함도는 보조 지표로만 보고한다(D-53 결정 1). multi-doc 보조 관찰은 보지 않는다(D-53 결정 7)
- 보류일 때: 상한이 δ 미만인 가설이라 지정 문구 없는 거부 수와 두 안전 조건을 보고 사용자가 예외 채택을 정한다(D-56). 메인과 exp-judge는 판정이나 권고로 정하지 않는다
- 함께 보고할 관찰(report): 지정 문구 없는 거부 수(기준 23), 그중 충실성 진술 없음으로 빠진 수(기준 4), 전체·부분 거부 수, 거부 교차 집계, judge 형식 오류·끝나지 않은 응답 수. 형식 오류가 기준(1건)보다 많으면 판정 전에 사용자에게 알린다(`.claude/skills/meet-rag/references/gen-exp.md` "형식 오류율")

## 결정 사항

1. 부분 거부 문장의 형식: v3 초안은 "(답하지 못한 내용)은 제공된 회의록에서 답을 찾지 못했습니다."로, 대상을 문구 앞에 두고 문구는 그대로 쓴다. 다른 안은 거부 문장을 지정 문구만으로 쓰고 대상은 쓰지 않는 것이다
   - 초안 안: "C의 시행 시기는 제공된 회의록에서 답을 찾지 못했습니다." 문구가 그대로라 거부로 판별되고, 무엇을 못 찾았는지 사용자가 안다. 대상 이름이 거부 문장 안에 있어 채점되지 않는다
   - 다른 안: "제공된 회의록에서 답을 찾지 못했습니다."만 쓴다. 판별은 같고 지시가 단순하지만, 부분 거부에서 무엇을 못 찾았는지 알 수 없다
   - 추천: 초안 안. PLAN H19 줄의 "지정 문구 문장을 그대로 두고 대상을 따로 쓴다"와 맞다
   - 결정: 초안 안(사용자 결정 2026-10-28)
2. 유료 호출 승인 범위: 새 지시 형식이라 의도대로 작동하는지 아직 모른다. gen-small만 먼저 승인받고, 작동을 확인한 뒤 gen-full을 승인받는 것을 추천한다(gen-exp B2). gen-small에서 바로잡는 다시 확인 실행은 처음 승인에 들어간다
   - 결정: gen-small만 먼저 승인, 착수 지시(사용자 결정 2026-10-28). gen-full은 gen-small 확인 뒤 다시 승인받는다
