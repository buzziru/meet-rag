## 목적

## 기준

번호가 낮을수록 먼저 봤다.

1. 단계 사이 약속: 앞 단계가 쓴 값·파일을 뒤 단계가 같은 뜻으로 읽는가
2. 평가와 배포의 차이: 어디서 다르고 차이마다 기록이 있는가
3. 조용히 틀리는 곳: 오류 없이 값이 바뀌는 경로
4. 재현과 기록: 지문, 해시, 저장 응답 키, revision 고정
5. 결정과 코드의 일치
6. 실행 안정성: 동시 실행, 이어 쓰기, 인코딩
7. 남은 코드: 심각도는 낮음까지만 준다

심각도: 높음은 평가 값이나 답변이 조용히 틀릴 수 있음, 중간은 특정 조건에서 틀리거나 멈춤, 낮음은 기록·읽기에만 영향이다. 정합 점검의 높음은 다음 작업이 틀린 규칙을 따를 수 있음이다.

## 결론

- 지난 실험이나 test 값을 바꾸는 지적은 확인되지 않았다. test 답변은 세지 않아 R2-1, R2-2가 test 값에 준 영향은 모른다. 세면 test 기록을 다시 분석하는 일이 되기 때문이다
- 평가와 배포는 프롬프트, 모델·제공자, 근거 구성, 발언자 표시, 조건 추출에서 같은 config와 같은 함수를 쓴다. 다른 곳은 재정렬 점수와 질의 임베딩의 출처이고 기록이 있다(S39, D-84). 재정렬 실패 때 RRF로 답하는 것은 평가에 없는 경로이고 기록이 있다(D-84 결정 3)
- 평가 질의로 드러나지 않는 앱 동작이 주된 지적이다(R1-1, R3-2, R3-9)
