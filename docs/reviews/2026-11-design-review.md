# 배포 페이지 디자인 점검 (2026-11-06)

## 목적

배포 페이지(`deploy/web/`)는 기능 위주로 만들어졌다. S41 공개 마감 전에 화면 전체를 디자인 기준으로 보고, 고칠 것을 `deploy` 세션에 넘긴다. 점검은 `main`이 하고 수정은 `deploy`가 한다(사용자 지시 2026-11-06, 같은 파일을 두 세션이 고치면 충돌한다).

## 범위

- 기준 커밋: `main` `d6a6023`(S40 병합 뒤). 줄 번호는 이 커밋 기준이다. `deploy`의 S51 브랜치가 `deploy/web/app.js`를 고치고 있어 줄 번호가 밀릴 수 있다
- 대상: `deploy/web/index.html`, `style.css`, `app.js`. 사이드바(연도·회의·문서 찾기), 상단 바(탭, 새 채팅), 대화 칸의 빈 화면과 입력칸, 문서 탭, 좁은 화면 서랍, 다크 모드
- 화면: production `https://meet-rag-ig-pr.vercel.app`을 `aside exec`로 봤다(하네스 "화면 검증" 절). 데스크톱 1280px, 좁은 폭 360·320px, 640px(200% 확대 대신), 다크 모드 에뮬레이션
- 대상 밖: 질문을 보내지 않아(OpenRouter 호출 없음) 답변·근거 목록·대기 문구·오류 문구의 렌더링은 화면으로 보지 않았다. 이 부분은 코드로만 봤고 화면 확인은 아래 "확인하지 못한 것"에 둔다
- 문서에 나온 회의록 본문은 Aside에 보냈다(허용 처리처, D-77). 평가 질의는 쓰지 않았다

## 기준

전역 스킬 `better-interface`가 분야별 스킬 여섯(`better-accessibility`, `better-layout`, `better-writing`, `better-typography`, `better-colors`, `better-ui`)의 규칙으로 보고 한 표로 합친 것이다(ADR-0106). 심각도는 `better-interface`의 기준이다.

- `HIGH`: 할 일을 막거나, 사용자를 오도하거나, 내용·조작을 숨긴다. 아래 신호는 보이면 `HIGH`다: 접근 가능한 이름이 없는 조작, 키보드로 닿는데 초점 표시가 없는 조작, 마우스로만 되는 경로, `prefers-reduced-motion`을 무시하는 움직임
- `MEDIUM`: 이해, 효율, 적응성, 일관성을 뚜렷이 해친다
- `LOW`: 영향이 작은 다듬기

스킬에 없는 규칙(한국어 줄바꿈 `word-break: keep-all` 등)은 기억으로 만들어 넣지 않았다.

## 확인한 것과 확인하지 못한 것

확인한 것(aside, production, 질문 보내지 않음):

- 첫 화면: 보내기 버튼은 빈 입력에서 비활성, "테스트"를 쓰면 활성, 지우면 다시 비활성
- 360·320·640px: 가로 스크롤 없음, 상단 바(☰, 탭 셋, 새 채팅) 한 줄, 겹침 없음
- 버튼과 선택 칸은 브라우저 기본 초점선이 남아 있다
- 다크 모드 토큰이 계산 스타일에 그대로 적용된다. 본문·흐린 글자의 대비는 밝은 모드 4.70:1 이상, 다크 모드 5.23:1 이상으로 통과(계산)

확인하지 못한 것:

- 답변 본문, 근거 목록, 5초 대기 문구, 답변 실패 문구의 화면 모양. 질문을 보내야 하고(OpenRouter 호출) 이번 점검에서는 보내지 않았다
- 실제 브라우저 200% 확대(640px 폭으로 대신 봤다), 스크린샷 대부분이 시간 초과로 실패해 눈으로 본 확인은 일부만 있다
- iOS Safari 확대(UI-8)는 실기기로 보지 않았다

답변 중 오류가 나면 나온 글을 지우고 실패 문구만 남기는 동작(`app.js:137`)과 생성이 `length`로 끝난 답변의 표시는 PLAN S41에 사용자 결정 대기로 있어 지적에 넣지 않았다(ADR-0106: 결정 대기인 동작은 고치지 않고 판단할 곳에 올린다).
