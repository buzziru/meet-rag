# S41 공개 마감

비공개 Space `ingyoun/meet-rag`와 로그인해야 열리는 Vercel 페이지를 누구나 쓰는 데모로 연다. 공개 전에 빈 화면 안내·추천 질의(UI-6), 목록 불러오기 표시, 오류 표시를 마치고, 데모 키 한도를 건 뒤 공개하고, 공개한 상태에서 3초 판정을 한다. 할 일 목록은 PLAN S41 줄과 STATUS `deploy` 다음 행동이다.

## 디자인 방향

- **대상과 독자**: 국회 회의록 질의응답 데모. 독자는 처음 들어와 무엇을 물을 수 있는지 모르는 방문자와 포트폴리오로 보는 면접관이다. 데스크톱·태블릿 기준이고 휴대폰은 대상이 아니다(S52 결정 1)
- **화면의 주된 역할**: 빈 화면에서 첫 질문을 하게 하는 것이다. 지금 빈 화면은 제목 하나라 다음 행동이 없다(UI-6)
- **방향**: 색·글꼴 토큰(`deploy/web/style.css`)과 S52 배치는 그대로 둔다. 새로 만드는 것은 빈 화면 안내와 추천 질의 버튼뿐이고, 기존 `.ghost-button`·`--muted`·`--control-line` 토큰으로 만든다. 눈에 띄게 할 곳은 추천 질의 하나이고, 나머지 안내 글은 `--muted`로 낮춘다. 움직임은 넣지 않는다(스피너 하나, 움직임 줄이기 설정이면 멈춘다)

```
빈 화면(대화가 없을 때)
┌──────────┬──────────────────────────────────────────┐
│문서 찾기  │            국회 회의록 질의응답              │
│ 연도      │  1996~2023년 국회 회의록에서 찾아 답하고,     │
│ 회의      │  답변마다 근거 원문을 붙입니다.              │
│ 문서      │                                            │
│           │  [추천 질의 1] [추천 질의 2] [추천 질의 3]   │
│           │ ┌────────────────────────────────────┐    │
│           │ │ 국회 회의록에 대해 물어보세요       ↑│    │
│           │ └────────────────────────────────────┘    │
│           │  무료 공유 GPU로 운영합니다. 오랜만에 …     │
└──────────┴──────────────────────────────────────────┘
첫 질문을 보내면 안내와 추천 질의가 사라지고 지금 대화 화면이 된다. "새 채팅"을 누르면 다시 나온다
```

- 연도 범위는 글에 박지 않고 Space `years` API 값의 처음과 끝으로 채운다(UI-6 권고). 불러오기 전에는 범위 문구를 빼고 보인다
- 지연 안내 문구는 사용자가 정한 글 그대로다(PLAN S41 줄, 2026-11-05): "무료 공유 GPU로 운영합니다. 오랜만에 접속하면 시작에 약 1분이 걸리고, 평소에도 가끔 답변 시작이 몇 초 늦어질 수 있습니다."

### 2. 공개 (외부 상태, 사용자 승인 뒤)

1. 사용자가 데모 키를 만들어 한도를 걸고 Space 시크릿을 바꾼다(결정 사항 2, 사용자 작업)
2. Space 변수 `LANGSMITH_TRACING`을 `false`로 바꾸고(결정 사항 4) Space를 공개로 바꾼다. 바꾸기 전에 Space 저장소에 데이터 파일이 없는지 본다(D-74). 공개 Space가 비공개 Dataset을 시크릿 `HF_TOKEN`으로 계속 내려받는지 재시작 로그로 본다(D-84)
3. Vercel production의 `ssoProtection`을 풀고 대표 주소를 정한다(결정 사항 5). 첫 production 배포에서 cron 등록을 본다
4. 로그인 없는 브라우저로 Vercel 주소에서 연결·문서 열람·질의 5\~10개를 본다(S39). 잠든 Space가 페이지 호출로 깨어나는지, S39b 뒤 고친 화면 항목(안내 위치, 목록 전체, 재연결)도 이때 본다
5. 3초 판정 재측정 1회(결정 사항 7)
6. 공개 뒤 막을 수 없는 호출을 확인한다: 점수 함수를 경로로 불러 대기열을 밀 수 있는지, API로 문서를 차례로 읽을 수 있는 범위(D-74 감수). 부를 수 있으면 막는 방법과 비용을 보고하고 사용자 결정을 받는다. 이 조각에서 막는 장치를 미리 만들지 않는다

각 단계 전에 공유 기록에 한 줄 적는다(Space 재시작·공개, Vercel 설정, `.claude/rules/sessions.md`).

### 3. 공개 뒤 정리 (PR 2)

- 병합 전 production 페이지를 위해 남긴 압축 안 된 회의 목록 API `meetings`를 지운다(PR 1에 더한 것, `meetings_packed`)
- S47 토큰 연결 코드(`deploy/web/app.js:33-34`)를 지운다. 공개 Space는 토큰이 필요 없다(D-88 결정 3). 병합·배포 뒤 사용자에게 토큰 폐기 시점을 알린다
- `meet-rag` 스킬 "화면 검증" 절의 토큰 옮기기 문장을 지운다. 하네스 변경이라 ADR을 하나 더한다(`docs/harness/adr/`)
- `docs/SPEC.md` 미결 3 줄에 3초는 대화의 첫 질문에만 적용한다는 표시를 붙인다(사용자 결정 2026-11-06)
- 앞 결정 표시: D-74(공개 API 표시를 끈다 → 목록에서 숨기고 호출은 연다, 페이지가 API를 부르기 때문), D-79·D-80(비공개 Space → 공개), D-84 결정 6. 무엇이 왜 바뀌었는지 적는다
- 프로젝트 설명의 지연 문단(결정 사항 5)
- 결과 절. cron이 절전을 막는지 3일 관찰은 STATUS에 남긴다

## 결정 사항

1\~5, 7은 권고안으로 정했다(사용자 결정 2026-11-06, 대화). 6과 8은 메인이 앞 결정을 적용했다.

1. **추천 질의 출처**: 평가 질의(dev·test·multi-doc)는 화면에 보이지 않는다(D-74). 그래서 평가 질의에서 고르지 않는다
   - 가(권고): 메인이 코퍼스 문서를 읽고 지어낸 질의 3개를 쓰고, 미리보기에서 실제 답변을 본 뒤 근거가 붙는 것만 남긴다. 위원회·연도가 겹치지 않게 고른다. 입력→동작: "2020년 법제사법위원회에서 공수처법 개정안에 대해 어떤 의견이 나왔나요?"처럼 문서에 있는 회의를 짚는 질의
   - 나: 사용자가 질의를 직접 쓴다. 메인은 답변 확인만 한다
2. **데모 키 크레딧 한도**: 지금 Space에는 로컬 실험과 같은 OpenRouter 키(Doppler `dev`)가 들어 있다(S38). Space에만 쓰는 키를 새로 만들어 그 키에 한도를 건다. 지금 키에 한도를 걸면 로컬 실험도 같은 한도에 막히고, 데모 키만 따로 폐기할 수 없어서다. 로컬 키는 그대로 둔다. 질의 1개는 약 $0.0015다(S52에서 6번 승인 $0.01 이하, 후속 질문은 재작성 호출이 더해진다). 한도에 닿으면 생성이 402로 실패하고 화면에 실패 문구가 나온다 정정: 추천 질의 확인 3번의 OpenRouter 응답 `cost`가 질의당 $0.00050\~0.00057이었다. 질의 수는 아래의 약 2.7배다(2026-11-06)
   - $2(약 1,300질의) / $5(약 3,300질의, 권고) / $10(약 6,600질의). OpenRouter 키 한도는 대시보드에서 정하고 언제든 바꿀 수 있다
3. **오류·`length` 표시**
   - 답변 중간 오류: 가(권고) 지금처럼 나온 글을 지우고 실패 문구만 남기되, 보낸 질문을 입력칸에 되살려 다시 보내기 쉽게 한다. 끝나지 않은 답변은 인용이 빠진 채 남을 수 있어서다. 나: 나온 글을 남기고 아래에 실패 문구를 붙인다
   - `finish_reason`이 `length`: 가(권고) 답변 아래에 "답변이 길이 제한으로 중간에 끝났습니다."를 붙인다. 나: 표시하지 않는다. 빈도는 재지 않았다
   - 생성 API 실패 때 빈 답변 칸: 실패 문구로 채운다(위 가와 같은 경로)
4. **방문자 질의 추적(D-71)**: 가(권고) 공개 Space에서 LangSmith 추적을 끈다. 방문자 질문이 외부에 쌓이지 않아 따로 안내할 것이 없고, 지금도 이번 달 한도 초과로 꺼져 있다. 지연은 Space 로그에 남는다. 감수하는 것: 방문자 질의에서 생긴 문제를 추적으로 되짚을 수 없다. 나: 추적을 켜 두고 빈 화면에 "질문과 답변은 품질 확인을 위해 기록됩니다"를 둔다
5. **대표 주소와 프로젝트 설명 위치**
   - 주소: 가(권고) Vercel 기본 주소(`meet-rag.vercel.app`, 쓸 수 있으면). 나: 사용자 도메인(구입·DNS는 사용자)
   - 프로젝트 설명(지연 문단: 첫 토큰 기준, 측정일을 붙인 중앙값, 공유 GPU 때문에 일부 질의가 늘어남): 저장소 루트에 README가 없다. 가(권고) 루트 `README.md`를 새로 두고 이 조각에서는 프로젝트 한 단락, 공개 주소, 지연 문단만 쓴다. 나머지 소개는 회고(`docs/retrospective/`)를 가리킨다. 나: Space README에 둔다(GitHub에서 보이지 않는다)
6. **추천 질의는 누르면 바로 보낸다(메인 판단)**: 첫 질문을 하게 하는 것이 빈 화면의 역할이라서다. 고쳐 쓰고 싶은 방문자는 입력칸에 직접 쓴다. 다르게 원하면 지시서 확인 때 말해 달라
7. **3초 재측정 시점**: 공개 직후 토큰 없는 스크립트로 1회 잰다. 방문자와 같은 경로이고 코드 상태는 공개 직전과 같다. 처음 지시서는 토큰 유무가 ZeroGPU 우선순위를 바꾼다고 보고 이 안을 권고했는데 틀렸다. 재정렬은 방문자 계정과 관계없이 Space 시크릿의 소유자 토큰으로 점수 함수를 불러 소유자 할당량과 우선순위로 돈다(D-84 결정 2, 사용자 지적 2026-11-06). 그래서 페이지 쪽 토큰 유무는 GPU 대기에 영향이 없고, 시점만 PLAN과 다르다
   - 규모: 지어낸 질의 20개의 첫 질문과 각 후속 질문 1개(40번), 첫 질문 중앙값으로 판정(D-30·D-37), 후속 질문과의 차이, 재정렬 10초 초과 횟수, 문서 찾기 4초를 서버 처리 시간과 왕복으로 나눈 값을 함께 본다. OpenRouter 약 60호출(후속 질문의 재작성 포함), 약 $0.10 이하
8. **동시 처리 수 1 유지(메인 판단)**: 올리려면 `rag.app.main`의 시작 확인과 임베딩 프로세스 파이프 공유를 함께 바꿔야 한다(이슈 #239). 공개 뒤 동시 방문이 많아 대기가 생기면 그때 본다. `configs/gen_eval/dev_queries.yaml`(qid 목록)은 Space에서 빼지 않는다. 같은 파일이 공개 GitHub 저장소에 이미 있어 빼도 공개 범위가 줄지 않는다

### PR 1에 더한 것 (사용자 결정 2026-11-06, 대화)

지시서 확인 뒤 미리보기를 본 사용자가 더했다.

- **근거 번호 링크**: 답변의 `[n]`을 버튼으로 바꾼다. 마우스를 올리면 근거 제목이 나오고, 누르면 접힌 근거 목록을 열어 그 근거로 옮겨 초점을 주고 잠깐 강조한다(움직임 줄이기면 테두리만). 근거가 온 뒤에만 버튼이 되고 스트리밍 중에는 글자다. 미리보기 확인: 번호 3개가 버튼이 되고 이름은 "근거 1, 2001년 9월 17일(월) 행정자치위원회-제2반", 누르면 목록이 열리고 그 근거가 화면 안에 초점과 함께 온다
- **인용한 근거와 참고만 한 근거**: 답변 글에 나온 번호로 나눈다. 미리보기: "근거 2개, 참고만 한 근거 3개"
- **원문에서 보기**: 근거 항목의 문서 뷰어 버튼 이름. 새 탭으로 여는 바깥 링크는 이름이 겹치지 않게 "회의록 원문"에서 "회의록 PDF"로 바꿨다(메인 판단, 점검 UI-12의 의도인 구별되는 이름과 새 탭 알림은 그대로다. 링크 대상은 `fileType=PDF`다)
- **날짜 형식**: 화면 날짜를 `2001년 9월 17일(월)` 하나로 맞춘다(`rag.docs.shown_date`). 원천에 `2000年6月28日(水)`, `2018년4월9일(월)`, 공백이 섞여 있다. 모델 입력은 그대로다
- **국정감사 이름**: 국정감사 원천은 회·차 칸에 연도와 날짜를 넣어(15,884건, 모두 `meeting_name` 국정감사, 조사는 subagent, 집합 일치는 메인 확인) 이름에 날짜가 두 번 나왔다. 회·차 대신 "국정감사"를 붙인다. 같은 날 같은 위원회의 국정감사가 여럿인 회의 1,167개는 전처럼 회의 번호가 붙는다(구별할 메타데이터가 없다)
- **회의 목록 지연**: 연도 하나의 회의 목록이 44\~72KB이고 Space 응답이 압축되지 않아 전송이 지연의 대부분이었다. 처음 방안(연결 때 전체 목록 1.5MB를 받기, eaa69ce)은 미리보기에서 그 응답이 98초 넘게 끝나지 않고 연도별 응답도 10.5초로 늦어져 되돌렸다(614b013). 회의 목록만 gzip+base64로 보낸다(`meetings_packed`, 2016년 4KB). 문서 목록과 문서 본문은 이미 0.3\~1.9초라 그대로 둔다. 병합 전 production 페이지를 위해 `meetings`도 열어 두고 PR 2에서 지운다

### 지시서와 다르게 하거나 더한 것

- 추천 질문의 답변 확인은 미리보기가 아니라 로컬 `rag.generate +exp=current retriever.rerank.enabled=false`로 했다(결정 사항 1은 "미리보기에서"). 로컬은 재정렬 점수 함수가 없어 재정렬만 끄고 같은 생성 설정으로 돌렸다. 미리보기에서는 하나를 눌러 근거가 붙는 것을 봤다. 세 문장의 핵심 어구는 dev 질의와 동결 multi-doc 세트에 없다(test는 열지 않음)
- 추적 끄기는 코드가 아니라 Space 변수로 한다(공개 단계 2)
- 지연 안내는 입력칸 아래가 아니라 빈 화면 안내 안 추천 질문 아래에 두었다. 첫 질문 뒤 함께 사라진다
