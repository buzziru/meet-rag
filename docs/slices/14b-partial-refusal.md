# S14b 부분 거부 처리

S14 생성 평가 모듈의 거부 처리를 고친다. 지금은 답변 어딘가에 거부 문구가 있으면 답변 전체를 거부로 보고 충실성·답변 관련성·핵심 답변 포함도를 채점하지 않는다(`judge.py`의 `judge_record`). 사용자 지적(PR #106 코멘트, 2026-10-20): "A 위원은 B를 제안했습니다[1]. C의 시행 시기는 제공된 회의록에서 답을 찾지 못했습니다."에서 첫 문장은 평가해야 하고, C의 시행 시기를 거부한 것도 이유에 따라 달리 평가해야 한다.

이 조각은 앞부분(부분 거부 답변의 채점)만 맡는다. 처음 지시서(e5608d4)는 거부 문장마다 이유를 나누는 judge 단계도 만들었으나, PR #118 리뷰에서 거부가 맞았는지는 질의가 묻는 항목 단위로 판단하기로 해(D-41 결정 2) 그 부분을 빼고 S14c로 옮겼다(사용자 결정 2026-10-20, (나) 방식).

점수로 무엇을 정하는 조각은 아니다. S14 표본 20질의는 거부가 0건이라 이미 기록한 점수는 바뀌지 않는다.

## 만드는 것

### 거부 판정 (코드)

- 답변을 인용 검사와 같은 `sentences()`로 나누고, 프롬프트의 거부 문구(`gen_eval.refusal`)를 담은 문장(공백 차이 무시)을 거부 문장으로 본다. 거부 문장도 아니고 내용 없는 문장(`gen_eval.filler_phrases`)도 아닌 문장이 내용 문장이다
- 전체 거부: 거부 문장이 있고 내용 문장이 없다. 부분 거부: 거부 문장과 내용 문장이 함께 있다
- judge 기록의 `refusal`을 `"full"`, `"partial"`, `null`로 바꾸고 거부 문장 목록을 남긴다. 이전 judge 기록은 그 커밋의 코드로 집계한다(구현 원칙: 과거 코드와 병용하지 않는다)
- 지정 문구를 따르지 않은 거부("근거에 나와 있지 않습니다")는 이 조각에서 잡지 않는다(초안 "코드로 판정하는 항목", 보정 표본에서 비율을 본다)

### 부분 거부 답변의 채점

- 충실성, 답변 관련성, 인용 검사, 메타데이터 일치는 거부 문장을 뺀 내용 문장으로 한다(결정 사항 1). 거부 문장에는 진술이 없어 충실성이 정의되지 않고, 관련성에서 거부를 깎으면 거부 평가(S14c)와 같은 일을 두 번 센다(초안 "거부 답변의 처리"와 같은 이유)
- 핵심 답변 포함도는 답변 전체로 본다. 거부한 부분의 핵심 진술은 답변에 없어 0으로 잡힌다
- 전체 거부 답변은 지금처럼 위 기준을 채점하지 않는다
- 예: "A 위원은 B를 제안했습니다[1]. C의 시행 시기는 제공된 회의록에서 답을 찾지 못했습니다." → 부분 거부. 충실성·관련성·인용 검사는 첫 문장 하나로 한다

### 집계

- `rag.gen_eval.report`: 전체 거부와 부분 거부 수를 따로 내고, 기준별 평균 표에 부분 거부 답변이 몇 개 들어갔는지 적는다. 기존 거부 교차 집계(근거 상태별)는 전체·부분 거부를 합친 거부로 그대로 둔다

## 결정 사항

모두 정했다(사용자 결정 2026-10-20). DECISIONS D-41로 기록한다.

1. 부분 거부 답변의 답변 관련성 입력: 거부 문장을 빼고 채점한다. 답하지 못한 부분은 포함도와 거부 평가(S14c)가 맡는다
2. 한 문장 안에 내용과 거부 문구가 함께 있으면 문장 전체를 거부로 본다. 이 손실은 생성 프롬프트에서 거부를 별도 문장으로 쓰게 해 해결한다(PLAN H19, PR #118 리뷰)

## 완료 기준

- `uv run pytest -q`, `uv run ruff check .` 통과
- 테스트
  - 거부 분리: 거부 없음, 전체 거부, 부분 거부(위 예시), 공백이 다른 거부 문구, 내용 없는 문장이 섞인 전체 거부("다음과 같습니다." + 거부 문장은 전체 거부)
  - 부분 거부의 judge 입력: 가짜 judge로 충실성·관련성에 거부 문장이 빠진 답변이, 포함도에 답변 전체가 가는지
- 회귀: S14 표본 20질의를 `rag.gen_eval.judge`·`report`로 다시 돌려 기준별 평균이 같다(거부 0건, 저장된 응답 사용)

### 뺀 설계의 확인 기록 (S14c 참고)

처음 지시서대로 만든 문장 단위 거부 이유 분류(`refusal_reason`, j_v6)를 합성 답변 5개로 확인한 기록이다(호출 5회, opencode Go 구독, `data/gen_eval/s14b_check.jsonl`). 코드는 빼고(c497344) S14c 설계의 참고로 남긴다.

| qid | 합성 답변 | 의도한 이유(근거로 쓴 신호) | judge 판정 |
| --- | --- | --- | --- |
| 051423-0007 | 전체 거부 | 근거에 답 있음(청크에 핵심 답 있음, 포함도 1.0) | 근거에 답 있음 |
| 035604-0001 | 원래 답변 첫 문장 + "구체적인 콘텐츠는 … 찾지 못했습니다." | 근거가 모호함(핵심 진술 "아직 구체화된 콘텐츠는 없고 보고할 예정") | 근거가 모호함 |
| 051488-0015 | 전체 거부 | 답변자 회피(참조 사용 불가) | 근거에 답 있음 |

- 일치 2/5다. 어긋난 3개는 의도한 이유를 정한 신호(정답 청크만, 참조 발언)가 근거 5개를 보고 근거만으로 판정하는 설계와 맞지 않았다
- 051488-0015에서 judge가 답으로 본 근거 내용이 답변자 발언인지 질의자 주장인지 확인하지 않았다. 이 문제를 두고 질의자·답변자 구분 규칙(세 갈래, D-41 결정 4)을 정했다
- 설계한 이유마다 정답을 아는 사례가 아니라 판정 타당성을 보이지 못한다. S14c는 정답을 아는 사례로 확인한다
