# S43 오차 분석

지금 생성 기준(DECISIONS 머리 줄)의 답변 미비점을 유형으로 묶고, 유형별 건수와 손실 몫을 내어 실험을 더할지 정한다(D-76 결정 6). 코드와 설정은 바꾸지 않고 새 API 호출도 없다.

## 만드는 것

근거 노트북 `notebooks/47_01_S43_오차분석.ipynb` 하나와 판독 표 하나다.

**손실 몫(판정 세트 330질의, 라벨·건수만).** 답변, 질의, judge 이유 문장은 읽지 않는다.

- 질의마다 종합 손실은 `1 − (충실성 + 관련성) / 2`다. 두 값이 모두 있는 질의만 쓴다
- report의 교차 집계와 같은 묶음(정답 문서 유무, 청크의 핵심 답 유무)과 전체 거부·부분 거부, 관련성 라벨, 충실성 1 미만 여부로 나눠 묶음별 질의 수, 손실 합, 전체 손실 대비 몫을 낸다. 묶음 정의는 `rag.gen_eval.report`의 것을 그대로 쓴다
- 항목 처리의 틀린 유형별 건수를 함께 적는다. 참고값이라(I11) 손실 몫에 더하지 않는다

**유형 판독(세트 밖 dev 100질의).** S42 결과 절의 `...-outset100` 생성·judge 기록을 읽는다.

- 대상은 종합 손실이 0보다 크거나 틀린 처리 항목이 있는 질의 전부다
- 서브에이전트 셋이 질의, 답변, 근거 5개, judge 판정을 읽고 질의마다 주된 유형을 하나 붙인다(처음 지시는 메인 판독이었고, 사용자가 작성 맥락과 분리하려고 서브에이전트로 바꿨다, 2026-11-05). 메인이 앞선 판독을 바탕으로 유형 목록을 정해 주고 판독자는 새 유형을 제안할 수 있다. 정의와 예를 결과 절에 적는다
- 대상 47질의 중 8질의는 다른 판독자가 다시 읽어 일치율을 낸다. 메인이 표본을 직접 확인한다
- S42의 첫 판독은 근거 원문과 대조하지 않았으므로 여기서 대조한다. 지어낸 내용이 있으면 따로 센다
- 판독 입력과 지시는 `data/gen_eval/error_analysis/`에 두고, 판독 표는 같은 곳 `s43-outset100.csv`(열 `qid`, `type`, `prompt_judge`, `note`, 그리고 지어낸 내용·재판독·반박 판독 열)에 둔다. 질의 원문이 나오는 파일과 메모는 `data/` 안에만 두고, 노트북 출력과 문서에는 집계와 지어낸 예만 쓴다(D-31)

**프롬프트 지시와 judge 규칙의 어긋남(사용자 2026-11-05).** S42에서 나온 문제다. 질의자 주장은 질의자 말로 쓰라는 지시와 거부하지 말고 상황을 쓰라는 지시를 따른 답변이 관련성(R8)이나 항목 처리(I6, I8)에서 감점되거나 틀린 처리로 잡힌다.

- 세트 밖: 질의마다 답변이 지시를 따랐는데 judge가 감점한 경우인지 판독해 건수와 손실 몫을 낸다
- 판정 세트: 라벨만으로 재는 값을 낸다. 항목 상태 "없음"에 처리 "상황을 밝히고 답함"인 항목 수, 그 질의들의 관련성 라벨 분포와 손실 몫
- 어긋남을 프롬프트, judge 규칙, 그대로 둠 중 어디서 풀지 권고한다. judge 지시는 동결이라 기준 문서 P1의 조건에 드는지 함께 적는다. 고치는 일은 이 조각 범위 밖이고 사용자가 정한다

**유형별 개선 상한.** 어떤 유형을 모두 고쳤을 때 종합 지표가 얼마나 오를 수 있는지를 세트 밖 100질의에서 계산한다. 그 유형 질의의 손실이 0이 된다고 가정한 상한이다. 판정 세트 묶음과 함께 보여 두 집합의 분포가 크게 다른지도 본다.

입력 → 동작(지어낸 예):

| 질의 상태 | 묶음·유형 예 |
| --- | --- |
| 답변자의 입장을 묻는데 근거에 질의자 발언만 있고, 답변이 질의자 말로 전함 | 답변자 답 없음, 질의자 말 전달 |
| 정답 문서가 상위 5개에 없음 | 검색 실패 |
| 근거에 답이 있는데 답변이 일부 항목만 다룸 | 항목 누락 |

## 결정 사항

1. **읽는 범위**: 내용 판독은 세트 밖 100질의로 한정하고 판정 세트는 라벨·건수만 쓴다(D-76 결정 6). 판독에 질의가 모자라면 더 만들지 호출 수와 비용을 보고하고 묻는다
2. **실험 추가**: 결과를 보고 사용자가 정한다. 메인은 유형별 상한과 예상 비용을 붙여 권고한다. 기준 설정을 바꾸지 않는다

**프롬프트 지시와 judge 규칙의 어긋남.**

- 어긋남이 판정 지표에 주는 몫은 작다. 세트 밖에서 규칙과 지시의 충돌은 9질의, 손실 몫 10.5%이고, 그중 관련성 "일부"는 2질의다. 나머지 7질의는 관련성 만점이고 항목 처리(참고값, I11)에서만 "근거 없이 답함"이다
- 판정 세트 라벨에서 상태 "없음"에 "상황을 밝히고 답함"인 항목은 16개다. 이런 항목이 있는 14질의의 손실 몫은 3.7%이고 12질의가 관련성 "답함"이다
- 충돌의 자리는 판정표 I8의 "없음" 행이다. 지시대로 상황을 밝혀도 "답함과 같음"이라 "근거 없이 답함"이 되므로, 프롬프트를 고쳐도 거부하지 않는 한 항목 처리가 맞음이 되지 않는다
- R8은 일관되게 적용되지 않는다. 판독자가 질의자 말 전달로 본 11질의 중 8질의가 관련성 "답함"이다. 이것은 지시와 규칙의 충돌이 아니라 judge 적용의 흔들림이다
- judge 적용 잡음에서 가장 흔한 형태는 judge가 정보 상태의 근거로 든 내용이 답변에 있는데 처리를 "다루지 않음"으로 본 경우다(4질의, 처리 단계는 근거 없이 답변만 본다). 잡음은 기준과 후보 양쪽에 있어 비교의 검정력을 낮추지만 한쪽으로 치우친다는 근거는 없다

메인 권고는 judge를 그대로 두는 것이었다. 동결 예외 조건(기준 문서 P1)은 제품의 기본 요구를 평가가 판정하지 못하는 결함이다. 항목 처리는 참고값이고 충돌의 판정 지표 몫이 작아 이 조건에 들지 않는다고 보았고, 프롬프트만 고쳐도 I8 때문에 항목 처리는 맞음이 되지 않는다.

결정: judge는 고치지 않고 이 결과를 프로젝트 회고에 참고한다(사용자 결정 2026-11-05, D-82). 실험 추가는 사용자가 정했다(D-83).

### 지시서와 다르게 한 것

- 질의 원문이 나오는 파일은 `data/` 안에만 둔다고 적었지만, 반박 판독자가 항목을 합친 사본을 세션 스크래치패드와 도구 출력 폴더에 남겼다. 모두 저장소 밖 로컬이다. 스크래치패드 사본은 사용자 지시로 지웠고(2026-11-05), 도구 출력과 세션 기록은 그대로 둔다
- 판독자 한 명이 작업을 마친 뒤 파싱 확인에서 다른 판독자의 `prompt_judge` 일부를 보았다. 판독을 모두 쓴 뒤이고 고친 파일은 없다
