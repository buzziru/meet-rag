# S39b 화면 분리

Space가 잠들면 방문자가 HF 대기 화면을 약 1분 본다. 화면을 Vercel 정적 페이지로 나누면 페이지는 항상 열리고 Gradio 화면의 한계도 벗어난다(D-84 결정 6). Space는 검색, 재정렬, 생성, 문서 열람을 그대로 맡고 API만 연다. 공개는 하지 않는다(S41).

## 만드는 것

- **정적 페이지**: `deploy/web/`에 HTML, CSS, JS를 둔다. 빌드 단계 없이 `@gradio/client`를 버전을 고정해 ESM으로 불러온다. 채팅과 근거, 문서 탭, 근거에서 문서 열기, 연도·회의·문서 고르기를 지금 앱과 같게 제공하고 휴대폰 폭에서도 읽을 수 있게 한다. 답변과 문서 본문은 HTML로 해석되지 않게 넣는다
- **Space API**: `rag.app`에 페이지가 부를 함수를 `api_visibility="undocumented"`로 연다(D-74). 채팅(답변 조각과 끝의 근거를 차례로 보냄), 연도 목록, 회의 목록, 문서 목록, 문서 한 건 읽기다. 문서는 한 건씩만 내고 일괄·파일 내려받기를 만들지 않는다. 화면과 API가 같은 함수를 쓰도록 로직을 나눈다. Gradio 화면은 로컬 확인용으로 둔다
- **대기 표시**: 첫 토큰이 5초 안에 오지 않으면 답변 밖에 스피너와 문구를 보이고 첫 토큰이 오면 없앤다. 답변 기록에 넣지 않는다. 시작 시간과 문구는 페이지 설정 한 곳에 둔다
- **연결 대기**: Space에 연결하지 못하면 오류 대신 잠시 뒤 다시 시도하는 상태를 보인다. 최종 문구는 S41 첫 구동 안내에서 정한다
- **절전 방지 호출**: `deploy/web/api/`의 Vercel Function과 `vercel.json` cron으로 하루 1회 Space 주소를 부른다. 질의를 보내지 않고 GPU와 OpenRouter를 쓰지 않는다. 토큰을 두지 않으며, 비공개인 동안에는 404를 받아 깨우지 못한다
- **Vercel 프로젝트**: 팀 `ig-pr`(Hobby)에 프로젝트 `meet-rag`를 만들어 이 GitHub 저장소를 연결한다. 루트는 `deploy/web`이고, 이 폴더가 바뀌지 않은 커밋은 배포를 건너뛴다

## 결정 사항

1. **검증과 공개의 순서(메인 권고, 사용자 결정 필요)**: 비공개 Space는 토큰 없는 브라우저에서 부를 수 없고, 공개는 크레딧 한도 같은 S41 항목을 마친 뒤 해야 한다. 그래서 화면은 로컬 페이지와 로컬 `rag.app`(재정렬 끔)으로 끝까지 확인하고, Space API는 소유자 토큰을 쓰는 스크립트로 확인한다. `vercel.app`에서 공개 Space를 부르는 확인은 S41로 넘긴다. 입력→동작: 이 조각이 끝난 뒤 Vercel 주소를 열면 페이지는 뜨지만 채팅은 연결 대기 상태이고, S41에서 공개하면 동작한다
2. **기술(메인 권고)**: 프레임워크와 빌드 없이 만든다. 화면 하나이고 의존성은 Gradio 클라이언트뿐이다
3. **OpenRouter 호출**: 약 15번, $0.01 이하로 본다(1,000질의당 약 $0.37). 재측정이 아니라 동작 확인이다. Colab과 유료 HF 하드웨어는 쓰지 않는다
4. **처리처**: Vercel에는 코드만 두고 질의와 코퍼스가 지나가지 않아 허용 처리처 목록을 바꾸지 않는다(`CLAUDE.md` 금지 절). 저장소와 페이지에 코퍼스 원문을 넣지 않는다

## 노트북과 결정의 순서

데이터나 점수를 보고 정하는 결정이 없어 노트북을 쓰지 않는다.

## 완료 기준

확인 질의는 지어낸 것만 쓴다. dev·test·multi-doc 질의를 쓰지 않는다. 화면 검증 대상 주소는 로컬 페이지 하나다.

| # | 명령 | 기대 결과 |
| --- | --- | --- |
| 1 | `uv run pytest -q`, `uv run ruff check .` | 통과. 합성 입력으로 채팅 API가 답변 조각과 근거를 차례로 내고, 문서 API가 한 건만 내며, 근거 값에 라벨(`summary_q`, `summary_a`)과 `splits`가 없다 |
| 2 | 로컬 `rag.app`과 로컬 페이지를 `aside`로 확인 | 답변이 나눠 나오고 근거 5개가 붙는다. 근거에서 문서가 열리고 근거 위치로 이동한다. 연도·회의·문서를 골라 읽을 수 있다. 첫 토큰을 늦춘 시험에서 5초 뒤 스피너와 문구가 나왔다가 첫 토큰에 사라지고 답변 기록에 남지 않는다. 좁은 폭에서 읽을 수 있다 |
| 3 | Space를 올리고 토큰을 쓰는 스크립트로 API 호출 | 지어낸 질의에 답변 조각과 근거 5개가 오고 재정렬이 돈다. 문서 API가 동작한다. 공개 API 목록이 비어 있다. Space는 비공개다 |
| 4 | Vercel 배포 뒤 주소 열기, cron 등록 확인 | 페이지가 뜨고 Space에 닿지 않아도 깨지지 않는다. cron이 하루 1회로 등록되고 함수가 실행된다. 저장소와 배포 파일에 토큰과 코퍼스 원문이 없다 |
| 5 | 사용자가 로컬 화면을 확인 | 디자인과 사용 흐름을 받는다 |
