# S52 디자인 점검 수정

배포 페이지 디자인 점검(`docs/reviews/2026-11-design-review.md`, 판정 `Block`, HIGH 4)의 지적 14개(UI-1\~5, UI-7\~15)를 고친다(사용자 결정 2026-11-06). UI-6(빈 화면 안내)은 S41에서 한다. S51 확인 중 정한 거부 문구 화면 표시도 이 조각에서 한다(PLAN S52 줄). 고치기 전과 뒤의 화면을 같은 장면으로 찍어 남기고 PR에서 나란히 본다(사용자 요청 2026-11-06).

## 디자인 방향

- **대상과 독자**: 국회 회의록 질의응답 데모. 독자는 회의록 내용을 묻고 근거 원문을 확인하려는 일반 방문자와, 포트폴리오로 이 프로젝트를 보는 사람이다
- **화면의 주된 역할**: 질문하고, 답변의 근거를 회의록 원문에서 확인하는 것이다. 사이드바는 회의록을 직접 찾아 읽는 보조 경로다
- **방향**: 지금 색·글꼴 토큰(`deploy/web/style.css:1-23`)과 모양을 유지한다. 이 조각은 점검 지적을 고치는 일이고 시각 정체성을 새로 정하지 않는다. 새 토큰은 점검이 권한 조작 경계 `--control-line` 하나와 초점 표시뿐이다. 모양을 새로 정하는 일은 범위 밖이다

## 만드는 것

| 묶음 | 지적 | 고치는 것 |
| --- | --- | --- |
| 키보드·초점(HIGH) | UI-1, UI-2, UI-3, UI-4 | 회의·문서 목록을 키보드로 고른다(점검 권고 순서: 먼저 `<input list>`·`<datalist>`, 모양이 맞지 않으면 APG 콤보박스). 입력칸 묶음에 초점 표시. 좁은 화면의 닫힌 서랍은 숨기고, 열 때 초점을 넣고 뒤 화면에 `inert`, Esc로 닫고 ☰로 초점을 돌린다. 서랍 움직임은 움직임 줄이기 설정을 따른다 |
| 알림·의미 | UI-5, UI-10, UI-13 | 답변 준비·완료와 연결 안내를 화면 낭독기에 알린다. 탭 키 동작이 없는 `role="tab"`을 `aria-pressed` 버튼으로 바꾼다. 보이는 주 영역을 `<main>` 하나로 |
| 읽기 | UI-7, UI-8, UI-9, UI-14 | 문서 탭의 안건을 번호마다 나눈 목록으로. 좁은 화면 입력칸 16px. 조작 경계 토큰 `--control-line`(밝은 `#8a8a8f`, 다크 `#75757b`). 안내 문구 "문서 찾기에서 …" |
| 다듬기·문구 | UI-11, UI-12, UI-15 | hover를 `@media (hover: hover)` 안으로. 근거 링크 글자 "회의록 원문"과 새 탭을 알리는 이름. 목록·서랍 `overscroll-behavior: contain` |

| 수정 전·후 화면 | 사용자 요청 | 아래 "화면 기록"의 장면을 고치기 전 production과 고친 뒤 미리보기에서 같은 크기·같은 순서로 찍는다 |

안건 나누기(UI-7)는 페이지가 Space에서 받은 안건 문자열을 나누는 한 곳(`deploy/web/app.js`)에 둔다. 서버 응답 모양을 바꾸지 않아, Space를 먼저 재시작해도 병합 전 production 페이지가 그대로 동작한다.

## 결정 사항

1. **디자인 방향(확인 필요)**: 지금 토큰과 모양을 유지하고 점검 지적만 고친다. 입력→동작: 색은 그대로이고 조작 칸 테두리만 진해지며, 키보드 초점에 테두리가 생긴다
2. **스크린샷 보관(확인 필요)**: 저장소 `docs/slices/52-screens/`에 PNG로 커밋한다(장면 8개 × 2, 장당 수백 KB 어림). 저장소는 공개이고 화면에는 공개 회의록과 지어낸 대화만 나온다. 고르지 않은 안은 Claude 아티팩트 페이지(링크로만 보이고 저장소에 남지 않음)다
3. **외부 호출과 재시작(승인 필요)**
   - OpenRouter: 장면 6·7을 수정 전·후로 찍는 질문 4번과 `better-interface` 리뷰에서 답변 화면을 볼 질문 2번, 합쳐 6번 안쪽. $0.01 이하
   - Space 재시작 1번: 거부 문구 표시가 앱의 화면 글 변환이라 Space를 다시 올려야 한다. 수정 전 장면은 재시작 전에 production에서 찍는다
4. **콤보박스 방식(메인 판단)**: 점검 권고 순서대로 `<datalist>`를 먼저 시도한다. 브라우저마다 목록 모양과 필터가 달라 회의 이름(길고 비슷함)을 고르기 어려우면 APG 콤보박스로 간다. 고른 쪽과 이유를 결과 절에 적는다
