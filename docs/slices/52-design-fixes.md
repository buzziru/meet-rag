# S52 디자인 점검 수정과 문서 뷰어 배치

배포 페이지 디자인 점검(`docs/reviews/2026-11-design-review.md`, 판정 `Block`, HIGH 4)의 지적 14개(UI-1\~5, UI-7\~15)를 고친다(사용자 결정 2026-11-06). UI-6(빈 화면 안내)은 S41에서 한다. 같은 조각에서 문서와 근거를 탭 대신 오른쪽 문서 뷰어로 열어, 대화와 문서·근거를 한 화면에서 보게 한다(사용자 결정 2026-11-06, Claude Code 앱처럼). S51 확인 중 정한 거부 문구 화면 표시도 한다(PLAN S52 줄). 고치기 전과 뒤의 화면을 같은 장면으로 찍어 남기고 PR에서 나란히 본다(사용자 요청 2026-11-06).

## 디자인 방향

- **대상과 독자**: 국회 회의록 질의응답 데모. 독자는 회의록 내용을 묻고 근거 원문을 확인하려는 방문자와, 포트폴리오로 이 프로젝트를 보는 면접관이다. 면접관은 데스크톱이나 태블릿으로 볼 수 있다. 휴대폰은 대상이 아니다(사용자 결정 2026-11-06)
- **화면의 주된 역할**: 질문하고, 답변의 근거를 회의록 원문에서 바로 옆에 펼쳐 확인하는 것이다. 문서 찾기(왼쪽)는 회의록을 직접 찾아 읽는 보조 경로다
- **방향**: 색·글꼴 토큰(`deploy/web/style.css:1-23`)은 유지하고 배치를 바꾼다. 새 토큰은 점검이 권한 조작 경계 `--control-line`과 초점 표시뿐이다. 처음 지시는 모양을 모두 유지하는 것이었고, 사용자가 문서 뷰어 배치를 이 조각에 넣기로 해 바꿨다(2026-11-06)

### 배치

```
넓은 화면(1024px 이상), 첫 화면                넓은 화면, 문서를 연 상태
┌──────────┬───────────────────────┐        ┌──────────────────────┬────────────────────┐
│문서 찾기 ✕│ 대화                   │        │☰ 대화                 │ 문서 뷰어   원문  ✕ │
│ 연도      │                        │        │ 질문                  │ 회의 이름          │
│ 회의      │                        │  ──▶   │ 답변 … [1][3]         │ 안건(목록)         │
│ 문서      │ [입력칸]               │        │ ▸ 근거 5개 ← 누름     │ ▼ 답변에 쓴 근거   │
└──────────┴───────────────────────┘        └──────────────────────┴────────────────────┘
```

- **첫 화면**: 문서 찾기와 대화만 있다. 문서 뷰어는 닫혀 있다
- **문서 뷰어**: 왼쪽에서 문서를 고르거나 대화의 근거를 누를 때만 오른쪽에서 열린다. 지금의 "문서" 탭과 "근거" 탭을 이 뷰어 하나로 합친다. 문서는 처음부터 보이고, 근거로 열면 근거 대목으로 스크롤해 표지(▼·▲)를 보인다. 다른 문서·근거를 고르면 내용만 바뀐다. 상단 탭은 없어진다
- **넓은 화면**: 뷰어가 열리면 문서 찾기가 접히고, ☰로 다시 펼친다(그때는 세 칸). 뷰어를 닫아도 문서 찾기는 접힌 채이고 ☰로 펼친다
- **닫기 버튼**: 문서 찾기와 문서 뷰어 모두 닫기(✕)를 둔다. 닫은 문서 찾기는 ☰로 다시 연다
- **좁은 화면(1024px 미만, 태블릿 세로)**: 문서 찾기와 문서 뷰어를 화면을 덮는 서랍으로 연다. 두 서랍은 같은 규칙을 따른다: 열 때 초점이 서랍 안 닫기 버튼으로 가고 뒤 화면에 `inert`, Esc와 닫기로 닫히면 연 버튼(또는 누른 근거)으로 초점이 돌아온다, 닫힌 서랍은 숨는다, 움직임 줄이기 설정을 따른다

## 결정 사항

1. **디자인 방향(사용자 결정 2026-11-06)**: 색·글꼴 토큰은 유지하고 위 배치로 바꾼다. 넓은 화면에서 뷰어를 열면 문서 찾기가 접힌다(권고안 가). 처음 지시는 모양을 모두 유지하는 것이었다
2. **스크린샷 보관(사용자 결정 2026-11-06)**: 저장소 `docs/slices/52-screens/`에 PNG로 커밋한다(장면 10개 × 2). 저장소는 공개이고 화면에는 공개 회의록과 지어낸 대화만 나온다
3. **외부 호출과 재시작(사용자 승인 2026-11-06)**
   - OpenRouter: 장면 5\~7·9를 수정 전·후로 찍는 질문 4번(장면 5·6·9는 같은 질문)과 `better-interface` 리뷰에서 답변 화면을 볼 질문 2번, 합쳐 6번 안쪽. $0.01 이하
   - Space 재시작 1번: 거부 문구 표시가 앱의 화면 글 변환이라 Space를 다시 올려야 한다. 수정 전 장면은 재시작 전에 production에서 찍는다
4. **콤보박스 방식(메인 판단)**: 점검 권고 순서대로 `<datalist>`를 먼저 시도한다. 브라우저마다 목록 모양과 필터가 달라 회의 이름(길고 비슷함)을 고르기 어려우면 APG 콤보박스로 간다. 고른 쪽과 이유를 결과 절에 적는다
5. **좁은 화면 경계(메인 판단)**: 1024px. 태블릿 가로(1024px 이상)는 넓은 화면 배치, 태블릿 세로(820px 안팎)는 서랍 배치다. 1024px에서 문서 찾기가 접히면 대화와 뷰어 두 칸이 된다

## 감수하는 것

- iPad Safari 확대(UI-8)는 실기기 없이 계산값으로만 본다
- 스크린샷은 Aside 브라우저 한 종류의 렌더링이다. 다른 브라우저의 `<datalist>` 모양은 보지 않는다
- 1024px 바로 위 폭에서 뷰어와 대화 두 칸이 좁아 보일 수 있다. 장면은 1280px와 820px만 찍는다
