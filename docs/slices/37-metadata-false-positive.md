# S37 회의 일자·위원회 불일치 오탐 수정

EXP-022에서 답변이 회의를 밝히기 시작하자 코드 판정의 회의 일자·위원회 불일치가 1 → 7답변(8건)으로 늘었다. 메인이 8건을 근거와 대조해 보니 모두 답변이 맞고 코드가 틀렸다(`docs/experiments/EXP-022.md` 결과 절, D-75 결정 2). H23을 채택하려면 이 값을 믿을 수 있어야 한다(사용자).

| 오탐 원인 | 건수 | 사례(입력 → 지금 동작) |
| --- | ---: | --- |
| 공백이 든 근거 날짜를 읽지 못함 | 2 | 근거 `2001年 9月 18日(火)`, 답변 "2001년 9월 18일 …[1]" → `doc_date`가 `None`을 돌려 불일치 |
| 약칭을 다른 위원회로 봄 | 4 | 근거 `감사원장(전윤철)임명동의에관한인사청문특별위원회`, 답변 "인사청문특별위원회에서 …[1]" → 불일치 |
| 본문의 다른 날짜를 회의 일자로 봄 | 2 | 근거 2018년 회의, 답변 "2018년 10월 16일 … 회의에서 … 2019년 1월 1일 자로 정규직 전환 …[1]" → 2019-01-01을 불일치 |

## 만드는 것

`src/rag/gen_eval/checks.py`만 고친다.

- `doc_date`: 공백을 없애고 읽는다. `rag.conditions.DOC_DATE`는 검색 조건 추출도 쓰므로 고치지 않는다
- `metadata_mismatches` 위원회: 답변의 위원회 이름이 인용한 근거의 `committee_name` 안에 들어 있으면 일치로 본다. 지금의 `committee_base` 대조를 대신한다. "국방위원회-제1반"에 "국방위원회"가 든다
- `metadata_mismatches` 날짜: 인용 근거의 회의 일자와 다른 날짜는 아래 둘 중 하나면 세지 않는다
  - 같은 문장에 인용 근거의 회의 일자가 함께 있다(회의를 밝힌 문장의 다른 날짜는 내용이다)
  - 인용 근거 본문에 그 날짜가 있다(근거에서 옮긴 날짜다)

입력 → 바뀐 뒤 동작:

| 문장 | 인용 근거 | 결과 |
| --- | --- | --- |
| "2018년 10월 16일 회의에서 2019년 1월 1일 자로 전환된다고 답했습니다[1]." | 2018-10-16 | 일치 |
| "2003년 1월 13일 규칙이 공표되었습니다[1]." | 2016년 회의, 본문에 그 날짜 있음 | 일치 |
| "2020년 3월 6일 행정안전위원회 회의였습니다[2]." | 2021-01-02, 국방위원회, 본문에 그 날짜 없음 | 날짜·위원회 모두 불일치(지금과 같음) |

## 재계산 범위

없다. 이 값은 코드 판정 관찰이고 판정 지표(종합 지표, 안전 조건)에 들어가지 않는다. judge 호출과 레시피도 바뀌지 않아 compare가 멈추지 않는다. 기존 judge 결과 파일에 저장된 `metadata`는 그대로 두고, 다음 실험의 기준값은 원인 분석 노트북에서 새 함수로 다시 센다. 유료 호출과 Colab을 쓰지 않는다.

## 완료 기준

| # | 명령 | 기대 결과 |

| 4 | 변형 사본(pytest 플러그인, 저장소 파일은 그대로): 공백 제거, 이름 포함 대조, 날짜 두 조건을 각각 되돌림 | 해당 테스트가 실패한다 |

## 범위 밖

- `rag.conditions.DOC_DATE`와 검색 조건 추출. 공백 든 날짜 문서가 검색 조건에서 빠지는지는 재지 않았다. 검색 단계가 끝나 고치지 않고, 이 PR 범위 밖 관찰로 PR에 적는다
- 기존 judge 결과 파일 다시 쓰기, 앞 EXP 수치 수정
- 인용 없는 문장 집계와 인용 지시(EXP-023)

## 알고 두는 한계

- 답변이 근거 본문의 날짜를 회의 일자처럼 잘못 쓰면 잡지 못한다. "2019년 1월 1일 회의에서 …[1]"인데 본문에 그 날짜가 있으면 일치로 본다. 이런 사례가 지금까지 있는지는 재지 않았다
- `병합 전 self-review` 대상이다(`git.md` PR 절 2, `checks.py`)
