# S42 답변 형식 통일

같은 질문의 답변이 불릿과 문단으로 달라진다(PLAN, D-75 결정 6). 프롬프트에 형식 지시가 없다. 지금 기준 v10의 gen-full 330답변을 코드로 세면 아래와 같다(내용은 읽지 않았다).

| 모양 | 답변 수 | 글자 수 중앙값 |
| --- | ---: | ---: |
| 한 문단 | 224 | 199 |
| 여러 문단 | 62 | 413 |
| 불릿, 첫 줄이 불릿 아님 | 37 | 586 |
| 불릿, 첫 줄부터 불릿 | 7 | 523 |

굵은 글씨는 2답변, 제목은 0답변이다.

사용자가 정한 형식(2026-11-04): 논지나 발언이 하나면 한 문단, 둘 이상이면 항목마다 불릿 하나. 규칙은 하나지만 모양은 둘이므로, 모델이 찾은 논지 수가 다르면 같은 질문의 모양도 달라질 수 있다. 이후 변경(사용자 결정 2026-11-04): 불릿 없는 문단으로 통일한다. 처음 형식의 v14가 답변 관련성 조건을 넘지 못하고 재생성 흔들림이 커졌다(아래 "중간 결과").

## 만드는 것

코드는 바꾸지 않는다. 이후 변경(사용자 결정 2026-11-04): 불릿이 한 줄뿐인 답변의 기호를 떼는 `strip_lone_bullet`을 더했고(v14 재현용), v15부터는 켜지 않는다.

- `configs/prompt/v11.yaml`: v10에 아래 지시 한 줄만 더한다. 위치는 "인사말, 맺음말…" 줄 다음이다. 거부 문구와 나머지 지시는 그대로다

  ```text
  - 답이 논지나 발언 하나면 한 문단으로 쓰고, 둘 이상이면 논지나 발언마다 "- "로 시작하는 한 줄로 쓰세요. 불릿 앞뒤에 다른 문장을 쓰지 말고, 번호 목록, 굵은 글씨, 제목은 쓰지 마세요. 답하지 못한 내용을 쓰는 문장만 불릿 뒤에 불릿 없이 따로 쓰세요.
  ```

- `configs/exp/exp024.yaml`: 기준 EXP-023을 직접 상속하고 프롬프트만 v11로 바꾼다. 실험 설정은 `configs/exp/expNNN.yaml`에 둔다는 금지 조항과, 별칭이 EXP를 가리킨다는 `test_current_alias_composes_as_its_baseline_exp`를 따르려는 번호다. 판정 실험이 아니라서 EXP 문서는 쓰지 않고 이 문서가 대응 문서다

입력 → 바뀐 뒤 기대 동작(지어낸 예):

| 근거에서 찾은 답 | 답변 모양 |
| --- | --- |
| 장관 발언 하나 | 불릿 없는 한 문단 |
| 다른 회의의 발언 둘 | `- ` 두 줄, 앞뒤 문장 없음 |
| 발언 둘과 답하지 못한 내용 | `- ` 두 줄, 그 뒤에 "(답하지 못한 내용)은 제공된 회의록에서 답을 찾지 못했습니다." 한 문장 |
| 답을 찾지 못함 | 거부 문구 한 문장 |

코드 판정은 고치지 않아도 된다. `checks.sentences`가 줄바꿈으로 문장을 나누고 인용 검사는 줄 안의 `[n]`을 찾으며, 거부 판별은 문구 포함 여부로 하므로 `- `가 앞에 붙어도 결과가 같다(코드 확인, 실행은 완료 기준 2).

## 실행 순서와 비용

유료 호출이라 아래를 승인받은 뒤 실행한다. 비용은 EXP-023 실측이다.

| 단계 | 호출 | 예상 비용 | 시간 |
| --- | --- | ---: | --- |
| gen-small 생성·judge | 생성 20회, judge 약 90회 | 약 $0.1 | 수 분 |
| gen-full 생성 | 330회 | $0.12 | judge와 합쳐 약 15분 |
| gen-full judge(j_v13) | 약 1,400회 | 비피크 약 $1.3, 피크는 그 2배쯤 | |
| gen-full 재생성(`gen_eval.gen_rep=1`, judge 없음) | 330회 | $0.12 | 수 분 |

합계는 비피크 약 $1.6이다. gen-small에서 지시가 의도대로 작동하지 않으면 지시를 고치고 gen-small부터 다시 하며, 이때 gen-small 비용이 반복마다 더 든다.

gen-small은 답변을 읽어 확인한다. gen-full은 코드 집계와 judge 지표만 보고 판정 전에 내용을 읽지 않는다.

## 재는 것

**성능(판정 지표)**: `rag.gen_eval.compare --base <기준> --cand <v11>`. 기준은 `docs/DECISIONS.md` 머리 줄의 생성 기준 결과다. report 관찰(거부 수와 교차 집계, 인용 없는 문장, 형식 오류)도 함께 낸다.

**형식(코드 집계, 노트북)**: 모양별 답변 수(위 표와 같은 분류), 번호 목록·굵은 글씨·제목이 든 답변 수, 불릿 앞에 문장이 있는 답변 수, 불릿 답변 중 답하지 못한 내용 문장 말고 뒤에 문장이 있는 답변 수.

**같은 질문의 흔들림**: v11 생성 반복 0과 1에서 불릿 유무가 다른 질의 수. 비교값은 v2·v4 재실행의 2\~3%(D-75 이유)다. v10은 재생성하지 않는다.

## 결정 사항

1. 성능이 떨어지지 않았다는 기준. 메인 제안은 SPEC의 세 안전 조건(기준별 하락, 과잉 거부, 잘못 귀속)을 통과하고 종합 지표 차이의 95% 구간 상한이 0 이상인 것이다. SPEC의 채택 조건(구간 하한 > 0, 점 추정 ≥ δ)은 쓰지 않는다. 내용을 바꾸지 않는 지시라 지표가 오르기를 기대하지 않고, 실험으로 채택을 정하지 않기 때문이다(D-75 결정 6). 입력→동작: 차이 −0.005 [−0.018, +0.008]에 안전 조건 통과면 기준을 만족하고, 차이 −0.020 [−0.035, −0.005]면 구간 상한이 0 미만이라 만족하지 못한다(수치는 지어낸 예)
2. 기준에 올릴지는 사용자가 정한다. 1을 만족하지 못하면 지시를 고칠지 그만둘지 사용자에게 묻는다
