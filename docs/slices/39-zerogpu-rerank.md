# S39 실시간 재정렬

S38의 Space는 재정렬을 끈 구성이라 평가한 기준 설정(EXP-017, D-36)과 검색 순서가 다르다. 자유 질의를 같은 Space의 ZeroGPU에서 재정렬해 기준 구성으로 맞춘다. 공개는 하지 않는다(S41).

배포의 목표 사용자는 HF 계정이 없는 인사담당자다. 로그인 없이 5\~10개 질의를 할 수 있어야 한다(사용자 2026-11-04). HF 문서의 비로그인 일일 GPU 할당량은 2분이고 다른 ZeroGPU Space와 공유한다.

## 만드는 것

- **실시간 재정렬 경로**: `Pipeline.rank`가 점수 파일이 없는 자유 질의에서 RRF 상위 `retriever.rerank.depth`개의 질의·근거 청크 쌍을 만들어 점수를 받는다. 후보와 청크 선택은 `rag.search` 후보 쌍과 같은 함수(`candidates`, `best_chunks`)를 쓰고, 순서 규칙은 `final_order`를 그대로 쓴다. 점수 파일 경로(`rag.generate`, 생성 평가)는 바꾸지 않는다
- **Space 진입점**: `deploy/space/app.py`가 시작할 때 모듈 수준에서 리랭커를 `cuda`, `float16`으로 올리고(HF 문서 권장, EXP-017과 같은 dtype), `@spaces.GPU`로 감싼 점수 함수를 앱에 넘긴다. S38의 부르지 않는 함수를 대신한다
- **건너뛰기**: 점수 함수가 실패하면 재정렬만 빼고 RRF 순서로 답하며, 답변 아래에 안내를 한 줄 보인다. 추적 메타데이터에 건너뛴 사실과 오류 종류를 남긴다
- **설정**: 켜는 값과 GPU 예약 시간(`duration`)은 `configs/config.yaml`의 `deploy` 키, 안내 문구는 `app` 키에 둔다. 생성 레시피가 `retriever` 전체를 기록하므로 `retriever`에 키를 더하지 않는다. 앱의 재정렬 시작 거부(`src/rag/app.py:178`)는 점수 함수가 없을 때만 멈추게 바꾼다
- **결정 기록**: 잰 값을 보이고 채택을 받은 뒤 DECISIONS에 적는다. PLAN S39 줄, SPEC 자원 제약의 "리랭커는 GPU 추론 서버" 문장, D-26·D-36의 서버 비용과 남은 일에 표시를 붙인다

## 결정 사항

1. **방안**: 같은 Space의 ZeroGPU에서 재정렬한다. 할당량이 떨어지면 재정렬을 뺀 검색을 쓴다(사용자 결정 2026-11-04). 처음 비교한 다른 안(CPU, HF Endpoint, 리랭커 없음)은 시험하지 않는다
2. **건너뛰는 범위(메인 적용)**: 할당량 오류만이 아니라 GPU 대기 시간 초과 같은 점수 함수 실패도 건너뛴다. 사용자 결정의 의도가 방문자 테스트가 막히지 않는 것이기 때문이다. 입력→동작: GPU 할당이 실패하면 오류 창 대신 재정렬 없는 답변과 안내가 나온다. 앱의 다른 오류(생성 API 실패 등)는 지금 그대로다
3. **OpenRouter 호출**: 약 25번, $0.02 이하로 본다(S38 추정과 같은 단가). 재정렬은 무료 할당량 안이고 Colab과 유료 HF 하드웨어는 쓰지 않는다

## 노트북과 결정의 순서

지연·할당량 실측 몇 개로 정하는 결정이라 노트북을 쓰지 않는다(S38과 같다). 결과 절에 표로 적어 사용자에게 보이고, 결정을 받은 뒤 기록한다.

## 완료 기준

확인 질의는 Space에 지어낸 것만 보낸다. dev·test·multi-doc 질의를 Space로 보내지 않는다(D-79). 완료 기준 2의 dev 질의는 로컬에서만 쓴다.

| # | 명령 | 기대 결과 |
| --- | --- | --- |
| 1 | `spaces` 패키지 소스와 HF 문서 확인 | 할당량이 떨어졌을 때의 예외 형태, 호출당 최소 차감 유무를 찾은 만큼 적는다. 찾지 못하면 그렇다고 적는다 |
| 2 | `tests/`와 로컬 대조(CPU) | 합성 입력에서 점수 함수 성공·실패 때 순서와 안내가 맞다. dev 질의 몇 개에서 실시간 경로의 쌍이 `data/rerank/summary_q-full-ms256-k20.pairs.jsonl`과 같고, 2개에서 점수 순서가 점수 파일과 같다(CPU·float32와 float16 차이는 값으로 보고) |
| 3 | Space에 올려 지어낸 질의 20개 | 답변과 근거 5개가 나오고 재정렬이 돈다. 첫 토큰 시간(중앙값, 최대), 재정렬 시간, GPU 대기·할당 시간을 결과 절에 적는다. 3초 판정 전 확인이고(D-30 상한, 중앙값 기준) 최종 판정은 S41이다 |
| 4 | `hf spaces zero-gpu quota` 전후 | 질의당 할당량 차감을 값으로 적고, 비로그인 2분으로 몇 질의가 되는지 계산한다. 5\~10개 목표에 못 미치면 멈추고 보고한다 |
| 5 | 사용자가 Space를 화면에서 확인 | 채팅, 문서 탭, 근거 탭을 쓸 수 있다. 재정렬 채택을 받는다 |
| 6 | `uv run pytest -q`, `uv run ruff check .` | 통과. 기존 점수 파일 경로의 결과가 그대로다 |

비로그인 방문자의 실제 동작과 실제 할당량 소진은 비공개 Space에서 시험할 수 없다(익명 접속이 404다). S41에서 공개 직후 로그인 없는 브라우저로 5\~10개 질의를 확인하고, 같은 브라우저의 할당량을 소진해 재정렬 없는 답변과 안내가 나오는지 본다(사용자 2026-11-04: 소유자 계정 할당량은 쓰지 않는다). S39의 건너뛰기는 완료 기준 2의 시험과 완료 기준 1에서 찾은 예외 형태로 확인한다. S41 항목에 더한다
