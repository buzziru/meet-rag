# S8b 인용 의미 판정 (JEV)

S8 검사·판정의 규칙 1(인용 대조)을 문자 유사도 판정에서 의미 판정으로 바꾼다. 원문에 그대로 있는 인용은 지금처럼 인정하고, 그대로 있지 않은 인용만 후보 대목을 찾아 TypeSafe Jev(`typesafe/jev-1.13`)로 같은 의미인지 판정한다(2026-10-07 사용자 결정, PR #31 뒤).

## 배경

- 인용 검증의 목적은 근거로 삼은 문장과 같은 의미가 근거 문서에 있는지다. 문자 유사도(`partial_ratio` 0.8)는 낱말·숫자를 바꿔 뜻이 뒤집힌 인용을 통과시키고, 정형화된 국회 말투 때문에 무관한 대목과도 유사도가 높게 나온다
- 파일럿 인용 대부분은 원문에 그대로 있다. 그대로 있지 않은 인용(파일럿 14개)만 판정하므로 호출 수가 적다
- Jev는 미리 정한 질문에 보정된 확률을 돌려주는 결정 모델이다. `noul` 질문은 예일 확률(0\~1)을 준다. 입력 $0.042/M 토큰, 출력 무료, 입력 한도 32K 토큰. 한국어 지원, 입력 길이 한도, 결정성은 공개 자료로 확인되지 않아 파일럿 실험에서 확인한다

## 판정 흐름

```
인용 ─ 원문에 그대로 있음(공백 정규화) ──────────────► 인정
     └ 없음 ─► 후보 대목 k개(rapidfuzz) ─► Jev noul: "후보 대목 중 인용과 같은 의미가 있는가"
                                          ├ P(yes) >= min_prob → 인정
                                          └ 미만 → 인정하지 않음(기존 quote_missing·quote_dependent 규칙)
```

- 후보 대목: 문서를 문장 끝 부호로 나누고 연속 `window_sentences`문장을 한 대목으로 묶어(한 문장씩 밀며), 인용과의 `partial_ratio` 상위 `top_k`개를 고른다. 문자 유사도는 후보를 고르는 데만 쓰고 판정에는 쓰지 않는다
- 15자 기준과 0.8 기준값은 없앤다. 짧은 인용도 같은 흐름으로 판정한다
- 생성 쪽 `evidence` 인용도 같은 흐름이다

## 만드는 것

### 1. 파일럿 실험 (노트북 `notebooks/08_02_인용의미.ipynb`)

| 묶음 | 내용 | 기대 |
|---|---|---|
| 양성 | 파일럿에서 원문에 그대로 있지 않은 인용 14개와 그 문서 | 같은 의미 |
| 대조 | 원문에 그대로 있는 인용 10개(무작위)와 그 문서 | 같은 의미 |
| 음성 1 | 노트북 08_01 9절의 다른 문서 대조 중 `partial_ratio` 0.6 이상 37쌍 | 다른 의미 |
| 음성 2 | 원문에 그대로 있는 인용 30개를 메인이 뜻을 바꿔 고친 변형(부정 10, 숫자·날짜 10, 주체·대상 10)과 그 문서 | 다른 의미 |
| 반복 | 양성 5쌍을 한 번 더 호출 | 같은 확률인지(결정성) |

- 묶음별 P(yes) 분포, 양성·대조와 음성의 분리, 기준값 후보, 호출당 지연·토큰·비용, 오류 응답을 본다
- 음성 2 변형과 응답 원문은 `data/multidoc/quote_semantic/`(커밋하지 않음)에 저장하고, 노트북에는 집계와 짧은 예시만 남긴다
- 호출 수 약 96회(14 + 10 + 37 + 30 + 5). 사용자 승인(2026-10-07, 약 100회·$0.01 미만)

### 2. 결정

노트북을 사용자에게 보이고 `min_prob`, `top_k`, `window_sentences`를 정한다. 분리가 안 되면(음성이 높은 확률로 인정되면) 채택하지 않고 보고한다. 결정은 D-14에 기록한다.

### 3. 구현 `rag.multidoc.check`

- `found`를 정확 일치 → 후보 대목 → Jev 판정으로 바꾼다. Jev 호출은 Decisions API(`POST https://openrouter.ai/api/alpha/decisions`)로 하고 키는 `OPENROUTER_API`
- 판정 결과는 검사 기록(`data/multidoc/check/{pool_id}.json`)에 `quote_checks`로 저장한다(문서·인용·후보 대목·P(yes)). 같은 인용은 다시 호출하지 않는다. 재판정은 저장된 확률로 하고, 기준값이 바뀌어도 호출하지 않는다
- `--dry-run`은 Jev 호출 수 추정도 출력한다
- 파라미터는 `configs/config.yaml`의 `multidoc.check.quote_semantic`(`model`, `url`, `top_k`, `window_sentences`, `min_prob`)에 둔다. `quote_match`는 지운다

### 4. 파일럿 재판정

검사 기록 40개를 새 규칙으로 다시 판정한다. Jev 호출은 원문에 그대로 있지 않은 인용 수만큼이다(약 14회, 실험 응답을 재사용할 수 있으면 0회). 실행 전 `--dry-run`으로 호출 수를 보고한다.

## 노트북과 결정의 순서

1의 노트북을 쓰고 사용자에게 보인 뒤 2에서 결정하고, 그다음 3을 구현한다. 결정 전에 D-14를 고치지 않는다.
