# S36 문서 탐색

테스터가 어떤 문서를 대상으로 하는지 보고, 문서를 읽고 자유 질의를 만들 수 있게 한다(사용자 2026-11-04). 코퍼스는 문서 38,516개, 회의 9,662개(`conference_number` 기준), 연도 1996\~2023이다. 연도당 회의는 많아야 약 520개이고, 회의당 문서는 중앙값 1개, 최대 60개다(2026-11-04 집계, 2016년부터 회의당 문서가 많다). 전체 트리를 한 번에 그리면 수만 개 항목이 화면에 올라가므로 단계별로 불러온다.

## 만드는 것

- `src/rag/docs.py`: 코퍼스 목록. 시작할 때 연도 → 회의 → 문서 묶음과 문서별 파일 위치를 만들고, 본문은 고른 문서만 파일에서 읽는다(`corpus_meta`를 쓰고 본문은 메모리에 올리지 않는다)
- `src/rag/app.py`: 좌측 `gr.Sidebar`에 연도 선택, 회의 선택(입력해 거를 수 있음), 그 회의의 문서 목록을 둔다. 문서를 고르면 본문 화면에 회의 정보, 안건, 회의록 링크, 발언자 표시를 붙인 본문을 보여 준다. 채팅 화면과 문서 화면은 탭으로 나누고, 문서를 고르면 문서 탭으로 옮긴다. 대화는 그대로 남는다
- 발언자 표시: 근거와 같게 `chunk_speakers`와 `render`를 쓴다. `speakers.mode`가 `off`면 본문만 보인다
- 설정: 탭 이름, 안내 문구를 `configs/config.yaml`의 `app` 키에 둔다
- 테스트: `tests/test_docs.py`. `data/`를 읽지 않고 합성 코퍼스 파일을 쓴다

보여 주는 값은 회의 정보(날짜, 위원회, 회차, 차수), 안건, 회의록 링크, 발언자, 본문이다. `splits`, `n_qa`와 라벨(`summary_q`, `summary_a`)은 보이지 않는다(D-74). 코퍼스 파일에는 라벨이 없고, 원천 라벨은 발언자 표시에만 쓴다. 다운로드 버튼을 두지 않고 공개 API 표시를 끈다(D-74).

## 결정 사항

1. 목록 모양: 연도 선택 → 회의 선택 → 문서 목록의 3단계로 둔다. 펼침 트리는 쓰지 않는다. 입력→동작: "2018"을 고르면 그해 회의 446개가 선택 칸에 들어가고, "미세먼지"를 입력하면 회의가 걸러지며, 회의를 고르면 그 회의의 문서가 보인다. 트리는 Gradio에 기본 구성요소가 없고 회의 수천 개를 한 번에 그려야 한다
2. 문서 화면 위치: 채팅과 탭으로 나눈다(메인 판단, 디자인은 추후 조정, 사용자 2026-11-04). 나란히 두면 화면이 좁아진다
3. 문서 이름: 날짜, 소관위, 회의로 만든다(사용자 2026-11-04. 처음 지시는 본문 앞 40자였고 사용자가 바꿨다). 입력→동작: `2018년4월9일(월) 미세먼지대책특별위원회 제359회 제3차`. 한 회의에 문서가 여럿이면 뒤에 `#2`처럼 순번을 붙인다(메인 판단, 이름이 모두 같아지기 때문이다)

### 사용자 화면 확인 반영(2026-11-04)

- 문서 목록을 라디오에서 선택 칸으로 바꾸고, 선택을 비우는 버튼을 더했다
- 근거 머리를 누르면 같은 페이지의 근거 탭에 그 문서를 연다. 처음 지시서는 범위 밖이었고 사용자가 물어 더했다. 새 탭으로 먼저 만들었다가 사용자 제안으로 바꿨다. 입력→동작: 근거 [1]의 머리를 누르면 근거 탭으로 옮겨 가고, 청크 앞뒤에 `▼ 답변에 쓴 근거`, `▲ 근거 끝`을 보이고 그 자리로 스크롤한다. 페이지를 다시 불러오지 않아 대화가 남는다. 청크 위치를 찾지 못하면 표시 없이 문서만 연다
- 시작 표지만 남기고 닫는 표지(`〈/답변〉`)를 뺐다. HTML 태그처럼 보였다
- 선택 칸의 긴 이름이 화살표와 겹쳐 오른쪽 여백을 비우고 넘치면 줄였다. 사이드바를 400px로 넓혔다(`app.sidebar_width`)
- 앞 칸을 고르기 전에는 뒤 칸을 막는다. 연도 없이 회의에 입력하면 선택지가 없어 오류로 표시됐다
- 문서와 근거의 본문을 문단으로 나눴다. 본문에 줄바꿈과 화자 구분이 없어, 라벨 QA의 발언 표지와 원천의 연속 공백에서만 나눈다. 라벨 밖 발언의 화자는 구분되지 않는다(예: `…지요? 예, 그렇습니다. 전문가들 중에는…`). 모델 입력은 그대로다

### 지시서와 다르게 하거나 더한 것

- 원천 날짜 형식이 섞여 있었다(`2000年6月28日(水)` 등, 4,910문서). 정렬은 숫자로 읽고 화면에는 원문 그대로 보인다
- test 회의 문서도 빼지 않고 같게 보인다(D-78). 지시서에 없던 결정이고 리뷰 가이드가 물어 사용자가 정했다
- 날짜, 위원회, 회차, 차수까지 같은 회의가 있어 그때만 회의 번호를 이름 뒤에 붙인다
