# S34 지정 문구를 변형한 거부를 거부로 판별

생성 모델이 지정 거부 문구 사이에 말을 넣으면("제공된 회의록에서 (대상)에 대한 답을 찾지 못했습니다") `refusal_split`이 거부로 세지 않아, 거부 문장이 충실성·인용 채점에 들어간다. 지시는 고치지 않고 판별 코드로 해소한다(D-70 결정 5). `unlisted_refusal`이 이미 이 문장을 찾으므로 그 조건을 거부 판별에 쓴다.

## 지금 기준 결과에서 바뀌는 범위

기준 gen-full 330질의를 코드로 센 값이다(답변 원문은 읽지 않았다).

| 구분 | 지금 | 바뀐 뒤 |
| --- | ---: | ---: |
| 전체 거부 | 3 | 6 |
| 부분 거부 | 18 | 23 |
| 거부 아님 | 309 | 301 |

변형 문장이 있는 8질의 모두 변형 문장이 한 답변에 하나이고 인용 번호가 없다. "찾지 못했다고 답했다"처럼 발언을 전하는 형태는 0건이다.

재계산 범위는 지금 기준 결과 하나다. 다음 실험은 새 코드로 채점한 후보를 이 기준과 비교한다. 앞 EXP의 결과와 판정은 그때 코드의 기록으로 두고 다시 계산하지 않는다.

- 전체 거부가 되는 3질의: 충실성·관련성·포함도를 채점하지 않는다. 새 judge 호출은 없다
- 부분 거부가 되는 5질의: 거부 문장을 뺀 내용으로 충실성을 다시 채점한다. `statements`·`verdicts` 질의당 2회, 약 10회(형식 재요청 제외)다. 호출 단가를 S25(1,731회 약 $1.34)로 환산하면 약 $0.01이다. 관련성·포함도·항목 평가는 입력이 그대로라 저장 응답을 쓴다
- 나머지 322질의: 요청 본문이 같아 저장 응답을 쓰고 값이 같다

## 만드는 것

- `src/rag/gen_eval/checks.py`: `refusal_split`이 지정 문구를 담은 문장과 함께 `gen_eval.unlisted_refusal` 조각을 모두 담은 문장도 거부 문장으로 본다. 전체·부분을 나누는 규칙과 "문장 전체를 거부로 본다"(기준 문서 X2)는 그대로다
- `src/rag/gen_eval/judge.py`: `refusal_split`에 조각을 넘기고, `judge_recipe`에 `unlisted_refusal`을 남긴다
- `src/rag/gen_eval/compare.py`: `JUDGE_KEYS`에 `unlisted_refusal`을 더한다. 값이 다른 결과(옛 판별로 채점한 기준과 새 판별로 채점한 후보)를 비교하지 않고 멈춘다. 거부 문구처럼 실험이 바꾸는 값이 아니라 채점 규칙이기 때문이다
- `src/rag/gen_eval/report.py`: 형식 관찰 표를 바꾼다. 변형 거부 답변을 전체 거부로 셈, 부분 거부로 셈, 거부로 세지 않음(옛 판별 결과에서만 나옴)으로 나눠 세고, "진술 없음, 변형 거부 아님"을 함께 낸다. 표 머리의 "거부로 세지 않고 지표도 그대로"를 지운다
- `configs/config.yaml`: `gen_eval.unlisted_refusal` 주석을 거부 판별에 쓴다는 내용으로 고친다
- 기준 재계산: 생성 호출 없이 기준 생성 기록을 새 코드로 다시 채점한다. 기존 결과를 덮어쓰지 않고 파일 이름 끝에 `-s34`를 붙여 새로 쓴다(앞선 `-n330-fr_v1`과 같은 방식)

```
LANGSMITH_TRACING=false doppler run -- uv run python -m rag.gen_eval.judge +exp=current paths.gen_judge=<기준 결과 경로에서 끝에 -s34>
```

- 문서: D-73(D-70 결정 5 `→ D-73`, DECISIONS 머리 줄의 기준 결과 경로), 기준 문서 X2·X3·"지정 문구를 따르지 않은 거부의 감지" 줄, `docs/SPEC.md:143`의 거부 문구 검사 설명, EXP-021 결과 절에 `이후 변경` 표시, `CLAUDE.md`의 기준 결과 명령이 바뀌면 그 줄, PLAN 줄을 PLAN-done으로

## 결정 사항

1. 범위: 전체 거부만 고칠지, 부분 거부까지 같은 규칙으로 볼지. D-70 결정 5와 PLAN은 전체 거부를 말한다
   - 부분 거부까지(추천): 규칙이 "거부 문장은 지정 문구 또는 조각을 담은 문장" 하나다. 8질의가 바뀐다. 사례: "A입니다[1]. 제공된 회의록에서 B는 찾지 못했습니다."는 뒤 문장을 뺀 "A입니다[1]."로 충실성을 채점한다. 지정 문구를 그대로 쓴 부분 거부와 같은 처리다
   - 전체 거부만: 3질의만 바뀌고 새 호출이 없다. 같은 사례의 뒤 문장은 지금처럼 내용 문장으로 채점되어, 지정 문구를 쓴 부분 거부와 처리가 갈린다. "내용 문장이 없을 때만 변형 문장을 거부로 본다"는 분기가 하나 더 든다
2. `docs/SPEC.md:143` 수정: 거부 문구 검사 설명에 변형 판별을 더한다. 평가 프로토콜 절이라 승인 대상이다
3. 기준 재계산의 judge 호출 약 10회(약 $0.01, opencode Go) 실행

### 지시서와 다르게 나온 것

완료 기준 6은 "나머지 322질의가 같다"였지만 320질의가 같고 2질의가 달랐다. 거부 종류가 바뀐 질의는 8개로 지시서와 같고, 그중 부분 거부 5질의의 점수와 전체 8질의의 항목 평가는 그대로다.

달라진 2질의는 앞 실행에서 첫 응답이 끝나지 않아(`finish_reason` length) 저장되지 않았던 단계다. 끝나지 않은 응답은 저장하지 않으므로(D-42) 재실행 때 다시 물었고 새 응답을 받았다.

| 질의 | 단계 | 값 |
| --- | --- | --- |
| 047495-0011 | `items`, `item_handling` | 판정 수는 같고 항목 문구만 다름 |
| 049566-0017 | `verdicts` | 충실성 0.5 → 0.75 |

새 호출 11회 중 3회가 이 2질의이고, 8회가 변형 문장을 뺀 부분 거부 채점이다. 지시서의 약 10회와 비슷하다.

앞 응답으로 되돌릴 방법이 없고 저장되지 않은 응답을 다시 묻는 것은 정해진 동작이어서 새 결과를 그대로 기준으로 쓴다(메인 판단, D-73 감수하는 것). 위 표의 차이에는 이 2질의의 잡음이 들어 있다.

### self-review 지적과 반영

- 판별 조건에 인용 번호 없음을 더했다. 조각만 보면 "찾지 못했던 자료를 제공된 회의록에서 확인했습니다[1]."처럼 거부가 없는 내용 문장이 전체 거부가 된다. 기준 결과의 변형 문장 8개는 모두 인용이 없어 값이 그대로다(거부 종류를 코드로 다시 내 재채점 결과와 대조). 재채점은 다시 하지 않았다
- `judge_recipe`가 `unlisted_refusal`을 남기는지 테스트를 더했다. 이 줄을 지우면 판별이 다른 결과를 compare가 멈추지 않는다
- report 표가 그 결과의 레시피로 판별을 가린다. 레시피에 키가 없는 옛 결과는 변형 문장이 든 답변을 모두 "거부로 세지 않음"에 두고, 조각은 지금 config가 아니라 레시피에서 읽는다
- 인용 없이 발언을 전하는 문장은 여전히 거부로 본다. 기준 결과에는 없고 드물어 조건을 더하지 않았다(D-73 감수하는 것)
