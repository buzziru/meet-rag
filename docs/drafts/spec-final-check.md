# SPEC 생성 평가 절 보강 초안 (마무리 정합 점검, 2026-11-09)

마무리 정합 점검에서 SPEC에 없던 두 경로를 더한다(사용자 결정 2026-11-09, 대화). 판정 규칙과 값은 바꾸지 않고, 이미 결정으로 쓴 경로를 SPEC에 적는다. 승인 뒤 SPEC으로 옮기고 D-93에 기록한다.

## 1. `docs/SPEC.md` 생성 단계 평가 머리 문단(지금 82행) 끝에 더할 문장

> 판정 실험이 아닌 사용자 경험 변경(답변 형식·안내 지시, S42·S44)은 이 절의 판정 대신 성능이 떨어지지 않았는지로 기준에 올린다. 기준별 하락·과잉 거부·잘못 귀속 안전 조건을 모두 통과하는지 보고, 지시가 의도대로 작동했는데 안전 조건에 걸리면 올리기 전에 사례를 함께 본다. 종합 지표의 채택 조건(구간 하한 > 0, 점 추정 δ 이상)은 요구하지 않고, 올릴지는 사용자가 정한다(D-75 결정 6, D-81, D-83 결정 4, D-85).

## 2. `docs/SPEC.md` "코드로 판정하는 항목"(지금 142\~144행) 끝에 더할 항목

> - 인용 전무: 안내 문장(`gen_eval.notice_key`)을 뺀 본문이 있는데 답변 전체에 `[n]`이 하나도 없는가(`rag.gen_eval.report.no_citation`). 판정에 쓰지 않고, 답변 형식 변경의 근거와 생성 test 보고 지표로 센다(S42, S44, D-87 결정 3)

## 3. 루트 `CLAUDE.md` 금지 절 허용 처리처의 Hugging Face 항목

- 지금: `배포용 Hugging Face 비공개 저장소(D-79, 라벨·질의 제외)`
- 바꿀 문구: `배포용 Hugging Face(비공개 Dataset에 저장하고 공개 Space에서 처리, D-79, D-92, 라벨·질의 제외)`

## 4. D-93 초안

## D-93 마무리 정합 점검: 공개 Space 처리를 처리처 목록에 맞추고 SPEC에 기준 변경 경로와 인용 전무 집계를 적는다

- 결정(사용자 결정 2026-11-09, 대화)
  1. 루트 `CLAUDE.md` 허용 처리처의 Hugging Face 항목을 "비공개 Dataset에 저장하고 공개 Space에서 처리"로 고친다. 처리 동작은 D-92 결정 1로 이미 승인된 그대로이고 목록 문구만 맞춘다
  2. SPEC 생성 단계 평가 머리 문단에 판정 실험이 아닌 사용자 경험 변경의 기준 반영 경로(위 1)를 적는다
  3. SPEC "코드로 판정하는 항목"에 인용 전무 집계(위 2)를 적는다. 판정에는 쓰지 않는다
- 이유: 점검에서 처리처 목록이 "비공개 저장소"로 남아 공개 Space의 데이터 처리가 글자 그대로는 목록 밖으로 읽혔다. 지금 생성 기준(S44 v19)이 올라온 경로와 test 보고 지표인 인용 전무 집계가 SPEC에 없어, SPEC만 읽으면 기준이 판정이나 EXP-019 예외로만 바뀐 것처럼 읽혔다
- 바뀌는 것: 루트 `CLAUDE.md` 금지 절 처리처 줄, `docs/SPEC.md` 생성 단계 평가 머리 문단과 "코드로 판정하는 항목", D-79 결정 1(보강), D-81 결정 1·D-85 결정 1의 "`docs/SPEC.md`는 바뀌지 않는다"(이후 변경). 판정 규칙·값과 코드·config는 바뀌지 않는다
- 감수하는 것: 생성 단계를 마친 뒤 SPEC에 경로를 적는 것이라 이 경로로 다시 기준을 올릴 일은 지금 계획에 없다
