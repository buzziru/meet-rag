# ADR-0023 multi-doc 실행 순서를 meet-rag 스킬로 옮김

- 상태: 채택
- 날짜: 2026-10-07
- 커밋: 3270682, 7385401

## 맥락

ADR-0022는 CLAUDE.md "명령" 절을 호출법만 두기로 했지만, multi-doc 세 줄은 S8c가 병합되지 않아 그대로 뒀다. S8c(PR #37)가 병합돼 검사가 `multidoc-checker` 에이전트로 바뀌었고, 순서(pools → prepare → 생성 작업자 → check --prepare → 검사 작업자 → check)와 재개 방식이 코드와 맞게 정해졌다.

PR #37 코멘트에서 사용자는 본 생성 한 번 동안 지시를 바꾸지 않고, 형식이 틀린 검사 출력의 재검사를 3회로 제한한다고 정했다(D-14). 재검사 상한은 `fix/s08-check-retry-limit`의 `multidoc.check.max_rejects`로 구현했다.

S8c 파일럿 재검사에서 작업자 다수가 "출력 파일이 이미 있는지 확인하지 못했다"고 보고했다. `multidoc-checker` 정의는 "있으면 덮어쓰지 않고 보고"라고 하지만, 훅(ADR-0020)이 `check_out` 읽기를 막아 에이전트가 확인할 방법이 없다. 실제 덮어쓰기는 Write 도구가 읽지 않은 기존 파일을 거부해 막힌다.

## 결정

- CLAUDE.md multi-doc 세 줄을 호출 순서 한 줄로 줄이고, 단계별 산출물·작업자·승인 지점·재검사 상한은 meet-rag 스킬 "실행 순서"에 둔다. CLAUDE.md의 Jev 승인 문구는 "금지" 절 OpenRouter 규칙과 중복이라 빼고, 승인 지점과 호출당 비용은 스킬 6단계에 둔다(ADR-0022)
- 스킬에 본 생성 중 생성·검사 지시 버전 고정을 적는다. 검사 기록의 지시 버전이 판정 시점 config 값이라, 도중에 바꾸면 기록이 실제 지시와 달라지기 때문이다
- `multidoc-checker` 정의의 덮어쓰기 문구를 실제 동작에 맞춘다: Read로 존재를 확인하지 않고, Write가 기존 파일 때문에 실패하면 건너뛰고 보고한다

## 결과

`CLAUDE.md` "명령" 절, `.claude/skills/meet-rag/SKILL.md` 작업자 절, `.claude/agents/multidoc-checker.md`, 이 ADR과 목록. ADR-0016\~0022의 커밋 칸을 채웠다.

- 스킬의 재검사 상한(`max_rejects`)은 `fix/s08-check-retry-limit`가 병합돼야 코드와 맞는다

## 삭제 조건

multi-doc 생성을 마치고(G3 동결) 실행 순서를 다시 쓸 일이 없으면 스킬 절을 줄이고 상태를 고친다.
