# ADR-0047 일일 종합의 인증을 구독 계정 OAuth 토큰으로 바꾼다

- 상태: 채택
- 날짜: 2026-10-20

## 맥락

- ADR-0046의 워크플로는 `claude-code-action`을 ID federation으로 인증했다. 교환은 성공했지만 첫 요청이 400 `billing_error`("Credit balance is too low")로 거절됐다(run 39363687778, `full_output`으로 확인)
- 조직의 구매 잔액은 $0이고, 프로모션 크레딧($100, 2026-11-04 만료)의 적용 대상은 Agent SDK, API, 배치 API, Playground, 관리형 에이전트다. Claude Code는 없다. 구독제의 클라우드 세션 보너스 크레딧은 claude.ai 로그인 클라우드 세션 전용이라 쓸 수 없다
- 대안은 둘이었다. 구독(Pro·Max) 계정의 OAuth 토큰으로 액션을 그대로 쓰는 것과, 스크립트가 수집하고 Messages API를 도구 없이 한 번 부르는 것(브랜치 `chore/digest-messages-api`, PR 없음)이다. 사용자는 액션 쪽을 먼저 시도하기로 정했다. 권한 범위를 벗어날 위험이 있어도 필요하면 저장소 파일을 읽어 확인할 수 있기 때문이다. 이 방식이 안 되면 Messages API 쪽으로 간다(사용자 결정 2026-10-20)

## 결정

- 액션 입력을 federation ID 네 개에서 `claude_code_oauth_token` 하나로 바꾼다. 토큰은 사용자가 로컬에서 `claude setup-token`으로 만들어 저장소 secret `CLAUDE_CODE_OAUTH_TOKEN`에 넣는다(액션 문서 `docs/setup.md`)
- federation을 쓰지 않으므로 워크플로 권한에서 `id-token: write`를 뺀다. 나머지(대상 PR 선택, 지시 파일, 도구 범위, `full_output`)는 그대로다

## 결과

- 사용량은 콘솔 크레딧이 아니라 구독에서 처리된다. 구독 사용 한도에서 차감되는지는 액션 문서에 없고, 차감된다고 본다(추론). 평소 Claude Code 작업과 한도를 나눠 쓴다
- 오래 쓰는 토큰을 secret에 보관하게 된다. ADR-0046이 federation을 고른 이유(저장된 비밀값 없음)는 사라진다. 액션 문서 권고대로 주기적으로 교체한다
- federation 규칙이 하던 `main` 브랜치 제한도 사라진다. 저장소 secret이라 이 저장소에 push된 어느 브랜치의 워크플로든 토큰을 읽을 수 있다(fork PR은 읽지 못한다). 이 저장소에 push하는 것은 사용자와 Claude뿐이다
- federation 설정(콘솔 규칙, secret 네 개)은 Messages API 방식으로 갈 때 다시 쓰므로 지우지 않는다

## 삭제 조건

- 첫 실행이 구독 토큰으로도 동작하지 않으면 이 ADR을 대체하고 Messages API 방식으로 바꾼다
- 그 밖에는 ADR-0046과 같다
