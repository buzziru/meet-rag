# ADR-0041 사용자에게 묻는 것을 사용자만 정할 수 있는 판단으로 좁히고, 해석은 사례로 적는다

- 상태: 채택
- 날짜: 2026-10-14

## 맥락

PR #1\~#75의 리뷰 가이드 질문과 사용자 코멘트를 짝지어 읽었다(사용자 요청 2026-10-14). 줄 코멘트와 리뷰는 0건이고 사용자 판단은 모두 PR 대화 코멘트에 있다.

- 답 없이 병합된 질문은 대부분 읽기·명령으로 확인되는 대조였다: config 값과 결정 대조, 동결 파일 SHA, 결정 문구 일치(PR #32\~#46), main 코드와 같은지(#62), 해시 일치(#65), 표기 변경 확인(#71). pr-briefer 정의가 "값 대조는 예/아니오로" 묻게 했다
- 이미 답한 것을 다시 물었다. SPEC 미결 1 해결 표시를 #8·#18·#21에서 물었고 사용자가 두 번 "해결 처리"라고 답했는데도 표시가 빠졌다. meet-rag D5가 해결 표시를 별도 승인 대상으로 둔 것이 원인이다. `poll` 2시간 상한은 그 길이의 작업이 없는데 #60·#74에서 두 번 물었다
- 사용자가 "추가 설명이 필요합니다"로 되물은 질문(#30·#31·#45·#49·#50·#57·#71)은 구체 사례나 수치가 없었다
- 코멘트 해석이 어긋나 후속 PR이 생겼다: "재시도 3회"(#37→#38), "3회"와 "한 가설"의 경계(#47→#48)
- 규칙을 넓게 해석해 사용자가 되돌렸다: 재배포 제한을 외부 처리 금지로 넓힌 일회성 예외(D-25 → D-31, #75), 리랭커 비용을 상시 가동 최대치로만 적음(#61), 근거 없는 "낙관 편향" 단서(#54)

공유 대화(Lauren Tan 발표 정리)의 원칙도 같은 방향이다. 사람의 판단은 출력 하나하나가 아니라 기준 단위로 한 번 내리고, 기계로 확인되는 것은 기계에 맡긴다.

## 결정

- pr-briefer "판단할 곳": 사용자만 정할 수 있는 지점(목표·기준, 지시 해석, 결정 간 양립) 0\~5개로 좁히고, 질문마다 입력→동작 사례나 수치를 붙인다. 읽기·명령으로 확인되는 대조, 이미 답이 있는 것, diff가 쓰는 범위 밖의 드문 경우는 질문으로 만들지 않고 "메인에게"에 적는다
- meet-rag "질문과 해석" 절: 묻기 전에 DECISIONS·스킬·이전 PR 코멘트에서 답을 찾는다. 코멘트 해석은 입력→동작 사례로 적는다. 규칙은 막으려는 대상까지만 적용하되 CLAUDE.md 금지 절과 평가 프로토콜을 좁히는 해석은 묻고(protocol-guard 기준은 그대로), 비용·위험은 예상값을 앞에 두고 최대치는 조건과 함께 적는다
- meet-rag D5: 사용자가 SPEC 미결 사항을 결정하면 같은 PR에서 해결 표시를 한다. 결정이 표시의 승인이다
- git.md PR 절 4: 코멘트 답글의 해석을 사례로 적는다

## 결과

`.claude/agents/pr-briefer.md` 출력 절, `.claude/skills/meet-rag/SKILL.md` "질문과 해석"·D5, `.claude/rules/git.md` PR 절 4.

판단할 곳이 "없음"인 PR이 생길 수 있다. 이것은 사용자가 diff만 읽으면 되는 PR이라는 뜻이다.

## 삭제 조건

PR 리뷰 가이드를 쓰지 않게 되거나, 사용자가 확인형 질문을 다시 받기로 할 때.
