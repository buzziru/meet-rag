# ADR-0018 multidoc-writer 정의에서 과제 규칙을 걷어냄

- 상태: 채택
- 날짜: 2026-10-06
- 커밋: (PR 병합 후 기록)

## 맥락

S8 파일럿을 생성 지시 v1→v2→v3로 고치는 동안 `questioner` 유형의 수율이 오르지 않았다. v2·v3는 질의자 중심 열거형(사안이 달라도 인물과 범위가 공통 축이면 허용)을 넣었지만, 에이전트는 세 번 모두 "공통 쟁점 없음"으로 skip했다. 에이전트 정의와 지시 파일을 함께 보니 정의에 v1 시절의 과제 규칙이 남아 지시 파일과 경쟁하고 있었다.

- "이어지는 문서를 고를 수 없거나 … 억지로 쓰지 않고 skip": 주제 연속을 전제한 선택·skip 규칙
- description의 "정답 문서가 2개나 3개": v3 상한 5와 다름
- 도입부의 S8 지시서 경로: v2에서 에이전트 2개가 범위 밖인 지시서를 읽음
- skip 판단 때 개요가 부족하면 어떻게 할지 없음: v3에서 skip을 확인하려고 고르지 않은 문서 원문을 읽음

ADR-0017은 "정의는 입출력·읽기 범위만, 지시 본문은 지시 파일"로 정했지만, 정의 문장 일부가 그 경계를 넘었다.

## 결정

- 정의에는 지시 버전과 무관한 불변 조건만 둔다: 읽기·쓰기 범위, 인용 원문 유지, 덮어쓰기 금지, 반환 형식. 문서 선택, 정답 수, 질의 형태, skip 조건, 출력 형식은 지시 파일만 정한다고 명시한다. 지시는 파일럿마다 바뀌는 실험 대상이라, 정의에 과제 규칙이 있으면 바뀐 지시와 충돌한다
- 원문은 지시 절차에 따라 개요·메타데이터로 정답 후보에 넣은 문서만 읽고, skip 판단도 개요·메타데이터로 한다. 저장소 문서와 코드는 읽지 않는다
- 반환의 후보 집합별 줄에 질의 형태와 어느 skip 조건인지를 적게 해, 메인이 지시 이행 여부를 확인할 수 있게 한다

## 결과

`.claude/agents/multidoc-writer.md`. ADR-0017은 일부 대체됐다. 도구 제한(Read·Write)은 그대로라 읽기 범위는 여전히 지시문으로만 막는다. 메인이 실행 기록에서 읽은 경로를 확인한다(S8 진행 기록).

## 삭제 조건

ADR-0017과 같다(G3 동결로 multi-doc 생성을 끝낼 때).
