# ADR-0071 docs 기록 규약(docs/CLAUDE.md)과 결정 기록 정합 감사(P12), 단계 종료 정합 점검

- 상태: 일부 대체(→ 0074)
- 날짜: 2026-10-28

## 맥락

이슈 #172를 처리하며 D-51 "동시 8 근거"가 SDK 재시도 2회를 전제로 남아 있었는데, PR #160이 judge를 대기 120초·재시도 1회로 바꾸면서 DECISIONS를 고치지 않았던 것을 찾았다(D-57로 기록). 사용자 요청으로 DECISIONS 전체를 검토했더니 뒤 결정·PR로 바뀌었는데 앞 결정에 표시가 없어 지금도 유효한 것처럼 읽히는 곳이 29곳(52줄) 나왔다. 그중 5곳은 다음 작업(리뷰 수정 SLICE, H24+H19, H20)이 틀린 기준을 따를 수 있는 곳이었다(PR #174에서 보강).

원인은 두 가지다. 새 결정을 쓸 때 앞 결정에 표시를 남기는 단계가 없었다(D-53은 "바뀌는 것"에 D-38을 적었지만 D-38에는 표시가 없었다). 결정 없이 결정 대상(config 값, 코드 동작)을 바꾸는 PR을 잡는 감사 항목도 없었다. 사용자는 DECISIONS를 이후 세션이 따르는 중요 문서로 쓰고 있어 지시만 더하지 않고 지키는지 감사하도록 했다(사용자 결정 2026-10-28).

## 결정

- `docs/CLAUDE.md`(새 파일): docs 기록 규약. 새 결정의 항목(바뀌는 것 포함), 바뀌는 앞 결정에 같은 커밋에서 붙이는 표시(`이후 변경`, `대체`, `→`, `보강`), 머리 줄 "현재 기준 설정" 갱신, 결정 없이 결정 대상이 바뀔 때의 처리, 당시 기록 보강 방식, 단계 종료 정합 점검 절차. 하위 폴더 CLAUDE.md는 Read·Write·Edit로 그 폴더 파일을 다룰 때 불러와져 meet-rag 흐름 밖의 세션에도 적용된다(사용자 제안, Claude Code 문서 memory·context-window). 셸로만 고치거나 docs를 열지 않고 config만 바꾸는 작업에는 불러와지는지 문서에 없어, 항상 불러오는 루트 CLAUDE.md "문서" 절에 "고치기 전에 읽는다"를 두고, 서브에이전트(사용자 정의 에이전트에서 불러오는지 문서에 명시 없음)에는 위임 프롬프트에 넣는다. 규칙 본문은 이 파일 한 곳에 두고 meet-rag 스킬("결정과 PR의 순서")에는 경로와 읽을 시점만 둔다
- protocol-guard P12: 새 결정의 "바뀌는 것"과 앞 결정 표시, 기준 설정을 바꾸는 결정의 머리 줄, config·코드를 바꿨는데 그 대상을 지금 규칙으로 적은 앞 결정이 그대로인 것, 당시 기록의 문장을 고친 것을 모두 위반으로 본다. 결정을 바꾼 PR에서 고치고 누적시키지 않는다(PR #175 리뷰, 사용자 결정 2026-10-28). 처음에는 grep의 오탐 때문에 뒤의 둘을 보고로 두었으나, 보고를 넘기면 PR #160 같은 경우가 다시 병합된다. 오탐은 감사가 지금 규칙으로 읽히지 않는 서술을 해당하지 않음으로 두고 이유를 적어 줄이고, grep이 놓치는 것은 단계 종료 정합 점검이 거른다. protocol-auditor 출력의 위반 항목에 앞 결정 줄 번호를 함께 적는다
- 단계 종료 정합 점검: 생성 단계 test 1회 전과 프로젝트 마무리 전에 DECISIONS 전체를 에이전트 둘로 나눠 검토한다(사용자 결정 2026-10-28). PLAN 생성 평가 진행 순서에 두 번을 각각 한 줄로 둔다

## 결과

`docs/CLAUDE.md`(새 파일), `.claude/skills/protocol-guard/SKILL.md`(P12, 판정 절), `.claude/agents/protocol-auditor.md`(출력 3), `.claude/skills/meet-rag/SKILL.md`("결정과 PR의 순서" 한 줄), `CLAUDE.md`("문서" 한 줄), `docs/PLAN.md`(진행 순서 두 줄). protocol-guard description은 바꾸지 않았다. protocol-auditor가 PR 감사에서 늘 이 점검표를 읽으므로 선택에 영향이 없다.

## 삭제 조건

P12 감사와 단계 종료 점검을 몇 차례 거친 뒤에도 표시 없는 앞 결정이 계속 나오면 grep 대신 결정마다 대상 키를 적는 방식 등으로 바꾼다. DECISIONS를 쓰지 않게 되면 지운다.
