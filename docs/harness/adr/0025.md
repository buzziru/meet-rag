# ADR-0025 정의 없는 서브에이전트 작업과 재판정 파일 구성

- 상태: 채택
- 날짜: 2026-10-08
- 커밋: a574e2e

## 맥락

G3 검수에서 표본 불량 두 유형(범위 모호, 정답 문서 내용 불일치)이 나왔다. 메인은 표본 밖 재판정 파일을 질의와 안건만으로 만들어, 불일치 유형은 판정할 수 없었다. 이를 알리지 않고 동결 뒤 단서로 PR에 질문을 남겼고, 사용자가 "재판정에 문제 유형을 모두 보여주고 검수하게 해야지 왜 일부를 남겨두고 물어보느냐"고 지적했다.

사용자는 law 190건 재판정을 서브에이전트에 맡기라고 했다. 전용 정의가 없어 general-purpose(Sonnet)로 띄웠다. 훅이 없어 작업 5에서 작업자가 목록 밖 입력 하나를 읽었고, 여러 작업자가 두 번째 입력부터 지시를 건너뛰고 읽었다. 질의자를 넣기 전과 뒤에 두 번 판정한 106건 중 8건은 같은 입력에서 판정이 갈렸다. 사용자는 실행 간 일치율을 보고 한 번이라도 통과가 아니면 빼기로 했다(D-15).

## 결정

- D 흐름 집계 단계: 표본 밖 재판정 파일은 앞에서 나온 불량 유형을 모두 판정할 수 있는 정보를 담는다. 판정할 수 없는 유형이 있으면 파일을 주기 전에 알리고 방법을 정한다. 그런 유형을 동결 뒤 단서나 PR 질문으로 넘기지 않는다
- 정의 없는 서브에이전트 작업은 general-purpose로 띄우되, 프롬프트에 읽기·쓰기 경로를 항목 목록으로 한정하고 항목마다 지시를 처음부터 읽게 한다. 같은 일을 다시 하면 F 흐름으로 정의(훅 포함)를 만든다. 일회성 작업마다 정의를 만들면 하네스가 늘어나고, 반복될 때 만들면 훅으로 범위를 막을 수 있다
- 판정형 작업자 결과로 데이터를 빼거나 남길 때는 판정이 실행마다 갈릴 수 있다는 점과, 두 번 판정한 항목이 있으면 그 일치율을 결정 전에 보고한다

## 결과

`.claude/skills/meet-rag/SKILL.md` 작업자 풀 절과 D 흐름 3단계.

## 삭제 조건

사람 검수 게이트(G 항목)와 정의 없는 서브에이전트 작업이 더 없으면 절을 지운다.
