# ADR-0098 상대 세션의 소식을 지시마다 컨텍스트에 넣는다

- 상태: 채택
- 날짜: 2026-11-05

## 맥락

사용자는 `main`과 `deploy` 두 세션에 각각 지시하고 리드 세션을 두지 않는다(사용자 방침 2026-11-05). 두 세션은 독립적으로 일하지만 자기 작업에 영향을 줄 상대 작업은 알아야 한다. 지금은 겹친 뒤에야 드러났다(D-84 번호 충돌, PR #225 `docs/SPEC.md` 충돌).

공유 기록은 메인 체크아웃 `_workspace/`에 있어 worktree에서도 닿는다(`deploy`의 `s45_main_progress.md`도 그곳에 있다). 막힌 곳은 위치가 아니라 읽는 계기다. `sessions.md`는 쓰기 전에 보라고 하지만 기억에 달렸고, 진행 기록은 작업별로 흩어졌고, STATUS는 핸드오프 때만 갱신된다.

## 결정

사용자가 방식을 골랐다(2026-11-05).

- 공유 기록 `_workspace/00_sessions_log.md` 한 파일에 영향을 줄 일만 덧붙인다. 적는 기준은 `.claude/rules/sessions.md`다
- `UserPromptSubmit` 훅 `sessions_news.py`가 지시마다 상대가 새로 적은 줄과 상대 브랜치의 새 커밋(파일 이름 포함)을 컨텍스트에 넣는다. 새 소식이 없으면 넣지 않는다. worktree는 같은 `.git`을 쓰므로 fetch 없이 본다. 적는 것을 잊어도 커밋된 변경은 전달된다. 커밋이 10개를 넘으면 오래된 커밋은 제목을 빼고 개수와 파일 이름만 넣는다. 파일 이름에 공통 파일이 있으면 보이게 하려는 것이다
- 내 브랜치에 이미 있는 커밋은 뺀다. 상대가 main을 병합해도 내 커밋이 소식으로 돌아오지 않는다
- 세션 이름은 worktree 폴더 이름이고 메인 체크아웃은 `main`이다. 새 Claude 세션은 앞서 받은 소식을 모르므로 기록의 최근 10줄을 다시 받는다
- 훅은 알리기만 하고 지시를 막지 않는다. 파이썬 안의 오류는 삼키고, 스크립트를 못 찾아 종료 코드 2가 나는 경우도 `|| true`로 막지 않는다(실측 2026-11-05)
- 상대의 다음 지시를 기다리면 늦는 일(다음 지시 전에 상대 작업이 망가질 수 있는 일, 상대의 답이 있어야 진행할 수 있는 일)은 기록에 적고 사용자 지시 없이 직접 보낸다. 훅은 사용자가 지시를 보낼 때만 돌아, 긴 자율 작업 중인 세션에는 이 경로뿐이다. 사용자가 메시지마다 개입하면 작업 흐름을 막는다고 봤다(사용자 결정 2026-11-05). ADR-0097의 입력 칸 확인 절차는 그대로 쓴다
- 직접 보내면서 생기는 위험은 세 가지로 막는다. 메시지는 상대 세션의 입력 칸으로 들어가 사용자 지시처럼 읽힐 수 있어, 보낸 세션을 앞에 붙이고 받는 쪽은 사용자 지시로 보지 않으며 사용자 승인이 필요한 일을 메시지로 시작하지 않는다. 두 세션이 서로를 깨우며 돌지 않게 답은 질문을 받았을 때만 하고 같은 안건으로 두 번 오가도 풀리지 않으면 사용자에게 넘긴다. 사용자가 나중에 볼 수 있게 보낸 내용을 기록에 적고 다음 보고 때 알린다(사용자 동의 2026-11-05)
- 기록에 적을 대상 목록은 공통 코드(`src/rag/`)와 `docs/PLAN.md`까지 늘리지 않는다. 이들은 커밋 소식으로 받는다. 운영하며 부족하면 다시 본다(사용자 결정 2026-11-05)
- test 질의와 점수는 기록에 적지 않는다. 상대 세션 컨텍스트로 자동 전달되기 때문이다. 커밋 제목은 이 규칙으로만 막는다

버린 안: 규칙만 강화(지금과 같이 기억에 의존), STATUS를 자주 커밋(`main` 직접 커밋이 늘고 두 세션이 같은 파일을 고침), `_workspace` 링크(원인이 경로가 아니고 링크 삭제 사고 위험, ADR-0058).

감수하는 것: 커밋 전 작업과 외부 상태 변경은 세션이 적어야만 전달된다. 긴 자율 작업 중인 세션은 직접 보낸 메시지 말고는 상대 소식을 받지 못한다. 직접 보낸 메시지는 사용자가 나중에야 본다. 사용자가 PR을 병합한 사실은 local ref에 없어 보이지 않는다(상대 브랜치 커밋은 병합 전에 이미 전달된다).

## 결과

`.claude/hooks/sessions_news.py`와 테스트, `.claude/settings.json`의 `UserPromptSubmit`, `.claude/rules/sessions.md`, meet-rag "작업 기록" 절을 고쳤다. 입력→동작: `deploy`가 `add "Dataset 커밋 교체" "main: 재시작 필요"`를 적으면 `main`의 다음 지시 컨텍스트에 그 줄이 한 번 들어가고, `deploy` 자신에게는 들어가지 않는다.

실측(2026-11-05): `claude -p`로 메인 체크아웃에서 시험 줄이 컨텍스트에 들어가는 것을 확인했다. 훅 한 번은 약 0.5초다. `deploy`에는 이 PR 병합 뒤 `main`을 병합하고 세션을 다시 시작해야 적용된다.

## 삭제 조건

다른 세션과 병행하지 않게 되면 ADR-0085·0097과 함께 지운다.
