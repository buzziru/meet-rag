# ADR-0074 docs/CLAUDE.md를 문서 종류별 기록 규약으로 넓히고 당시 기록 범위를 늘림

- 상태: 채택
- 날짜: 2026-10-28

## 맥락

ADR-0071의 `docs/CLAUDE.md`는 DECISIONS 작성, 당시 기록 보강, 정합 점검만 다뤘다. 다른 문서의 규칙은 meet-rag 스킬(PLAN-done 옮기기, SLICE·EXP 필수 내용, SPEC 미결 표시), 루트 CLAUDE.md(STATUS 형식, 끝난 항목 목록), exp-judgment(결과·결론 형식), ADR README에 흩어져 있었고, reviews·research·search-stage-summary·gen-eval-criteria에는 규칙이 없었다. 2026-10-28 조사에서 다음이 나왔다.

- 같은 규칙이 두 곳에서 다르게 적혀 있었다. 끝난 항목 목록은 루트 CLAUDE.md에 "대체"가 있고 meet-rag B6에는 없었다. meet-rag 0단계는 STATUS의 "판정 대기"를 읽는데 STATUS에는 그 절이 없었다
- 병합된 문서를 표시 없이 고쳤다. S6 지시서 규칙을 뒤 조각이 직접 바꿨고(7471ff3, 46d1b92), 병합된 ADR-0069 본문이 바뀌었다. `이후 변경` 표시는 S25에 두 줄뿐이었다
- 같은 종류 안에서 형식이 갈렸다(EXP 결론 첫 줄 세 가지, EXPERIMENTS 행 순서, 리뷰 지적 ID `D-1`이 결정 번호와 겹침)
- `docs/ML 프로젝트 문서 작성 원칙.md`(사용자의 일반 원칙)가 이 저장소 운영과 여러 곳에서 다르지만 어느 쪽을 따를지 적힌 곳이 없었다

사용자는 docs의 다른 문서 규약도 이 파일에 정의되길 원했다(사용자 요청 2026-10-28).

## 결정

- `docs/CLAUDE.md`에 문서 종류를 고치는 방식으로 나눈 표(진행 문서, 현재 규칙 문서, 누적 기록, 조각·실험 문서, 스냅샷)와 종류별 절(PLAN·PLAN-done, STATUS, SLICE, EXP·EXPERIMENTS, SPEC·drafts, data·criteria, reviews·research·단계 정리, ADR)을 둔다
- 당시 기록 범위: 병합된 SLICE·EXP 문서는 지시서 본문까지, 병합된 reviews·research·search-stage-summary·옮긴 drafts·ADR 본문까지 넓힌다. 사실 오류는 `정정:`을 붙인다(사용자 결정 2026-10-28, Q1·Q2)
- EXPERIMENTS 새 줄은 표 맨 위에 넣는다(사용자 결정, Q3). ML 원칙 문서보다 이 파일이 우선한다(사용자 결정, Q4)
- 규칙 본문은 한 곳에 둔다(ADR-0071). 옮긴 것: PLAN-done 옮기기(meet-rag "결정과 PR의 순서", 루트 CLAUDE.md 세션 마무리 3), STATUS 형식(루트 CLAUDE.md 세션 마무리 4), SLICE 필수 절(meet-rag A1), EXP 필수 절·변형 번호(meet-rag B1), SPEC 미결 표시 형식(meet-rag D5). 원래 자리에는 경로만 남겼다. 그대로 둔 것: EXP 결과·결론·EXPERIMENTS 줄 형식(exp-judgment. exp-judge가 docs/CLAUDE.md를 불러오는지 보장되지 않음), 지연·비용·원인 분석(meet-rag B6 절차), drafts 사용(meet-rag), ADR 형식(README. 루트 CLAUDE.md 변경 기록의 항목 나열은 경로로 줄임)(사용자 결정, Q5)
- exp-judgment 5절에 결론 첫 줄 `- SPEC 판정: …`을, ADR README에 "병합된 ADR은 상태 줄만 고친다"를 더한다
- 새 형식은 앞으로 쓰는 문서에 적용한다. 기존 문서를 맞추는 일은 별도 PR로 한다(사용자 결정 2026-10-28)
