# ADR-0001 하네스 v2 구성: 검증·감사·판정을 작성 맥락과 분리

- 상태: 채택
- 날짜: 2026-09-29
- 커밋: f00a4f3

## 맥락

SLICE 구현과 EXP 판정을 작성자가 같은 맥락에서 직접 확인하면, 자기 결과에 맞춰 기준을 느슨하게 읽거나 평가 프로토콜 위반(test 접근, 보호 경로 수정)을 놓칠 수 있다.

## 결정

오케스트레이터 스킬 `meet-rag`(A SLICE, B EXP, C 세션 마무리)와 서브에이전트 셋을 둔다. `slice-verifier`는 완료 기준을 명령으로 판정하고, `protocol-auditor`는 diff를 `protocol-guard` 점검표로 감사하며, `exp-judge`는 `exp-judgment` 절차로 dev-full 결과를 판정한다. 구현과 문서 작성은 메인이 하고 판정은 에이전트에 맡긴다.

## 결과

`.claude/skills/meet-rag`, `.claude/skills/protocol-guard`, `.claude/skills/exp-judgment`, `.claude/agents/`의 에이전트 셋, CLAUDE.md 하네스 절. 이후 ADR은 모두 이 구성을 조정한다.

## 삭제 조건

검증·감사·판정을 사람이 직접 하거나, 작성 맥락과 분리된 다른 검토 수단(CI 자동 점검 등)이 같은 범위를 대신할 때.
