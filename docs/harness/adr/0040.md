# ADR-0040 colab CLI를 공식 저장소 main 고정 커밋으로 설치하고, 설치 패키지를 로컬에서 고치지 않는다

- 상태: 채택
- 날짜: 2026-10-14

## 맥락

- 하네스 대기 목록의 colab CLI 0.6.0 → 0.7.4 업데이트를 EXP-012 Colab 실행 전에 하고 작동을 확인하라는 사용자 지시가 있었다(2026-10-14)
- PyPI 0.7.4는 Windows에서 시작하지 못했다. `colab_cli/console.py`가 Unix 전용 `termios`를 무조건 import한다. 0.7.0\~0.7.3과 PyPI 0.6.0(uv 캐시의 7월 설치본 포함)도 같았다. 그동안 쓰던 0.6.0은 설치 뒤 로컬에서 고친 상태였던 것으로 보인다(사용자: colab-operator를 meet-rag 절차에 통합할 때 수정이 있었던 것 같다). 그 수정은 어디에도 기록되지 않아 다시 설치하자 원인을 바로 알 수 없었다
- googlecolab/google-colab-cli 이슈 #78·#100이 같은 문제다. 수정 PR #135가 2026-10-06 main에 병합됐지만 릴리스되지 않았다(0.7.4는 2026-09-26). 이슈 #155(오래 켠 세션에서 런타임 프록시 자격 증명이 갱신되지 않아 upload·download가 실패)는 0.7.4에서 고쳐졌다. EXP-009 업로드 멈춤, EXP-011 압축 뒤 fetch 멈춤과 증상이 비슷하다(같은 원인인지는 확인하지 않음)

## 결정

- 공식 저장소 main의 고정 커밋 d4f855d(0.7.5.dev6, 0.7.4 + #135 Windows 수정 + #158 + 의존성)로 설치한다. 다음 릴리스에 #135가 들어가면 PyPI 버전으로 돌아간다
- 설치한 패키지 파일을 로컬에서 고치지 않는다. 고쳐야 하면 공식 저장소의 수정 커밋으로 설치하고 이 기록처럼 남긴다
- colab-operator 본문을 새 버전의 `colab skill` 출력으로 바꾼다(keep-alive 데몬이 없어지고 백엔드가 커널 활동으로 세션을 유지한다). meet-rag E2에 설치 명령과 세션 유지 주의를 적는다

## 작동 확인 (CPU 세션 `meet-rag-clitest`, 2026-10-14 06:03\~06:08 UTC)

`colab_job.py` 함수로 확인했고 모두 성공했다: exec 6초, 코퍼스 288MB 업로드(gzip) 67초, 백그라운드 실행과 `poll` 64초, VM에서 만든 600MB 파일의 압축·다운로드(`fetch`) 108초, `colab console` 파이프 명령. 오래 켠 세션의 자격 증명 갱신(#155)은 5분 세션으로 확인할 수 없어 EXP-012 GPU 세션에서 본다.

## 결과

`.claude/skills/colab-operator/SKILL.md`(본문 교체, description 버전), `.claude/skills/meet-rag/SKILL.md` E2.

## 삭제 조건

google-colab-cli가 Windows 수정을 담은 버전을 PyPI에 릴리스해 그 버전으로 바꿀 때(설치 명령 항목).
