# ADR-0033 리뷰 가이드 구조 절을 분기 판단용으로 좁힘

- 상태: 채택
- 날짜: 2026-10-12

## 맥락

ADR-0016의 `pr-briefer`는 새 흐름이 생긴 SLICE·EXP PR에 다이어그램과 의사 코드를 쓰고, 노드와 단계마다 `file:line`을 달게 했다. 사용자는 순서도를 읽어도 내용을 파악하기 어렵고, 분기 없는 한 줄 파이프라인에는 순서도가 필요 없다고 지적했다(2026-10-12). 순서도와 의사 코드를 둔 목적은 여러 조건·분기가 있을 때 사용자의 판단을 돕는 것이다. 순서도가 들어간 PR 6개(#30·#32·#33·#37·#45·#46)에서 반복된 문제는 다음과 같다.

- 노드 라벨에 함수명·설명·`file:line`이 `<br/>`로 함께 들어가, 흐름보다 식별자를 먼저 해석하게 했다. 노드마다 `file:line`을 달라는 규칙이 원인이다
- 흐름 전체를 그려 이번 PR이 바꾼 곳이 드러나지 않았다(#46)
- 마름모에서 라벨 없는 화살표와 같은 두 노드 사이의 중복 화살표가 있었다(#46). 분기가 거의 없는 일렬 흐름에도 노드 10개짜리 그림을 그렸다(#30·#45)
- "판단할 곳"이 그림의 어느 분기인지 표시가 없었다
- 의사 코드가 그림과 같은 흐름을 되풀이하거나(#46) 줄마다 줄 번호를 달았다(#32·#37). 정상 흐름과 이어지지 않는 중단·복구 경로가 같은 그림에 섞였다(#33)

## 결정

`pr-briefer.md` `### 구조` 항목을 다시 썼다.

- 작업 종류와 관계없이 diff가 분기(조건, 건너뛰기·오류·재시도 경로, 모드 전환)를 둘 이상 더하거나 바꾼 경우만 쓴다. 분기가 없거나 하나뿐이면 절을 뺀다(사용자 결정). ADR-0016의 "다이어그램·의사 코드는 새 흐름이 생긴 SLICE·EXP PR에만 둔다"를 대체한다. 하네스·규칙 문서는 절차의 단계 순서나 갈림이 바뀐 것만 분기로 세고 산문 조건은 세지 않으므로, 대부분의 하네스 PR에는 여전히 그림이 붙지 않는다
- `flowchart LR`로 바뀐 분기와 그 앞뒤 한 단계만 그리고, 바뀌지 않은 구간은 노드 하나로 접는다. 새로 생기거나 바뀐 노드는 강조색(`classDef new fill:#fde68a,color:#111`)으로 칠한다(사용자 결정)
- 노드 라벨은 짧은 한국어 한 줄이고 식별자·`file:line`을 넣지 않는다. 근거는 그림 아래 노드 → `file:line` 표에 모은다. diff에서 확인한 동작을 쓴다는 원칙은 그대로다
- 조건은 마름모로 쓰고 나가는 화살표에 모두 조건 값 라벨을 단다. 판단할 곳에 해당하는 노드에 번호를 붙인다. 중단·복구 경로는 그림에 넣지 않는다
- 의사 코드는 그림에서 드러나지 않는 조건 세부(판정 순서, 경계값)가 있을 때만 쓰고, `file:line`은 함수 머리에 한 번 단다

description의 다이어그램 조건도 "분기가 둘 이상 생기거나 바뀐 PR"로 맞췄다.

트리거·정의 검증(서브에이전트)의 지적으로 다음을 더했다. 의사 코드의 `file:line` 위치를 작업 원칙과 맞추고, 노드 라벨을 따옴표로 감싸게 하고(괄호에서 파싱 오류), `\~` 규칙은 코드 펜스 안을 예외로 두었다. diff가 더하거나 바꾼 코드 안의 오류·재시도 경로는 그림에 넣고 코드 흐름 밖의 복구 경로만 뺀다. 판단할 곳에 번호를 매기고, 다시 호출하거나(pr-briefer) 코멘트를 반영할 때(git.md PR 절 4) 그림 번호도 맞춘다.
PR #51 사용자 코멘트로 다음을 바꿨다.

- 의사 코드를 그림의 하위 항목에서 떼어, 그림 유무와 관계없이 diff가 조건 세부(판정 순서, 경계값, 여러 조건의 조합)를 바꿨을 때 쓴다. 그림이 없을 때 의사 코드도 없는 경우가 많은 것은 조건 없는 일렬 처리에 옮길 알고리즘이 없어서이지, 그림과 동치여서가 아니다
- 조건에 따라 쓰는 에이전트·스킬이 달라지는 오케스트레이션의 갈림도 하네스 PR의 분기로 센다
- 판단할 곳의 질문이 바뀐 구간 밖의 단계(새 분기에 닿을지 정하는 앞 조건, 바뀐 출력을 쓰는 뒤 단계)에 걸리면 그 단계까지 이어 그린다. 이어 그린 노드는 칠하지 않는다. "판단에 도움이 되면"처럼 열어 두면 에이전트가 안전하게 전체를 그리는 쪽으로 기울어 처음 문제(바뀐 곳이 안 보임)로 돌아가므로, 판단할 곳 질문이 그 단계를 가리킬 때로 조건을 묶었다
- 강조색은 지금 값을 쓴다(사용자, 필요하면 나중에 수정)

## 결과

`.claude/agents/pr-briefer.md`(description, 작업 원칙, 출력, 다시 호출할 때), `.claude/rules/git.md` PR 절 4, ADR-0016 상태(일부 대체)와 ADR 목록. ADR-0016의 다이어그램 조건을 대체한다.

## 삭제 조건

리뷰 가이드에서 구조 절을 없애거나, 사용자가 PR 리뷰에 다른 시각 자료를 쓰기로 할 때.
