# ADR-0015 하네스 수정은 F 흐름으로, 첫 단계에서 harness:evolve 호출

- 상태: 채택
- 날짜: 2026-10-02
- 커밋: 85c7652

## 맥락

하네스를 고친 PR #19와 ADR 분리 브랜치에서 `harness:evolve`를 부르지 않고 기억으로 진행해, 변경마다 검증·description 트리거 검증·퇴행 확인이 빠졌다(사용자 지적). S4에서 `colab-operator`를 부르지 않은 것과 같은 유형이다. 절차로 정한 스킬 호출이 기억으로 대체되는 일이 반복된다.

## 결정

오케스트레이터에 F 흐름(하네스 수정)을 두고 0단계 대응에 넣는다. 첫 단계는 `harness:evolve`를 Skill 도구로 불러오는 것이고, 이어서 `chore/` 브랜치, 변경마다 frontmatter·참조 검증, description을 바꾸면 서브에이전트로 트리거 검증, ADR 기록, `protocol-auditor`, 수정안 확인 후 PR 순서로 한다. 사후 점검으로 PR #19의 `protocol-guard`·`protocol-auditor` description 트리거를 요청 9개로 검증했고(9개 모두 기대대로), 용어를 "평가 질의(summary_q)"로 맞췄다.

## 결과

`.claude/skills/meet-rag` 0단계·F절, STATUS 흐름 표기 `[F]`, CLAUDE.md 호출 조건, `protocol-guard`·`protocol-auditor` description. meet-rag description에는 하네스 수정 트리거를 넣지 않았다. 사용자가 하네스 수정을 요청하면 `harness:evolve` description이 이미 받으므로, 같은 문구를 넣으면 두 스킬이 경쟁한다. 이번 누락처럼 작업 중 Claude가 하네스를 고치는 경로는 CLAUDE.md 호출 조건과 대기 목록 규칙이 F 흐름으로 잇는다.

## 삭제 조건

하네스 수정 절차가 훅 등으로 강제되어 evolve 호출을 건너뛸 수 없게 될 때.
