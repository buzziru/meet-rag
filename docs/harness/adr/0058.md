# ADR-0058 공유 data/를 지우는 명령을 훅으로 막고, 위임 지시에 data/ 규칙을 넣음

- 상태: 채택
- 날짜: 2026-10-22

## 맥락

2026-10-22 13:04, S21 하위 세션(별도 worktree)이 main 비교용 임시 worktree에 원본 `data/`로 가는 junction을 두고 정리하면서 `git worktree remove --force`를 실행했다. 명령이 junction을 따라가 원본 `data/gen_eval`(669개: 생성 기록, judge 결과, judge 캐시, 검수 문서)과 `data/conditions`(4개)를 지웠고, Permission denied로 멈췄다. Windows 섀도 복사본(HarddiskVolumeShadowCopy13)에서 해시까지 같게 되살렸지만, 백업이 없었다면 유료 호출 결과인 judge 캐시와 생성 기록은 되살릴 수 없었다.

`data/`는 AI Hub 재배포 제한과 크기 때문에 git으로 추적하지 않아 revert로 되돌릴 수 없다. 원인은 둘이었다. 메인의 위임 지시에 `data/`가 공유 원본이고 지우면 안 된다는 내용이 없었고, 막는 장치도 없었다.

한편 사용자는 지난 작업에서 worktree의 산출물(감사, 생성, judge 결과)을 원본 `data/`에 junction으로 이어 반영한 적이 있고, 이것은 필요한 작업이다. 문제는 링크를 만든 것이 아니라 링크째 지운 것이다(사용자 설명 2026-10-22).

## 결정

- 훅 `data_delete_guard`(PreToolUse, Bash·PowerShell): 명령을 `&&`·`;`·`|`로 나누고, 삭제 동사(`rm`, `rmdir`, `Remove-Item`, `del`, `git worktree remove`, `git clean`, `.Delete()`, `find -delete`, Python 삭제 호출)가 든 구간의 대상만 본다
  - 막음(deny): 재귀 삭제나 `git worktree remove`의 대상이 링크이거나 안에 링크가 있을 때. 안내 메시지에 링크만 지우는 명령(`(Get-Item <링크>).Delete()`, `cmd /c rmdir <링크>`)을 적는다. 링크가 없는 worktree는 `git worktree remove --force`도 그대로 지운다
  - 사용자 확인(ask): worktree에서 도는 세션(`.git`이 파일)이 `data/` 아래(원본, 링크를 따라간 위치 포함)를 지우는 명령, `git clean -x/-X`, `data/` 경로가 든 Python 삭제 호출. 막으려는 것은 분리된 세션의 임의 삭제이고, 메인 체크아웃의 `data/` 삭제는 그대로 둔다(사용자 결정 2026-10-22). 처음에는 모든 세션에 확인을 띄웠고, 커밋 메시지에 적힌 삭제 명령까지 읽어 이 세션에서 확인 창이 잦았다(사용자 지적). 그래서 따옴표 안의 공백이 든 문자열(커밋 메시지 등)과 heredoc 본문은 명령으로 보지 않는다
  - 막음(deny)은 세션과 관계없이 건다. `data/` 삭제를 금지하는 것이 아니라, 명령이 링크를 따라가 원본을 지우는 경우만 막고 링크를 먼저 지우면 통과하기 때문이다
  - 그대로 둠: 링크를 만드는 명령, 링크만 지우는 비재귀 명령, `data/` 밖의 링크 없는 대상
  - `if` 조건으로 삭제 동사가 든 명령에만 훅을 띄운다(훅 하나에 약 0.5초, ADR-0055). 명령 해석은 낱말 단위 근사라 놓치는 형태가 있을 수 있고, 아래 위임 규칙이 함께 막는다
  - 보호하는 `data/`는 훅이 도는 체크아웃의 `data/`와, worktree에서 돌면 `.git` 파일(gitdir)로 찾은 원본 저장소의 `data/`다. 하위 세션은 `.claude/worktrees/<이름>`에서 돌아 원본 `data/`를 절대 경로로 지울 수 있다(리뷰 가이드 지적). 셸 와일드카드(`wt/*`)는 펼쳐서 대상으로 본다
  - 이동 명령(`mv`, `Move-Item`)은 훅이 보지 않는다. 이동은 원본이 다른 자리에 남아 되돌릴 수 있어, 위임 규칙("옮기지 않는다")으로만 막는다(protocol-auditor 보고)
- meet-rag 스킬 "공유 `data/`와 위임" 절: `data/` 안을 지우거나 옮기지 않고 지워야 하면 사용자 확인, worktree 산출물을 잇는 링크는 만들어도 되지만 지울 때는 링크만 지우는 명령을 쓴다, 하위 세션·서브에이전트에 일을 넘길 때 이 두 항목과 진행 중인 다른 작업이 쓰는 `data/` 파일을 지시에 적는다
- 백업(섀도 복사본 설정 확인, 판정 산출물 주기 백업)은 이번에 넣지 않았다(사용자 결정 2026-10-22, 훅과 위임 규칙만 적용)

검증: 훅 테스트(`.claude/hooks/test_data_delete_guard.py`, 33개)에서 실제 junction을 만들어 사고의 명령(`git worktree remove --force`)과 `rm -rf`·`Remove-Item -Recurse`·`rmdir /s`·`rm -rf <worktree>/*`가 막히고, 링크만 지우는 명령과 링크 없는 worktree 정리, `cd <저장소> && rm -rf <임시>`는 통과하며, worktree 세션의 원본 `data/` 삭제와 `git clean -fdx`는 확인을 띄우고 메인 체크아웃에서는 띄우지 않으며, 커밋 메시지·heredoc 본문의 삭제 명령은 무시하는 것을 확인했다. 이 세션에서 임시 폴더에 junction을 두고 `rm -rf`가 막히고, `rmdir <링크>` 뒤 같은 `rm -rf`가 통과하며 링크 대상 파일이 남는 것을 확인했다.

## 결과

`.claude/hooks/data_delete_guard.py`와 테스트, `.claude/settings.json`(PreToolUse Bash·PowerShell), `.claude/skills/meet-rag/SKILL.md`("공유 `data/`와 위임"). 삭제 동사가 든 명령마다 약 0.5초가 더해진다. 데스크톱 앱의 worktree 정리 기능은 Bash를 거치지 않아 이 훅이 보지 못한다. 링크를 만든 worktree는 정리 전에 링크를 먼저 지운다는 위임 규칙으로 막는다.

## 삭제 조건

`data/`의 판정 산출물을 git 밖의 버전 관리(예: 별도 백업 저장소, DVC)로 되돌릴 수 있게 되면 확인(ask) 범위를 줄인다. 링크를 따라가는 삭제 위험은 Windows junction을 쓰는 동안 남으므로 deny는 유지한다.
