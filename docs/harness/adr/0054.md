# ADR-0054 산출물 보존 원칙을 S15에 맞추고 PR 전 점검(P10)을 둠

- 상태: 채택
- 날짜: 2026-10-21

## 맥락

코드 리뷰 2026-10의 높음 6건(A-1·A-2·A-3·B-1·B-2·C-1)은 모두 산출물을 만든 설정과 대조하지 않거나 덮어쓰기를 막지 않는 유형이었고, S15(PR #122)에서 고쳤다. 사용자가 PR #122 리뷰에서 이를 규약에 넣지 않아도 되는지, 기존 지시가 없었는지 물었다.

- meet-rag 스킬 "구현 원칙"에 2026-10-14(f6589ee)부터 "산출물은 덮어쓰지 않는다"와 "실행 config에 따라 바뀌는 입력은 만든 기준을 기록하고 읽을 때 대조한다"가 있었다
- 조항이 "새 쓰기 경로를 만들면"으로 시작해 그 전 모듈(`splits.py` 09-29, `index.py` 10-01, `rerank.py` 10-12)은 고치지 않았다. 높음 5건이 여기서 나왔다
- 조항을 확인하는 단계(protocol-guard 점검표, 감사, 가이드)가 없어, 조항 이후 모듈(`gen_eval/review.py` 10-20, C-8)도 PR을 통과했다
- S15로 함수 위치가 `rag.search.write_guarded`에서 `rag.index`로 바뀌었고, 다시 만들면 값이 달라지는 출력은 시작 때 멈춘다(`refuse_existing`, PR #122 리뷰), 지문 대조(`check_basis`), 지문 없는 기존 산출물은 실행 기록과 대조한 뒤 `adopt_basis`로 받아들인다(S15 결정 사항 1)는 규칙이 생겼다

## 결정

- 스킬 "구현 원칙": `data/`에 쓰는 경로는 새로 만들 때와 기존 쓰기 경로를 고칠 때 모두(고치지 않는 줄은 그 작업에서 바꾸지 않는다) `write_guarded`(같은 입력이면 같은 내용) 또는 시작 때 `refuse_existing`(다시 만들면 값이 달라지는 출력)을 거친다. 지문은 `check_basis`로 대조하고, 지문 없는 기존 산출물은 대조 뒤 `adopt_basis`로만 받아들인다
- protocol-guard P10(산출물 보존): diff의 `data/` 쓰기 경로와 설정 의존 산출물을 읽는 새 경로, `adopt_basis` 실행의 대조 기록을 본다. 평가 오염이 아니라 기록 보존이라 위반과 따로 "보고"로 두고, 원래 목적의 결함인지는 메인이 정한다(사용자 결정 2026-10-21). 요청 해시 캐시·재개용 이어 쓰기가 보고되는 잡음은 관찰한 뒤 예외 문구를 정한다. protocol-auditor 출력에 보고 칸을 더하고, 두 description에 이 점검을 적었다(트리거 검증: should-trigger 4, near-miss 4 일치. 복구 요청으로 오발동하지 않게 대상을 "코드"로 한정)
- 점검을 새 에이전트나 slice-verifier에 두지 않았다. diff를 읽고 금지 조항을 대조하는 감사가 이미 PR마다 돈다

## 결과

`.claude/skills/meet-rag/SKILL.md`(구현 원칙), `.claude/skills/protocol-guard/SKILL.md`(P10, description), `.claude/agents/protocol-auditor.md`(description, 출력). 에이전트 정의 수정은 실행 중인 세션에 바로 반영되지 않으므로 다음 세션의 감사부터 적용된다.

## 삭제 조건

`data/` 쓰기가 모두 한 모듈(예: 산출물 저장 함수 하나)을 거치게 되어 코드 구조로 보장되면 P10을 지운다.
