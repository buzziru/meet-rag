# ADR-0077 앞 결정의 의도가 덮는 사례는 메인이 적용해 기록하고 묻지 않는다, G3 동결 sha 보호

- 상태: 채택
- 날짜: 2026-10-29

## 맥락

- 사용자 지적(2026-10-29): 이미 결정한 내용에 대해 작은 사례를 들고 와 "이것도 맞나, 이것까지 맞나"로 결정을 요구하는 일이 PR마다 반복돼 리뷰를 늦췄다
- 최근 병합 PR 19개(#160\~#185)의 리뷰 가이드 결정 항목 54개 중 23개가 원안을 바꾸지 않고 닫혔다. 집계는 번호 붙은 항목의 `(결정: ` 바로 뒤가 그대로·인정·동의·받아들임·승인·감수·지금대로·한계를 인정·데이터 한계로 용인·메인이 준비·규약과 맞음·금지 절과 P4로 시작하는 것이다(키워드 집계라 정당한 확인도 섞여 있다). #176 2(D-50)는 앞 결정이 답이었다. 이슈 #182(일일 종합) 16개 항목은 대부분 저장소를 읽거나 앞 결정으로 닫혔고, 사용자 결정은 ADR README 분류, H20 프롬프트, SPEC 표현처럼 일부에만 필요했다. #185 판단할 곳 1·2는 사용자가 "지난 결정으로 처리할 수 있다"며 돌려줬다
- ADR-0041이 확인형 질문과 이미 답이 있는 질문을 뺐지만, 답이 결정 문구에 그대로 있을 때만 걸렀다. pr-briefer 정의가 "사용자 지시를 해석해 정한 부분"과 "결정끼리 양립하는지"를 판단할 곳으로 두어, 앞 결정을 새 사례에 적용할 때마다 질문이 됐다. 일일 종합은 저장소를 보지 못한 채 모든 범위 밖 항목을 체크박스로 올려 관찰을 결정 요청으로 바꿨다. 메인은 가이드·종합 이슈의 질문을 앞 결정으로 닫히는지 보지 않고 넘겼다
- PR #185 판단할 곳 2(사용자 위임, 메인 판단): D-62의 대조 기준값 `multidoc.frozen_sha256`이 보호 목록에 없어, 동결 파일을 다시 만들고 이 값까지 고친 PR이 보호 경로 점검을 통과한다

## 결정

- 원칙: 결정 문구에 그 사례가 없어도 결정의 의도(막으려는 위험, 정한 기준)가 덮으면 메인이 적용하고 PR 본문 "메인이 정한 것"에 결정 번호와 입력→동작 사례로 적는다. 답을 기다리지 않고, 어긋나면 사용자가 리뷰에서 지적한다. 묻는 것은 덮는 결정이 없을 때, 두 결정이 같은 사례에 다른 답을 낼 때, 새 비용·위험을 감수할지 정할 때, 해석이 둘 이상이고 동작이 달라질 때다. CLAUDE.md 금지 절과 SPEC 평가 프로토콜을 좁히는 해석은 앞 결정이 있어도 묻는다(ADR-0041 유지)
- meet-rag "질문과 해석": 위 원칙과, 가이드·일일 종합·감사 관찰이 만든 질문도 넘기기 전에 앞 결정으로 닫히는지 본다는 문장. "적용 범위가 애매하면 묻는다"를 "갈려 동작이 달라지면 묻는다"로
- pr-briefer "판단할 곳": "사용자 지시를 해석해 정한 부분"을 위 네 경우로 바꾸고, 앞 결정 적용은 "메인에게"에 결정 번호와 사례로 적는다
- git.md PR 절 3: 본문에 "메인이 정한 것"을 두고, 범위 밖 항목은 결정 대기인지, 미룬 일·관찰이면 어디에 남겼는지 적는다
- 일일 종합 프롬프트: `(결정: …)` 표시가 붙은 판단할 곳은 모으지 않는다. 범위 밖 항목은 결정·확인 대기만 체크리스트에 올리고, 미룬 일·관찰은 "참고" 절에 한 줄씩만 적는다. 체크리스트 항목이 없으면 `NO_ITEMS`
- G3 동결 sha: CLAUDE.md 금지 절, protocol-guard P3, pr-briefer R3 목록에 `multidoc.frozen_sha256`을 더한다. D-15가 막으려는 것(동결 세트가 바뀜)과 같은 대상이다. protocol-guard description은 바꾸지 않는다(본문 P3이 기준이고 description은 호출 판단용이라 트리거가 바뀌지 않는다)

## 삭제 조건

"메인이 정한 것"으로 적용한 결정이 리뷰에서 뒤집히는 일이 반복되면 그 유형을 다시 질문으로 돌린다. 리뷰 가이드나 일일 종합을 쓰지 않게 되면 해당 항목을 지운다.
