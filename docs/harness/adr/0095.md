# ADR-0095 ML 문서 원칙에서 뺀 제안 중 PR 협업·코드 품질을 전역 규칙으로 올린다

- 상태: 채택
- 날짜: 2026-11-05

## 맥락

PR #217은 `docs/ML 프로젝트 문서 작성 원칙.md`에 회고 제안을 반영하면서, 에이전트와 일하는 방식에 가까운 C2(작성·검증 분리), C3(PR 리뷰 가이드), C4(폴더별 규약·정기 리뷰)를 넣지 않았다. 이 저장소의 하네스에는 셋 다 이미 있어, 올릴지는 다른 프로젝트에 미치는 영향의 문제다.

## 결정

사용자가 정했다(2026-11-05).

- C3·C4를 전역 `~/.claude/rules/project-practice.md`에 둔다. 플러그인으로 올리지 않는다
- C2는 전역 `delegation.md`의 "작성 과정의 맥락과 분리된 판단이 필요한 review·test·검증" 위임과 겹쳐 뺀다
- C3의 기록처 "STATUS나 PLAN"은 그 문서가 없는 저장소에 맞지 않아 "저장소의 진행 문서"로 고쳐 쓴다

감수하는 것: 작은 일회성 저장소의 세션에도 이 규칙이 읽힌다.

## 결과

저장소 하네스 파일은 바꾸지 않았다. 전역 파일은 저장소 밖이라 이 PR의 diff에 나오지 않는다. 사용자 승인을 받았지만 세션의 자동 모드 분류기가 전역 규칙 쓰기를 거부해(Self-Modification) 세션에서 만들지 못했고, 우회하지 않았다. 사용자가 아래 내용으로 직접 만든다.

```markdown
# 프로젝트 운영

## PR 협업

PR에는 사람이 판단할 곳과 안 읽어도 되는 파일을 적은 리뷰 가이드를 둔다. 미룬 일은 PR 본문만 기록처로 쓰지 않고 저장소의 진행 문서에 적는다.

## 코드 품질

폴더별 규약(CLAUDE.md)과 정기 코드 리뷰는 프로젝트 시작부터 둔다. 품질 조치를 뒤늦게 더하면 쌓인 코드를 한꺼번에 고치게 된다.
```

## 삭제 조건

전역 규칙 파일을 지우거나 옮기면 이 ADR의 상태를 고친다.
