# ADR-0046 PR 일일 종합 이슈를 GitHub Actions로 만든다

- 상태: 채택
- 날짜: 2026-10-20

## 맥락

- 사용자는 PR을 한 번 읽고 병합한 뒤 다시 열지 않는다. PR #75\~#107 33개 중 22개 본문에 "범위 밖" 항목(약 38개)이 있었고 모두 병합된 본문에만 남았다. 이슈는 쓰지 않고 있었다
- 자동 병합과 판단할 곳에 대한 AI 사전 의견도 검토했으나 넣지 않는다. 자동 병합 대상(양방향이고 판단할 곳 없음, 또는 `docs/`만 바꾼 PR)은 33개 중 7개였고 대부분 몇 줄짜리 문서였다. 사전 의견은 사용자만 정할 질문(ADR-0041)에 같은 계열 모델의 답을 먼저 달게 된다(사용자 결정 2026-10-20)

## 결정

- `.github/workflows/daily-pr-digest.yml`이 매일 00:00 KST(`0 15 * * *`)와 수동 실행(`workflow_dispatch`)으로 돈다. 대상은 직전 성공 실행의 시작 시각 이후(처음에는 지난 24시간) 열렸거나 병합된, 저장소 소유자의 PR이다. 예약 실행이 늦어지거나 수동 실행이 끼어도 PR이 빠지거나 겹치지 않게 하려는 것이다. 대상 PR이 없으면 Claude를 부르지 않고 끝낸다
- 대상 PR이 있으면 `anthropics/claude-code-action@v1`이 Claude Opus 5.5로 `.github/prompts/daily-pr-digest.md` 지시를 따라 `daily-digest` 라벨 이슈를 하루 하나 만든다. 모으는 것은 답 없는 "판단할 곳", 반영 기록 없는 사용자 코멘트, 처리되지 않은 "범위 밖" 항목, 열린 이전 종합 이슈 중 처리된 항목, 사용자가 놓쳤을 수 있는 것이다(모델·이슈 단위·건너뛰기는 사용자 결정 2026-10-20)
- 인증은 Anthropic 워크로드 ID federation이다. 저장소 secret에 API 키를 두지 않는다. federation 규칙의 subject를 `main` 브랜치로 묶어 예약·수동 실행만 토큰을 받게 한다. 규칙·조직·서비스 계정·워크스페이스 ID는 식별자라 Actions 변수(vars)에 둔다
- 사용자가 놓쳤을 수 있는 것(지시 5번)은 병합 뒤에 모으는 항목이라, 리뷰 전에 판단할 곳에 의견을 다는 것(위에서 넣지 않기로 한 것)과 다르다. 사용자가 요청한 "빼먹은 것"이 이 항목이다
- Claude 도구는 파일 읽기, `gh pr`·`gh issue` 조회와 이슈 생성, `gh api repos/{저장소}/pulls…`(줄 코멘트 조회)로 한정한다. 도구 패턴은 접두 일치라 `gh api`에 `-X POST`를 붙인 쓰기를 막지 못한다. 쓰기의 상한은 GitHub 토큰 권한(`issues: write` 외에는 읽기)이고, 이슈 생성 밖의 쓰기 금지는 지시로만 건다
- 공개 저장소라 외부인이 연 PR 본문의 지시가 Claude에 들어갈 수 있다. 대상 PR을 저장소 소유자가 연 것으로 거르고, PR 코멘트·리뷰도 소유자가 쓴 것만 읽게 지시한다. checkout은 `persist-credentials: false`로 해 `.git/config`에 토큰을 남기지 않는다. Claude의 `gh`는 액션에 넘긴 `github_token`을 쓰므로 Claude가 쓸 수 있는 GitHub 권한은 위 토큰 권한과 같다
- 판단할 곳·코멘트·범위 밖·놓친 것은 대상 기간에 병합된 PR에서만 모으고, 열린 PR은 목록에 상태만 적는다. 열린 날과 병합된 날에 같은 항목이 두 번 올라가지 않게 하려는 것이다
- 이슈는 공개되므로 질의 원문·기대 답·회의록 원문을 옮기지 않는다(D-31)

## 결과

- 추가: `.github/workflows/daily-pr-digest.yml`, `.github/prompts/daily-pr-digest.md`
- 지시 파일은 PR 본문의 "리뷰 가이드"·"판단할 곳"·"범위 밖"·"코멘트 반영" 절 이름에 기댄다. `.claude/rules/git.md` PR 절이나 `pr-briefer` 형식에서 이 이름을 바꾸면 지시 파일도 바꾼다
- 비용은 콘솔 크레딧에서 나간다. PR이 있는 날 한 번에 약 $0.3\~1로 추정해(측정 전) 보고했고, 사용자가 이를 보고 Opus 5.5로 진행하기로 정했다(2026-10-20). 첫 실행 사용량으로 확인한다. 하루 상한은 `--max-turns 40`뿐이다
- 예약·수동 실행은 기본 브랜치의 워크플로 파일로만 돌고 federation subject도 `main`이라, 병합 전에는 시험할 수 없다. 첫 수동 실행에서 확인할 것: 기본 GitHub 토큰으로 Claude GitHub App 없이 동작하는지, 지금 권한으로 액션이 동작하는지(Claude의 `gh`가 토큰을 받는지 포함), 사용량

## 삭제 조건

- 이슈가 처리되지 않고 쌓이거나, 사용자가 종합 이슈를 읽지 않게 되면 워크플로를 지운다
