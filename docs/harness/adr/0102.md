# ADR-0102 앞 기록의 표시에 왜 바뀌었는지를 적는다

- 상태: 채택
- 날짜: 2026-11-05

## 맥락

전체 파이프라인 점검(`docs/reviews/2026-11-pipeline-review.md`)에서 표시 37건(45줄)을 붙이며 D-14를 어떻게 할지 물었다. ADR-0049는 남은 에이전트 이름을 과거 실행 기록이라 고치지 않는다고 적었다. 사용자는 표시를 붙이라고 정하고 기준을 말했다. 과거에 어떤 결정을 했고 어떻게 변했고 왜 변했는지를 기록으로 남겨 당시 결정의 의도를 알 수 있게 하고, 뒤에 번복이나 변경을 정할 때 어떤 조건이 변해서 일어나는지 추적할 수 있게 한다(2026-11-05).

ADR-0071의 형식(`이후 변경: 무엇이 어떻게(D-새번호)`, `→ D-새번호`)은 무엇과 어디서만 요구해, 왜를 적지 않아도 형식을 지킨다. 초안 표시도 대부분 번호만 가리켰다.

## 결정

1. 표시(`이후 변경`, `대체`, `→`, `보강`, `정정`)에는 무엇이 어떻게 바뀌었는지와 왜 바뀌었는지(어떤 조건이 변했는지)를 적는다. 뒤 결정의 이유를 한 구절로 옮기고, 그 이유가 길면 원본을 가리킨다. 이유를 기록에서 찾지 못하면 찾지 못했다고 적는다
2. 과거 실행 기록의 원문은 고치지 않는다(ADR-0049 그대로). 표시는 원문을 고치는 일이 아니므로 지운 에이전트를 적은 결정에도 붙인다

감수하는 것: 표시가 길어진다. 이미 붙은 표시는 소급해 고치지 않는다.

## 결과

`docs/CLAUDE.md`의 "당시 기록"과 "DECISIONS.md" 절을 바꿨다. 입력→동작: 뒤 결정이 앞 결정의 대상을 지우면 `→ D-NN`만 적지 않고 `이후 변경(ADR-0049): 두 에이전트를 지웠다. G3 동결로 생성이 끝났기 때문이다`처럼 적는다. 감사는 protocol-guard P12가 표시 유무를 보는 그대로이고, 이유의 유무는 작성 때 지킨다.

## 삭제 조건

프로젝트를 마쳐 결정을 더 쌓지 않으면 지운다.
