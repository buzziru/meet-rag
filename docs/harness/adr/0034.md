# ADR-0034 main을 맞출 때 병합된 로컬 브랜치 정리

- 상태: 채택
- 날짜: 2026-10-12

## 맥락

`git.md` 기본 규칙 7은 "병합 후 브랜치를 삭제한다"였지만, 누가 어느 시점에 어느 쪽(원격·로컬)을 지우는지 정하지 않았다. 사용자는 PR을 병합하며 원격 브랜치를 지우고, Claude는 핸드오프 때 `git pull --ff-only`만 했다. 2026-10-12 세션 시작 때 main에 병합된 로컬 브랜치 12개가 쌓여 있었다. 그중 하나(`chore/multidoc-checker-agent`, PR #33)는 원격 브랜치도 남아 있었다. 사용자가 병합 확인 때 로컬 브랜치도 맞춰 지우는 규칙을 요청했다.

## 결정

`git.md`에 "main 맞추기" 절을 두고, main을 원격과 맞출 때마다(세션 시작, PR 병합 확인, 핸드오프) 이 절차를 쓴다.

- `git fetch --prune` 뒤 `git pull --ff-only`
- `git branch --merged main`의 브랜치를 `git branch -d`로 지운다. `-D`는 쓰지 않아 병합되지 않은 커밋을 잃지 않는다
- 원격이 `gone`인데 병합되지 않은 브랜치, 병합됐는데 원격이 남은 브랜치는 지우지 않고 사용자에게 알린다. 앞의 경우는 병합하지 않고 닫은 PR일 수 있고, 뒤의 경우는 원격 삭제가 사용자 몫이기 때문이다

기본 규칙 7에 원격은 사용자가, 로컬은 Claude가 지운다고 나눠 적었다.

## 결과

`.claude/rules/git.md` 기본 규칙 7, 세션 시작 절, 새 "main 맞추기" 절, 핸드오프 1단계.

## 삭제 조건

GitHub 저장소 설정이나 다른 도구가 로컬 브랜치 정리를 맡게 될 때, 또는 사용자가 원격 브랜치 삭제를 Claude에게 넘길 때(이 경우 절차를 다시 쓴다).
