# ADR-0089 앱 화면 검증에 Aside를 쓰고 대상 주소는 실행마다 넘긴다

- 상태: 일부 대체(→ 0099)
- 날짜: 2026-11-04

## 맥락

S35·S36에서 화면 모양과 실제 클릭은 사용자가 눈으로 봐야 했다. 메인이 DOM 스크립트로 확인한 S36 점검은 스크립트 14번이 걸렸고, 접힌 근거 칸 때문에 실제 링크 클릭은 끝내 확인하지 못했다. 사용자의 주 브라우저는 Aside이고(2026-11-04), Chrome 확장은 연결되어 있지 않다.

## 결정

`meet-rag` 스킬에 "화면 검증" 절을 둔다. 눈으로 볼 일은 `aside exec`, 값으로 판정할 일은 `aside repl`에 맡기고, 판정에 걸리는 값은 메인이 다시 확인한다. 범위는 고정 주소가 아니라 실행마다 넘기는 대상 주소 하나로 건다. localhost로 고정하면 배포 뒤 Space 검증에서 규칙을 다시 고쳐야 한다(사용자 지적). 처리처 추가는 D-77이다.

## 결과

`.claude/skills/meet-rag/SKILL.md`(화면 검증 절), `CLAUDE.md`(명령 한 줄, 허용 처리처)에 반영했다. CLI와 `aside-browser` 스킬은 전역 설치라 저장소에 두지 않는다(`aside skills install --target claude-code`). 훅은 더하지 않는다. 첫 시험(S36 화면 점검, 353초)은 항목 4개를 재현 단계와 함께 보고했고, 메인이 실제 링크 클릭을 재확인해 일치했다. 한글 필터 실패 보고는 자동화 입력 때문이었다(사용자 직접 입력에서는 동작). 사용량은 사용자의 클로드 구독에서 차감되어 재지 않는다(기본 Sonnet 5.5 medium, 사용자 2026-11-04).

## 삭제 조건

Aside를 쓰지 않게 되면 지운다.
