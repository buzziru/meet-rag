# ADR-0069 생성 EXP의 판정·실행 절차를 하네스에 넣음

- 상태: 채택
- 날짜: 2026-10-27

## 맥락

SPEC "생성 단계 평가"(D-53)가 생성 EXP의 판정 규칙(종합 지표, δ 0.02, 기준별 하락 안전 조건, 과잉 거부 안전 조건)을 정했고, S27(PR #167, D-55)이 그 판정을 내는 `rag.gen_eval.compare`를 만들었다. 하네스에는 검색 EXP 판정(dev-full 순위 파일, Recall@5)만 있어 H10 같은 생성 EXP를 B 흐름으로 돌리면 exp-judge가 판정할 입력도, 메인이 따를 생성·judge 실행 절차도 없었다. PLAN "하네스 반영" 항목은 SPEC 개정 뒤 생성 실험 착수 전에 이것을 하기로 했고(사용자 결정 2026-10-19), 메타데이터 판정 부분은 ADR-0065에서 먼저 반영했다.

대기 목록(2026-10-19 항목)은 생성 판정 스킬을 따로 두는 안과 B 흐름에는 갈래만 두는 안을 적었다. B 본문에 절차를 더하면 다른 지시가 묻히기 때문이다.

## 결정

- `exp-judgment` 6절: 생성 EXP는 judge가 `rag.gen_eval.compare`를 직접 다시 돌려 메인이 준 비교 결과 JSON과 대조하고, `verdict`와 걸린 조건(`failed`)을 판정으로 쓴다. 표를 손으로 적용하지 않는다. 명령이 멈추면(gen-full이 아님, judge 다름 등) 판정하지 않고 보고한다. 보류의 예외 채택은 사용자가 기준별 값을 보고 정하고(D-28·D-33, D-53 결정 6), 기각은 예외 채택 대상이 아니다(ADR-0037). 기준별 값(충실성, 관련성, 종합 지표, 포함도(보조), 과잉 거부율)과 report 출력의 참조 사용 불가·거부 교차 집계·judge 형식 오류를 보고하고, EXPERIMENTS.md에는 "생성 단계" 표를 따로 둔다(검색 표의 열이 Recall@5라 맞지 않는다). 스킬을 따로 만들지 않은 것은 SPEC 우선·해석 분리·기록 원칙(1\~5절)을 함께 쓰기 때문이다
- `exp-judge`: 생성 EXP 판정 원칙 한 줄과 입력(judge 결과 파일, 비교 JSON, report 명령)을 더한다
- `meet-rag` B: 생성 EXP 갈래 한 단락만 두고 절차는 `references/gen-exp.md`에 둔다. 절차는 B1(SPEC 생성 판정 절 옮김, 기준은 S25 베이스라인, judge는 바꾸는 것에 넣지 않음), B2(생성·judge 비용·시간을 가까운 실측에서 질의 수 비율로 보고·승인), B3(gen-small 작동 확인 뒤 gen-full, `LANGSMITH_TRACING=false`, 저장 응답을 지우지 않고 `judge.rep`로 재채점, 결과 경로가 있으면 경로를 바꿈, 지시 버전이 바뀌면 기준도 다시 채점, gen-small에서 실행 오류·설정 누락이 있으면 고쳐 다시 확인, 형식 오류 수를 실행마다 기록하고 기준보다 많으면 판정 전에 사용자에게 알림), B4(judge 입력)다
- `protocol-guard`: P2에 gen-small 점수로 판정하는 것을 더하고, P11(judge 지시·판정표·기본 judge 설정의 동결, D-49·D-50)을 둔다. 동결 대상은 CLAUDE.md 보호 경로가 아니라 테스트로 막기로 해서(D-49) P3에 넣지 않았다

## 결과

`.claude/skills/exp-judgment/SKILL.md`, `.claude/agents/exp-judge.md`, `.claude/skills/meet-rag/SKILL.md`(B 머리, B4), `.claude/skills/meet-rag/references/gen-exp.md`(새 파일), `.claude/skills/protocol-guard/SKILL.md`(P2, P11). 대기 목록의 "주기적 사람 재확인"은 블라인드 확인 중단(D-51)으로 넣지 않았고, "judge 반복 흔들림 대비 판정"은 SPEC의 δ·허용폭이 변동 폭(D-50·D-53)으로 정해져 따로 넣지 않았다. 생성 단계 test 1회는 ADR-0067에서 P1에 있다.

## 삭제 조건

SPEC "생성 단계 평가 > 판정"이 바뀌거나 `rag.gen_eval.compare`의 인자·출력 키(`verdict`, `failed`, `metrics`, `check_settings_diff`)가 바뀌면 `exp-judgment` 6절과 `gen-exp.md`를 함께 고친다. judge 동결이 풀리거나 보호 경로로 옮겨지면 P11을 고치거나 지운다.
