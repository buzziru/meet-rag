# ADR-0032 질의 쪽 라벨을 검색 입력으로 쓰는지 감사(protocol-guard P9)

- 상태: 채택
- 날짜: 2026-10-08

## 맥락

D-19로 메타데이터를 질의 조건 방식(H14)으로 쓰기로 했고, S10은 문서에 화자 필드를 더한다. 평가 질의 레코드에는 정답 문서에서 온 필드(`doc_id`, 정답 문서의 화자 등)가 함께 있다. 질의 조건 코드가 질의 텍스트 대신 이 필드를 `qid`로 이어 쓰면 정답이 검색에 샌다. PLAN H12에 "질의 행의 라벨을 그대로 쓰면 정답이 샌다"는 문장이 있지만 감사 점검표(protocol-guard)에는 없어, `protocol-auditor`가 이 경로를 보지 않았다. 사용자가 H14·S10 전에 하네스를 먼저 고치라고 지시했다(2026-10-08).

## 결정

protocol-guard에 P9를 더했다. 검색(색인·질의 처리·순위 결정) 경로가 평가 질의 레코드의 `query` 밖 필드나, 원천 라벨의 QA 단위 필드를 `qid`로 이어 읽으면 위반이다. 채점과 분석 노트북은 해당하지 않는다. 문서 쪽 메타데이터는 정상이다. 문서에 붙인 QA 라벨 유래 필드(S10의 화자)는 쓸 수 있지만, single-doc 정답 문서의 그 값이 질의를 만든 QA 라벨에서 온다는 단서가 EXP 문서에 없으면 보고한다. description은 바꾸지 않았다(감사자는 점검표 본문을 읽는다).

## 결과

## 삭제 조건

평가 질의 레코드에서 정답 관련 필드를 분리해 검색 코드가 읽을 수 없게 만들 때.
