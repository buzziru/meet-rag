# ADR-0017 multi-doc 질의 생성 에이전트 multidoc-writer

- 상태: 채택
- 날짜: 2026-10-06
- 커밋: (PR 병합 후 기록)

## 맥락

S8은 후보 집합마다 정답 문서가 2개나 3개인 질의를 생성하고 다른 모델로 검사한다(`docs/slices/08-multidoc-queries.md`). 사용자는 생성은 Claude Code Sonnet 에이전트, 검사는 OpenRouter `openai/gpt-6-luna`로 정했다(2026-10-05). 같은 모델로 생성·검사하면 같은 편향이 두 단계에 겹치기 때문이다. 지금까지 에이전트는 모두 검증·감사·판정용이었고 생성 작업자는 없었다. 메인(Opus)이 직접 생성하면 이 결정과 다른 모델이 쓰게 된다.

## 결정

- `.claude/agents/multidoc-writer.md`를 둔다. `model: sonnet`, 도구는 Read·Write뿐이다. Bash·Grep이 없으면 지정 파일 밖을 찾아 읽을 수단이 줄어든다
- 생성 지시 본문(문서 선택, 질의 작성 규칙, 출력 형식)은 에이전트 정의가 아니라 S8 산출물 `configs/multidoc/prompt/gen_vN.yaml`에 둔다. 지시는 G3 검수 뒤 바뀔 수 있는 실험 대상이라 S6 프롬프트처럼 버전으로 남긴다. 정의에 두면 지시를 고칠 때마다 하네스 변경과 ADR이 따라온다
- 정의에는 읽는 범위(지시 파일, 생성 입력, 고른 문서 원문)와 읽지 않는 것(평가 질의, 분할, 검색 결과)을 이유와 함께 적는다(SPEC 누수 방지)
- 지시 파일이 정의보다 우선하는 것은 문서 선택·질의 작성 규칙·출력 형식뿐이다. 읽기 범위와 덮어쓰기 금지는 지시 버전이 바꿀 수 없다(리뷰 가이드 지적)
- 메인은 프롬프트에 입출력 디렉터리를 함께 넣고, 처음 부르기 전에 후보 집합 수와 예상 소요 시간을 보고해 승인받는다(SPEC 자원 제약, 감사 지적)
- 출력 파일이 있으면 덮어쓰지 않는다. 파일럿 결과를 본 생성에서 재사용한다는 사용자 요구를 에이전트 쪽에서도 지킨다
- 오케스트레이터 에이전트 표에 넣고, 검증 에이전트가 아니라 생성 작업자라고 적는다. "구현과 문서 작성은 메인이 직접"이라는 실행 모드의 예외이기 때문이다

## 결과

`.claude/agents/multidoc-writer.md`(신규), `.claude/skills/meet-rag/SKILL.md` 에이전트 표, `docs/harness/adr/README.md`. 에이전트 신설은 `harness:harness`의 범위지만 ADR-0016과 같이 구성 확장이 작아 F 흐름(`harness:evolve`)으로 했다. 생성 지시 파일과 호출 코드는 S8 브랜치(`feat/s08-multidoc-queries`)에서 만든다.

Read·Write 도구에는 경로 제한이 없어, 읽기·쓰기 범위는 지시문으로만 막는다. 설정의 deny 규칙은 메인과 다른 에이전트에도 걸려 쓰지 않았다.

## 삭제 조건

G3에서 세트를 동결해 multi-doc 질의를 더 생성하지 않을 때. 다시 생성하게 되면 되살린다.
