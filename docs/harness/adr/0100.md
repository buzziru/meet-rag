# ADR-0100 세션 간 메시지의 쓰던 글은 `draft`를 먼저 보고, 충돌 표식과 파일 끝 줄바꿈을 점검한다

- 상태: 채택
- 날짜: 2026-11-05

## 맥락

하네스 대기 목록의 네 항목을 함께 반영한다.

- ADR-0097의 `draft` 확인이 오탐한다는 사용자 지적이 있었다. Claude 추천 문구가 `draft`에 나와 입력 칸이 비었는데도 전송을 미뤘다. 대기 목록에는 `❯` 줄을 기준으로 삼는 안이 적혀 있었다
- 병합 커밋 8f60f69(PR #225)에 `docs/SPEC.md` 충돌 표식이 들어갔고 다음 커밋에서 고쳤다. `file_damage_check`는 충돌 표식을 보지 않았다
- 스크립트로 파일 끝에 덧붙이다 `.gitignore` 두 줄이 붙은 채 커밋됐다(S39b)
- `meet-rag` 스킬에 Vercel 작업 절이 없다

시험용 Orca 터미널에서 Claude를 띄우고 `orca terminal read --screen --json`을 비교했다(2026-11-05).

| 상태 | `draft` | `❯` 줄 |
| --- | --- | --- |
| 빈 입력 칸, 시작 직후 | 없음 | `Try "edit <filepath> to..."` |
| 빈 입력 칸, 응답 뒤 | 없음 | 빈 줄 |
| 글자 입력 중 | `시험글자` | 빈 줄 |

글자는 `orca terminal send`(Enter 없이)로 Claude 입력 칸에 넣었다. 사용자가 Orca 화면에서 직접 치는 경우는 시험하지 않았다. 추천 문구는 응답 두 번으로 재현하지 못해, `draft`에 나온다는 것은 사용자 관찰로만 안다. 사용자가 제안한 입력 커서 위치로 구분하는 방법도 시험했다. `read`와 `show` 출력에 입력 커서 값이 없고(`nextCursor` 등은 출력 줄 번호다), `tailRows`에 글자 색이 없으며, 기본 `read`는 이스케이프 문자를 지워 CLI로는 읽을 수 없다.

## 결정

1. 쓰던 글은 `draft`를 먼저 본다. `❯` 줄이 비었다고 입력 칸이 빈 것으로 보지 않는다. 실제 입력 중에도 `❯` 줄이 비어 보여, 이 기준이면 메시지가 쓰던 글에 섞인다. `draft`가 없어도 `❯` 줄에 `Try "…"` 안내 문구 말고 다른 글자가 있으면 보내지 않는다. 직접 친 글은 시험하지 않았고, ADR-0097이 막으려는 사고가 섞임이기 때문이다
2. `draft`가 있으면 기다렸다 다시 보고, 같은 글이 남아 있으면 그 문구를 보여 주고 보내도 될지 사용자에게 묻는다. 메인이 정했다. 사용자가 다르게 정하면 바꾼다
3. `file_damage_check`가 줄 맨 앞의 충돌 표식(`<`나 `>` 7개와 공백)을 본다. `git commit`이 든 명령 뒤에도 돌고, 이때는 마지막 커밋이 바꾼 파일을 함께 본다. 충돌 표식은 작업트리를 보는 것만으로는 커밋한 뒤 놓치기 때문이다. 막지 않고 알리므로 push 전에 고친다
4. 파일 끝에 덧붙일 때는 Edit 도구로 하거나 끝 줄바꿈을 먼저 본다. 끝 줄바꿈이 없는 것은 정상 파일에도 있어 훅으로 알리면 오탐이 되므로 스킬의 규칙으로만 둔다
5. `meet-rag` 스킬에 "Vercel 작업" 절을 둔다(`vercel-cli` 스킬 먼저, Git 연결 배포만, CLI 사용)

감수하는 것: 결정 2는 추천 문구일 때도 질문이 한 번 늘어난다. 결정 3은 `git commit` 명령마다 훅 하나만큼(약 0.5초, ADR-0055) 늦어지고, 같은 명령에 push를 묶으면 알림이 push 뒤에 온다. `git merge --continue`처럼 `git commit` 문자열이 없는 명령 뒤에는 마지막 커밋을 보지 않는다. 반복되면 그때 넓힌다.

## 결과

`.claude/rules/sessions.md`, `.claude/hooks/file_damage_check.py`와 테스트, `.claude/settings.json`, `.claude/skills/meet-rag/SKILL.md`를 바꿨다. ADR-0097의 `draft` 확인은 결정 1·2로, ADR-0055의 검사 대상과 보는 명령은 결정 3으로 일부 대체된다.

입력→동작: `draft`에 같은 글이 남아 있으면 보내지 않고 사용자에게 묻는다. `draft`가 없고 `❯ Try "edit…"`만 있으면 보낸다. `draft`가 없어도 `❯ 수정해 줘`처럼 다른 글자가 있으면 보내지 않는다. 병합 커밋에 충돌 표식이 남으면 커밋 직후 `spec.md:2: 병합 충돌 표식이 남아 있다`처럼 알린다.

## 삭제 조건

결정 1·2는 다른 세션과 병행하지 않게 되거나 Orca가 추천 문구와 쓰던 글을 구분해 주면 지운다. 결정 3은 ADR-0055와 함께 지운다.
