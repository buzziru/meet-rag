# ADR-0024 작업자 풀 큐 보조 스크립트와 끝까지 읽기

- 상태: 채택
- 날짜: 2026-10-08
- 커밋: aca7ac3, fff6e34, 이후 PR #43 정리 커밋

## 맥락

G3 본 생성에서 메인이 작업마다 `pool_id`를 손으로 프롬프트에 옮기다 작업 274·290에서 항목을 빠뜨렸다(`law-0235`, `questioner-0029`). 스크래치 스크립트로 작업 번호에서 항목을 읽어 해결했다.

같은 본 생성에서 작업자가 긴 입력의 일부만 읽고 출력을 썼다. 한 줄이 Read 한도를 넘는 검사 입력 12개는 보류했고, `questioner-0305`는 70KB 입력의 일부만 읽어 `answerable=false`를 냈다. 생성 작업자도 긴 원문의 일부만 읽었다(gen 52·54·94). 검사 입력은 PR #40에서 긴 줄을 나눴다. 사용자는 PR #40 코멘트에서 그 목적을 "에이전트 Read가 한 번에 읽을 수 있는 길이 제한이 있고, 드물게 문서 일부만 읽는 경우가 있어서"라고 남겼다. 생성 입력은 아직 나누지 않았다.

## 결정

- `.claude/skills/meet-rag/scripts/worker_queue.py`를 둔다. `plan`은 대기 항목을 작업으로 묶고(기존 작업 목록 파일은 덮어쓰지 않음), `start`는 출력이 없는 항목만 출력하며 `running`을 기록하고, `done`은 출력을 대조해 `done`·`partial`을 기록한다. 작업 번호는 작업 목록 파일마다 1부터라 큐 기록에 파일 이름을 함께 남긴다. 프롬프트의 항목 목록은 `start` 출력을 그대로 붙인다. 남은 일의 기준은 여전히 출력 파일이다
- `multidoc-checker`·`multidoc-writer` 정의에 입력을 끝까지 나눠 읽고, 끝까지 읽지 못하면 그 후보 집합을 건너뛰고 보고한다고 적는다. 일부만 읽고 쓴 출력은 형식 검사를 통과해 판정까지 가므로, 코드가 아니라 작업자가 멈춰야 잡힌다

## 결과

`.claude/skills/meet-rag/scripts/worker_queue.py`, `tests/test_worker_queue.py`, `SKILL.md` 작업 큐 기록·작업자 풀 절, `docs/slices/08c-checker-agent.md` 큐 기록 문장, `.claude/agents/multidoc-checker.md`, `.claude/agents/multidoc-writer.md`.

- 생성 입력(`gen_in`·`docs`)의 긴 줄 나누기는 코드 변경이라 다음 추가 생성 때 한다(STATUS 개선 후보). Read의 offset/limit는 줄 단위라 한 줄이 한도를 넘으면 나눠 읽어도 끝까지 못 읽는다. 줄을 나누기 전에 생성하면 그런 후보 집합은 건너뛰어지므로, 스킬 "실행 순서"에 생성 전에 줄 나누기와 안건 목록 중복 제거를 먼저 넣으라고 적었다(PR #43 사용자 코멘트)
- 건너뛴 항목은 출력 파일이 없어 계속 대기로 남는다. 같은 입력이면 다시 실패하므로 메인이 다시 띄우지 않고 진행 기록에 적어 사용자에게 보고한다. 보류를 스크립트에 기록하는 기능(`hold`)은 넣었다가 뺐다. 필요했던 경우가 G3 긴 줄 12개 한 번뿐이라 장치를 둘 만큼 반복되지 않았다(ADR-0026)

## 삭제 조건

작업자 풀을 더 쓰지 않거나, 항목 배정을 하네스가 대신 맡게 되면 스크립트와 절을 지운다.
