# ADR-0061 wrap_up 보고 훅을 없앰

- 상태: 채택
- 날짜: 2026-10-26

## 맥락

ADR-0052는 Claude Code 업데이트 뒤 본문 보고 없이 질문 상자(wrap_up `ask`)만 띄우는 일이 반복돼, 본문이 400자 미만이면 wrap_up을 막는 PreToolUse 훅(`wrap_up_report_guard.py`)을 달았다. ADR-0060은 같은 메시지의 본문이 transcript에 늦게 기록돼 0자로 세던 문제를 tool_use 행을 기다려 읽는 방식으로 고쳤다.

그 뒤에도 2026-10-26 하루에 오탐이 네 번 났다. 본문을 400자 넘게 쓴 메시지에서 0자 또는 131자로 셌고, transcript에는 그 메시지의 본문 행이 끝까지 없었다(thinking 행과 tool_use 행만 남음). 기다리는 방식으로는 잡을 수 없는 경우였다. 막힐 때마다 질문을 본문으로 옮기고 ask 없이 다시 불러야 해서 사용자는 질문 상자를 쓰지 못했다.

사용자 판단(2026-10-26): 훅을 단 이유였던 Claude Code의 보고 생략 증상은 그 뒤 업데이트로 달라졌고, 해결됐는지는 모르지만 훅으로 인한 불편이 더 커졌다. 훅을 끄고, 보고 생략이 다시 나타나면 다른 방식으로 해소한다.

## 결정

- `wrap_up_report_guard.py`와 그 테스트를 지우고 `.claude/settings.json`의 PreToolUse `mcp__ccd_turn__wrap_up` 항목을 뺀다. ADR-0052의 삭제 조건(짧은 답에서 막힘이 잦아 사용자가 불편을 지적함)에 해당한다
- PostToolUse `wrap_up_reminder.py`(wrap_up 뒤 보고를 다시 쓰지 않게 하는 알림, ADR-0042)는 막지 않고 알리기만 해 그대로 둔다
- 보고 생략이 다시 나타나는지는 관찰한다. 메모리 `report-work-in-chat`·`exp-report-full-metrics`의 보고 규칙은 그대로다

## 결과

`.claude/hooks/wrap_up_report_guard.py`, `test_wrap_up_report_guard.py` 삭제, `.claude/settings.json`. ADR-0052는 폐기, ADR-0060의 wrap_up 대기 방식 항목은 이 ADR로 대체된다.

## 삭제 조건

보고 생략이 다시 반복돼 장치가 필요해지면 새 ADR로 다른 방식을 정하고 이 ADR의 상태를 고친다.
