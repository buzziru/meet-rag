# ADR-0049 multi-doc 생성 하네스를 걷어내고 끝난 단계의 서술을 정리

- 상태: 채택
- 날짜: 2026-10-20

## 맥락

- multi-doc 질의 생성(S8·G3)은 2026-10-08 G3 동결 세트 600건으로 끝났다(D-15). G4는 질의 유형을 더하지 않고 닫았고(2026-10-19), 생성 단계도 동결 세트로 보조 관찰만 한다(D-38). ADR-0017·0018·0019·0020·0021·0023의 삭제 조건("G3 동결로 multi-doc 생성·검사를 끝낼 때")이 충족됐다
- 끝난 단계의 절차가 meet-rag 스킬 본문(52KB)에 남아 다른 지시를 묻었다. A6(S3 뒤 eval 명령 추가)도 끝난 일이고, 생성 경로와 5xx 확인 대상은 Google AI Studio 기준으로 남아 있었다(지금은 OpenRouter D-37, judge opencode Go D-38)

## 결정

- `multidoc-writer`·`multidoc-checker` 에이전트와 `multidoc_read_guard.py` 훅을 지운다
- meet-rag 스킬에서 multi-doc 작업자 표 행, 프롬프트 구성, 실행 순서 1\~7, 지시 버전 고정, CLI 메인 세션 규칙, 중단과 재개 절, G3 시나리오를 지운다. CLAUDE.md 명령 줄은 동결 사실과 다시 만들 때 볼 곳(slices/08, 이 ADR들)만 남긴다
- A6을 지우고, E절의 생성 경로 문장과 오류 처리의 5xx 확인 대상을 지금 쓰는 제공자로 고친다
- 테스트 시나리오에서 끝난 조각 고유의 예시(S1 건수, S5 노트북 번호)를 흐름 단위 예시로 바꾼다

남긴 것: 작업자 풀·작업 큐 절과 `worker_queue.py`는 G2에서도 썼고 G5에서 쓸 수 있어 남긴다(ADR-0024·0025). configs·docs·src에 남은 에이전트 이름은 과거 실행 기록이라 고치지 않는다.

## 결과

`.claude/agents/multidoc-writer.md`·`multidoc-checker.md`, `.claude/hooks/multidoc_read_guard.py` 삭제. `.claude/skills/meet-rag/SKILL.md`(실행 모드, 에이전트 표, multi-doc 절, A6, E절 첫 문단, 오류 처리, 테스트 시나리오), `CLAUDE.md` 명령 절. ADR-0017·0018·0019·0021·0023 상태 폐기, ADR-0020 일부 폐기.

## 삭제 조건

- 없음. multi-doc 질의를 다시 만들게 되면 git 이력에서 정의와 절차를 되살리고 새 ADR로 기록한다
