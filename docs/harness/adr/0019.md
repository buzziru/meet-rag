# ADR-0019 multidoc-writer 읽기·쓰기 범위를 훅으로 강제

- 상태: 채택
- 날짜: 2026-10-06
- 커밋: (PR 병합 후 기록)

## 맥락

ADR-0018로 정의에 "저장소 문서(`docs/`)와 코드를 읽지 않는다"를 명시했지만, S8 파일럿 v4 생성에서 에이전트 2개가 모두 `docs/slices/08-multidoc-queries.md`를 다시 읽었다(v2에 이어 두 번째). `questioner` 에이전트는 skip을 확인하려고 정답 후보가 아닌 원문 2개를 읽었다. 정의 본문의 읽기 규칙은 지시일 뿐 도구를 막지 않는다. 서브에이전트에도 프로젝트 CLAUDE.md가 로드되는데, CLAUDE.md "문서" 절이 `docs/slices/NN-이름.md`를 안내한다. 이것이 지시서를 찾아 읽은 원인으로 보인다.

평가 누수는 아니었다(지시서에 평가 질의·`test`·검색 결과가 없다). 하지만 생성 쪽이 알 필요 없는 파일럿 진단을 읽었고, 같은 위반이 반복됐다. 원문 읽기가 늘면 "개요로 고른다"(D-13)는 절차가 후보 집합마다 달라지고 토큰이 는다. 사용자는 정답 후보 원문만 건네는 2단계 호출은 호출 수가 늘어 채택하지 않았다.

## 결정

- 정의 frontmatter에 PreToolUse 훅(`.claude/hooks/multidoc_read_guard.py`)을 둔다. Read는 생성 지시 디렉터리, `gen_in`, `docs`(원문), `gen_out` 아래만, Write는 `gen_out` 아래만 허용하고 나머지는 종료 코드 2로 거부한다. 이 에이전트에만 등록하므로 메인과 다른 에이전트에는 영향이 없다
- 훅은 예외가 나면 막는다. 통과시키면 제한이 조용히 풀린다. 사유 문구가 한글이라 cp949 출력 오류로 종료 코드가 바뀌지 않게 stdin·stderr를 UTF-8로 고정한다
- `omitClaudeMd: true`로 서브에이전트에 CLAUDE.md를 넣지 않는다. 필요한 규칙은 정의와 지시 파일에 있다
- 정답 후보가 아닌 원문 읽기는 같은 디렉터리 안이라 경로로 구분할 수 없다. 본문 지시와 메인의 실행 기록 확인에 맡긴다

## 결과

`.claude/agents/multidoc-writer.md`(frontmatter, 본문 한 문장), `.claude/hooks/multidoc_read_guard.py`(신규), 이 ADR과 목록.

- 검증: 훅 스크립트를 합성 입력 7건(허용 3, 거부 3, 다른 에이전트 통과 1)과 손상된 입력 1건(거부)으로 시험했다. 새 세션에서 메인이 이 에이전트를 부르는 형태로 실행해, `docs/SPEC.md` Read가 거부되고 CLAUDE.md가 컨텍스트에 없음을 확인했다
- 실행 중인 세션은 시작 때 불러온 에이전트 정의를 계속 써서, 같은 세션에서 frontmatter를 바꿔도 적용되지 않았다. 이 변경은 병합 뒤 새 세션부터 효력이 있다
- 허용 경로는 `configs/config.yaml`의 `paths.multidoc_*`와 같아야 한다. 스크립트에 적어 두었고, config가 바뀌면 함께 바꾼다
- 훅 명령은 `uv`가 PATH에 있어야 한다. 없으면 명령이 실패해 거부로 처리된다(이 에이전트가 아무것도 읽지 못한다)

## 삭제 조건

ADR-0017과 같다(G3 동결로 multi-doc 생성을 끝낼 때).
