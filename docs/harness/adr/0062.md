# ADR-0062 worktree를 지울 때 `_workspace/` 기록이 남아 있으면 막음

- 상태: 채택
- 날짜: 2026-10-26

## 맥락

`_workspace/`는 세션과 에이전트 사이에 작업 내용을 넘기는 로컬 디렉터리이고 .gitignore 대상이다. git.md main 맞추기 6은 병합된 worktree를 지우기 전에 그 `_workspace/` 진행 기록을 메인 `_workspace/`로 옮기라고 한다.

2026-10-26 메인 세션이 병합된 하위 세션 worktree(`docs-gen-ideas`)를 정리하며 `_workspace/genideas_main_progress.md`를 확인 출력으로 보고도 같은 명령에서 `git worktree remove`를 실행해 기록을 지웠다. `git worktree remove`는 고친 추적 파일과 추적하지 않는 파일이 있으면 거부하지만, 무시 대상 파일은 검사하지 않고 경고 없이 지운다(스크래치 저장소 실험으로 확인). 이번에는 내용이 PR #151에 반영돼 있었지만, 사용자는 `_workspace/`가 세션 사이에 작업을 넘기는 곳이라 반복되면 잃는 것이 클 수 있다고 보고 바로 하네스를 고치게 했다(사용자 지시 2026-10-26).

## 결정

- `data_delete_guard` 훅이 worktree(`.git`이 파일인 디렉터리)를 대상으로 한 재귀 삭제·`git worktree remove`(`git -C` 포함)에서 그 `_workspace/`에 파일이 하나라도 있으면 막는다(deny). 메시지에 파일 이름과 옮길 곳을 적는다. 옮긴 뒤 빈 폴더만 남으면 통과한다
- 메인 체크아웃의 `_workspace/`나 worktree가 아닌 디렉터리는 대상이 아니다. 막으려는 것은 worktree를 정리하며 기록을 함께 지우는 경우뿐이다
- git.md main 맞추기 6에 "옮긴 것을 확인한 다음 명령에서 지운다"와 이유를 적는다

## 결과

`.claude/hooks/data_delete_guard.py`(`workspace_files`, `check_targets`), `test_data_delete_guard.py`, `.claude/rules/git.md` main 맞추기 6.

## 삭제 조건

`_workspace/`를 세션 사이 공유에 쓰지 않게 되거나, worktree 정리를 앱 기능(clean_up_worktrees 등)으로만 하게 되어 이 경로가 쓰이지 않으면 지운다.
