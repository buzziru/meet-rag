# ADR-0021 multi-doc 작업자는 CLI 메인 세션에서만 띄운다

- 상태: 채택
- 날짜: 2026-10-07
- 커밋: (PR 병합 후 기록)

## 맥락

ADR-0019·0020은 `multidoc-writer`·`multidoc-checker`의 읽기·쓰기 범위를 정의 frontmatter의 PreToolUse 훅으로 막는다. 두 ADR의 검증은 합성 입력과 `claude -p` 새 프로세스에서 했다. 2026-10-07 Cursor 확장 세션에서 Agent 도구로 부른 작업자는 금지 경로 읽기·쓰기가 거부되지 않았다. 처음에는 원인을 몰라 작업자를 `claude -p --agent` 프로세스로 띄우는 PR #34를 올렸다. 이어서 원인을 좁혔다.

| 실행 방식 | Claude Code | 훅 |
|---|---|---|
| Cursor 확장 세션(재실행 직후), Agent 도구 | 2.1.283(확장 번들) | 미적용 |
| 확장 번들 바이너리 `-p`, Agent 도구 | 2.1.283 | 거부 |
| CLI `claude -p`, Agent 도구 | 2.1.289 | 거부 |
| 같은 세션을 CLI 대화형으로 재개(`claude --resume`), Agent 도구 | 2.1.289 | 거부 |

같은 바이너리도 CLI로 실행하면 훅이 걸리고, 같은 세션 기록도 CLI로 재개하면 걸린다. 버전과 세션 시작 시점은 원인이 아니고 IDE 확장 실행 환경이 원인이다. 확장 안에서 훅이 불리지 않는지, `agent_type`이 다르게 넘어오는지는 확인하지 못했다. 사용자는 메인 세션을 CLI에서만 실행하기로 했다.

## 결정

- 작업자는 CLI로 실행한 메인 세션에서 Agent 도구로 띄운다. ADR-0020의 실행 방식은 그대로다. PR #34의 `claude -p` 전환은 닫는다
- 메인은 시스템 프롬프트에 VS Code 확장 환경이 적혀 있으면 작업자를 띄우지 않고 사용자에게 CLI 재개를 요청한다. 확장 세션에서는 제한이 오류 없이 풀려, 실행 기록을 봐도 알아채기 어렵다

## 결과

`.claude/skills/meet-rag/SKILL.md` 작업자 풀 절, 이 ADR과 목록.

- 검증: 위 표의 시험. CLI 대화형 세션에서 writer는 `gen_in` 읽기 허용, `check_in` 읽기·scratchpad 쓰기 거부, checker는 `check_in` 읽기 허용, `gen_out` 읽기·scratchpad 쓰기 거부였다
- 하네스의 강제 장치(훅·권한)는 실제로 운영할 실행 경로에서 검증해야 한다. ADR-0019는 `claude -p`로만 검증해 IDE 확장 세션의 차이를 놓쳤다

## 삭제 조건

IDE 확장 세션에서 Agent 도구로 부른 작업자에 훅이 적용되는 것을 확인하면 삭제한다. 그 전이라도 G3 동결로 multi-doc 생성·검사를 끝내면 ADR-0017과 함께 삭제한다.
