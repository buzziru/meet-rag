# ADR-0021 multi-doc 작업자를 claude -p 프로세스로 실행

- 상태: 채택
- 날짜: 2026-10-07
- 커밋: (PR 병합 후 기록)

## 맥락

ADR-0020은 `multidoc-writer`·`multidoc-checker`를 메인이 Agent 도구로 띄우고, 읽기·쓰기 범위를 정의 frontmatter의 PreToolUse 훅으로 막는다고 정했다. 2026-10-07 VS Code 확장 세션에서 Agent 도구로 부른 `multidoc-checker`는 두 번(PR #33 병합 직후 세션, 새로 시작한 세션) 모두 `gen_out` 읽기·쓰기가 거부되지 않았다. 훅 스크립트는 예외가 나도 막도록 되어 있으므로 훅이 불리지 않았거나 `agent_type`이 다른 값으로 넘어왔다고 본다. 어느 쪽인지는 확인하지 못했다.

같은 날 `claude -p --agent multidoc-checker --model sonnet --permission-mode acceptEdits`로 실행한 작업자는 `check_in` 읽기와 `check_out` 쓰기만 허용되고 `gen_out` 읽기·쓰기는 훅이 거부했다. 출력의 `modelUsage`는 Sonnet이었다(Claude Code 내부 보조 호출의 Haiku 포함).

## 결정

- 생성·검사 작업자는 작업마다 `claude -p --agent <작업자> --model sonnet --permission-mode acceptEdits --output-format json` 프로세스 하나로 띄우고, 메인은 Bash 백그라운드로 실행해 종료 알림을 받는다. 훅이 실제로 거부하는 것을 확인한 실행 방식이 이것뿐이다
- `--model sonnet`을 명시한다. `--agent`가 정의의 `model`을 따르는지 확인하지 않았고, 따르지 않으면 메인 세션 기본 모델로 돈다
- 반환 메시지는 출력 JSON의 `result`로 받아 `_workspace/{작업}_jobs/`에 둔다. 작업자 풀·큐·중단·재개 규칙(ADR-0020)은 그대로다. 끝난 작업자를 이어 쓰지 않는다는 규칙은 `--continue`·`--resume`을 쓰지 않는 것으로 지킨다

## 결과

`.claude/skills/meet-rag/SKILL.md` 작업자 풀 절, 이 ADR과 목록, ADR-0020 상태.

- 검증: `multidoc-checker`는 위 맥락의 시험. `multidoc-writer`도 같은 방식으로 `gen_in` 읽기 허용, `check_in` 읽기·`check_out` 쓰기 거부, `modelUsage` Sonnet을 확인했다
- `--agent` 실행의 init 메시지(`--output-format stream-json --verbose`)에서 사용 가능한 도구는 정의의 `tools`대로 `Read`·`Write`뿐이었다. 훅이 보지 않는 Grep·Glob·Edit으로 범위 밖에 접근하는 경로는 없다
- 프롬프트를 큰따옴표로 넘기면 Git Bash가 Windows 경로의 `\`와 `$`를 해석한다. 스킬 예시는 작은따옴표로 쓴다
- 프로세스마다 Claude Code를 새로 띄우므로 Agent 도구보다 시작 시간이 더 든다. 작업 하나가 수 분이라 영향은 작다고 본다(측정하지 않음)
- `--agent` 실행에서 정의의 `omitClaudeMd`가 적용되는지는 확인하지 않았다. 범위 밖 읽기는 훅이 막는다

## 삭제 조건

Agent 도구로 부른 작업자에 정의의 훅이 적용되는 것을 확인하면 Agent 도구 방식으로 되돌린다. 그 전이라도 G3 동결로 multi-doc 생성·검사를 끝내면 ADR-0017과 함께 삭제한다.
