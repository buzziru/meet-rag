# ADR-0026 리뷰 가이드 지적 처리와 하네스 스크립트 테스트

- 상태: 채택
- 날짜: 2026-10-08
- 커밋: PR #43 정리 커밋

## 맥락

PR #43(대기 24\~26)에서 메인은 `pr-briefer`의 "판단할 곳"을 고칠 목록으로 받아, 지적마다 작업 큐 스크립트에 기능(보류 기록, 회차 구분, 인자 확인)을 더하고 가이드를 다시 불렀다. 가이드를 세 번 받는 동안 매번 새 경계 사례가 나와 커밋이 8개로 늘었다. 더한 기능 중 보류는 G3 긴 줄 12개 한 번만 필요했던 드문 경우다. 스크립트에 테스트가 없어 리뷰어는 코드를 읽고 동작을 추정했다. 사용자가 이 과정의 문제를 물었고, 보류 기능을 빼고 테스트를 붙이는 정리를 택했다.

규약상 가이드를 다시 부르는 조건은 감사 지적을 고쳐 커밋했을 때인데, 메인은 가이드 지적에 대응한 뒤에도 다시 불렀다.

## 결정

- 가이드의 "판단할 곳"은 사용자가 판단할 지점이다. 메인은 변경의 원래 목적에 대한 결함(틀린 동작, 문서와 코드 불일치)만 고치고, 새로 생긴 드문 경우에 대비하는 기능은 더하지 않고 PR 본문이나 진행 기록에 관찰로 남긴다. 반복되면 그때 만든다
- 감사·가이드 지적을 반영한 커밋이 있으면 반영을 마친 뒤 최종 diff로 가이드를 한 번 더 받아 PR 본문에 넣는다(PR #43 사용자 코멘트: 감사 지적 후 다시 가이드를 받아 diff의 수정 사항이 모두 반영되게). 이 마지막 가이드의 지적은 원래 목적의 결함일 때만 고치고 PR 본문 "self-review 지적과 반영"에 적으며, 가이드는 더 부르지 않는다
- 가이드 대응 커밋은 감사를 거치지 않으므로 PR 전에 메인이 `protocol-guard`로 확인하고, 보호 경로나 금지 조항에 걸리는 파일을 바꿨으면 `protocol-auditor`를 다시 부른다(감사 지적)
- 하네스 보조 스크립트를 새로 만들거나 고치면 `tests/`에 동작 테스트를 같은 커밋에 둔다
- PR #43의 `worker_queue.py`에서 보류 기능을 뺀다(ADR-0024 결과 갱신). 건너뛴 항목은 메인이 진행 기록에 적고 사용자에게 보고한다

## 삭제 조건

`pr-briefer`를 쓰지 않게 되면 첫 두 항목을 지운다. 하네스 스크립트가 없어지면 셋째 항목을 지운다.
