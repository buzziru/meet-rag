# ADR-0087 Hugging Face 작업은 hf-cli 스킬을 쓰고 저장소 규칙을 메인이 지킨다

- 상태: 채택
- 날짜: 2026-11-04

## 맥락

배포 조각에서 Space 생성, 인덱스 업로드, 시크릿 설정을 반복한다(사용자 요청 2026-11-04). HF가 제공하는 `hf-cli` 스킬은 CLI 버전에서 생성한 명령 목록이라 이 저장소의 규칙을 모른다. `hf upload`는 없는 저장소를 만들 수 있고, 데이터를 공개 저장소에 올리면 D-31 위반이다. HF는 지금 허용 처리처 목록에 없다.

## 결정

스킬은 전역에 설치한다(`hf skills add hf-cli --global`). 저장소에 두면 CLI를 올릴 때마다 생성 파일의 diff가 생긴다. CLI는 전역 uv 도구로 설치한다(`uv tool install huggingface_hub`). 공식 설치 프로그램은 PATH를 고치고 별도 venv를 만들며, `colab` CLI도 uv 도구로 쓰고 있다.

`meet-rag` 스킬에 "Hugging Face 작업" 절을 둔다. 문자 절 이름을 쓰지 않은 것은 G가 사람 검수 게이트 항목과 겹치기 때문이다. HF 작업 전에 스킬을 불러오고, 처리처 확인과 파일 선택(`queries-*.npz` 제외), 비공개 저장소 선행 생성, 과금 승인, 토큰·시크릿 비출력을 메인이 지킨다.

## 결과

`.claude/skills/meet-rag/SKILL.md`(0단계 대응, 새 절), `CLAUDE.md`(명령 한 줄)에 반영했다. HF를 처리처에 더하는 일은 이 ADR에서 하지 않고, 데이터를 올리기 전에 사용자 승인, DECISIONS 기록, 목록 추가로 한다(D-72). 훅은 더하지 않는다. 같은 위험을 D-72가 장치 없이 받았고, 업로드 경로가 아직 없어 어떤 명령을 막을지 정해지지 않았다.

CLI를 올리면 `uv tool upgrade huggingface_hub` 뒤 `hf skills update -g`로 스킬을 다시 만든다. `hf update`가 uv 도구 설치를 갱신하는지는 실행해 확인하지 않았다.

## 삭제 조건

배포를 HF 밖으로 옮겨 HF 작업이 없어지면 지운다.
