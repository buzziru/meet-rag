# ADR-0088 커밋 타입 훅 오탐을 고치고, 판정 스킬의 거부 문구와 감사 스킬의 버전 표기를 지금 기준에 맞춤

- 상태: 채택
- 날짜: 2026-11-04

## 맥락

- 대기 목록을 점검해 끝난 항목의 표시를 정리하고, 지금도 유효한 후보 3건을 사용자가 골랐다(사용자 결정 2026-11-04)
- `commit_type_guard`는 `git commit` 글자 뒤 어디서든 `-m`을 찾았다. `git commit -F -` 뒤 명령의 `python -m rag.x`나 heredoc 본문의 글자, `echo`에 든 글자를 메시지로 읽어 막았다. 대기 목록 기록 3회에 이번 점검 중 조정자에게 보내는 질문 명령에서 1회 더 걸렸다. 실행 전 차단이라 손상은 없지만 매번 명령을 나눠 다시 실행해야 했다
- S34·D-73부터 변형 거부도 거부로 세는데, `exp-judgment`는 "지정 문구 없는 거부"(report 표 이름이 바뀜)와 "지정 거부 문구를 쓰지 않은 거부는 거부로 세지 않아"(지금은 조각도 없을 때만)로 적고 있었다. 그대로면 판정 보고가 변형 거부를 거부 아님으로 설명한다
- `protocol-guard` description은 동결 대상을 "j_v8 지시"로 적었다. 기준 지시 버전은 바뀌어 왔고, 바뀌는 값은 하네스 문서에 고정하지 않는다(ADR-0076). 본문 P11은 버전 없이 맞게 적혀 있어 감사 범위는 달라지지 않는다

## 결정

1. `commit_type_guard`: `git commit`이 명령 자리(시작, `;`·`&`·`|`·`(`·`{`·줄바꿈 뒤, 환경 변수 대입 뒤)에 있을 때만 보고, `-m`은 그 명령 안(첫 구분자 앞, `\` 줄 잇기는 같은 명령)에서만 찾는다
2. `-F -` 메시지의 타입은 지금처럼 검사하지 않는다(사용자 결정 2026-11-04). 규약 밖 타입 실패는 `-m` 경로에서 2회였고 `-F -` 경로에는 기록이 없다. 입력 `git commit -F -`의 heredoc 첫 줄 `perf: x` → 통과
3. `exp-judgment` 보고할 값: 세지 않는 거부는 지정 문구도 변형 조각(`gen_eval.unlisted_refusal`)도 없는 거부로 적고, report 항목은 전체·부분 거부와 그중 변형 거부, 진술 없음·변형 거부 아님으로 적는다
4. `protocol-guard` description: "j_v8 지시" → "judge 지시"

## 결과

`.claude/hooks/commit_type_guard.py`와 `test_commit_type_guard.py`(실제로 막힌 네 형태, 구분자·환경 변수·줄 잇기 뒤의 규약 밖 타입), `.claude/skills/exp-judgment/SKILL.md:117-118`, `.claude/skills/protocol-guard/SKILL.md:3`.

`echo "a; git commit -m perf"`처럼 문자열 안에서 구분자 뒤에 나오는 경우와, 한 명령에 `git commit`이 둘이어서 뒤쪽이 규약 밖인 경우는 고치지 않았다. 앞의 것은 오탐으로 막히고 뒤의 것은 놓치며, 둘 다 기록이 없다.

## 삭제 조건

훅의 삭제 조건은 ADR-0055를 따른다.
