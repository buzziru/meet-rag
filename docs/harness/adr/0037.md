# ADR-0037 EXP 문서를 먼저 쓰고, 판정 보고에 지연·비용과 예외 규칙을 둔다

- 상태: 채택
- 날짜: 2026-10-13

## 맥락

- EXP-010에서 구현과 dev-small을 먼저 하고 EXP 문서를 나중에 썼다(사용자 지적). 가설·판정 기준을 결과를 보고 쓴 것처럼 읽힐 수 있다
- EXP-006(리랭커)은 SPEC 판정이 채택이었지만 사용자가 비용을 이유로 운영을 보류했다(D-26). 사용자는 성능만으로 최종 채택하지 않고 지연·비용을 함께 보고하라고 지시했다
- EXP-009(snowflake-ko)는 보류였지만 사용자가 근거를 들어 예외로 기준에 올렸다(D-28). PR #65 코멘트: 예외는 보류 판정에 한하고 합당한 근거가 필요하며, 기각 판정을 채택하는 것은 금지한다

## 결정

- meet-rag B1: EXP 문서와 config를 먼저 커밋한 뒤 구현·dev-small로 넘어간다
- meet-rag B6: 판정 보고에 지연과 운영 비용을 낸다. SPEC 채택(성능)과 운영 채택(기준 설정, 사용자가 비용과 함께 결정)을 나눈다. 보류 판정의 예외 채택은 DECISIONS에 이유·감수하는 점·새 기준 해시를 적고 SPEC은 고치지 않는다. 기각 판정의 채택은 금지한다
- exp-judgment·exp-judge: "결과" 절에 지연·비용 줄을 두고, 결론에서 SPEC 판정과 미리 정한 사용자 결정을 나눠 적는다. 기각을 채택으로 바꾸는 결론은 쓰지 않는다

## 결과

`.claude/skills/meet-rag/SKILL.md` B1·B6, `.claude/skills/exp-judgment/SKILL.md` 기록 형식, `.claude/agents/exp-judge.md` 출력.

## 삭제 조건

SPEC에 운영 채택 기준(지연 상한, 비용)이 들어가 판정 규칙 안에서 정해질 때, 또는 예외 채택 규칙을 SPEC으로 옮길 때.
