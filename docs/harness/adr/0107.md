# ADR-0107 worker 모델은 일의 입력에 따라 고르고, 한 번에 맡기는 범위를 나눈다

- 상태: 채택
- 날짜: 2026-11-06

## 맥락

- ADR-0105는 worker 모델 셋(deepseek-v4.1-flash, crouton-alpha-free, pulse-alpha-free)을 나열만 하고 고르는 기준을 두지 않았다. 그 뒤 worker 여덟 번을 모두 deepseek-v4.1-flash로 돌렸다
- 사양은 opencode가 models.dev에서 받아 보여 준다(`opencode models <제공자> --verbose`, 2026-11-06). 컨텍스트는 셋 다 약 100만 토큰이고 최대 출력은 384,000, 270,000, 131,072 토큰이다. 가격은 deepseek만 있고(Go 구독 한도에서 차감, judge와 같이 씀) 스텔스 둘은 0이다
- 회고 자료 추출에서 큰 문서 하나로 표 여러 개를 한꺼번에 뽑게 한 두 번의 출력이 5.6KB, 27KB에서 끊겼다. 모델 최대 출력보다 훨씬 작아 원인은 확인하지 못했다. 같은 작업을 결정 번호 구간으로 나누자 끝까지 나왔다. 제공자 용량 초과(`prefill_cap_refused`)로 1회 실패했다

## 결정

1. 공개 웹·공개 저장소 조사는 스텔스 모델(`opencode-go/crouton-alpha-free` 먼저, 다음 `opencode/pulse-alpha-free`)로 해서 Go 한도를 아낀다. 이 저장소는 GitHub에 공개돼 있어도 여기에 넣지 않는다(결정 2의 입력 처리 조건을 GitHub 경유로 비켜 가지 않게)
2. 저장소 문서를 복사해 넘기는 일은 `opencode-go/deepseek-v4.1-flash`로 한다. 입력 처리 조건(학습 미사용·보존 0일, D-38)이 확인된 쪽이기 때문이다
3. 스텔스 모델이 실패하거나 결과가 모자라면 같은 지시로 deepseek을 다시 부른다. AI Hub 데이터는 세 모델 모두 처리처 승인 전에는 쓰지 않는다(ADR-0105 결정 4 그대로)
4. 한 번에 맡기는 범위를 표 하나나 범위 하나씩으로 나누고, 결과가 지시한 마지막 항목까지 왔는지 본다
5. 제공자 쪽 일시 오류는 한 번만 다시 부른다

사용자가 기준에 동의했다(2026-11-06). 입력→동작: GitHub trending 디자인 스킬 조사는 crouton, DECISIONS·EXP 문서에서 실험표를 모으는 일은 deepseek.

감수하는 것: 모델 사이의 품질과 속도는 재지 않았다. 출력이 끊긴 원인을 모르므로 나눠 맡기는 것은 증상을 피하는 방법이다. pulse의 무과금은 메타데이터 가격(0) 기준이고 Console 사용량으로는 아직 보지 않았다.

## 삭제 조건
