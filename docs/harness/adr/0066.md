# ADR-0066 리뷰로 정해진 판단할 곳은 질문을 남기고 결정을 머리에 붙임

- 상태: 채택
- 날짜: 2026-10-27

## 맥락

`.claude/rules/git.md` PR 절 5는 대화로 받은 리뷰를 반영할 때 본문 "판단할 곳"을 지금 diff에 맞추라고 하면서, 정해진 질문은 "지우거나 결정을 적고"라고 두 방식을 모두 허용했다. 그래서 세션마다 달랐다. PR #163은 질문을 지우고 결정했다는 말만 남겼고, PR #164는 질문과 사례를 둔 채 항목 머리에 `(결정: …)`을 붙였다. 사용자는 논의 자체가 남는 #164 방식이 낫다고 했다(2026-10-27). 질문을 지우면 diff를 읽을 때 무엇을 왜 정했는지 보이지 않는다.

pr-briefer의 "다시 호출할 때"는 판단할 곳을 새 diff 기준으로 다시 쓰라고만 해서, 리뷰 반영 뒤 가이드를 다시 받으면 정해진 질문이 빠지거나 번호가 바뀔 수 있었다.

## 결정

- git.md PR 절 5: 리뷰로 정해진 질문은 질문과 사례를 지우지 않고 항목 머리에 `(결정: 요지, 커밋 해시)`를 붙인다. 반영 커밋이 없으면 해시를 빼거나 근거 결정 번호를 적는다. 결정 항목의 `file:line`은 반영 뒤 diff에 맞춘다(줄이 밀리면 링크가 다른 줄을 가리킨다). 새로 생긴 판단은 다음 번호로 더하고 앞 번호는 바꾸지 않는다
- pr-briefer "다시 호출할 때": 리뷰 반영 뒤 부르면 같은 방식으로 직전 판단할 곳을 남긴다. 출력 형식의 0\~5개 상한에는 결정이 붙은 항목을 세지 않는다. 세면 결정 항목 4개가 남은 PR에서 새 판단 2개 중 하나를 버려야 한다(가이드 지적)

## 결과

`.claude/rules/git.md`(PR 절 5), `.claude/agents/pr-briefer.md`(출력 형식의 판단할 곳, 다시 호출할 때). PR 댓글과 본문 "리뷰 반영" 절의 기록 방식은 그대로다. 리뷰 전 수정 커밋 뒤 다시 부를 때의 번호 다시 매기기(그림 번호 맞춤)는 그대로다.

## 삭제 조건

사용자가 PR 리뷰를 대화가 아닌 다른 경로로 받기로 하거나, 리뷰 가이드에서 판단할 곳 절을 없애면 함께 고친다.
