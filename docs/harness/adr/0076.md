# ADR-0076 채택마다 바뀌는 값을 고정하지 않고 지금 기준을 두 곳에만 둠, 병합된 PR 브랜치에 push하지 않음

- 상태: 채택
- 날짜: 2026-10-28

## 맥락

- 첫 생성 EXP(EXP-018) 채택 뒤 PR #180 리뷰에서 같은 원인의 문제가 셋 나왔다. CLAUDE.md 생성 명령이 `+exp=exp017`로 기준 EXP 번호를 적었고, 경로 테스트가 `-v2-`를 기대값에 적었고, 생성 EXP 절차 문서(`gen-exp.md`)가 기준 결과 경로를 적었다. 사용자 지적: 코드의 "파라미터는 configs로" 원칙을 명령·테스트·문서에는 적용하지 않아, 고정하면 안 되는 것을 고정해 생긴 문제다. #180에서 별칭 `configs/exp/current.yaml`을 두고 기준을 그곳과 DECISIONS 머리 줄에만 두었다(D-61)
- 이미 병합된 PR 브랜치에 push해 사용자가 지운 원격 브랜치를 다시 만든 일이 두 번 있었다(이슈 #120 세션, 2026-10-27 STATUS 커밋 aea30e7). 그 커밋은 어느 PR에도 들어가지 않았다

## 결정

- 루트 CLAUDE.md 금지 절: 채택마다 바뀌는 값(지금 기준 EXP, 프롬프트 버전, 기준 결과 경로)을 명령·테스트 기대값·하네스 절차 문서에 적지 않는다. 지금 기준은 `configs/exp/current.yaml`과 DECISIONS 머리 줄에만 두고, 명령은 `+exp=current`, 테스트는 config에서 값을 읽고, 문서는 머리 줄을 가리킨다
- `docs/CLAUDE.md`: 기준을 바꾸는 결정은 머리 줄과 `current.yaml`을 같은 PR에서 고친다. 새 EXP config는 기준 EXP를 직접 상속하고 별칭은 상속하지 않는다(별칭을 상속하면 기준이 바뀔 때 그 EXP 설정도 바뀌어 재현되지 않는다)
- meet-rag B6 채택의 두 층, `gen-exp.md` B1: 같은 규칙을 그 단계에 한 문장씩
- protocol-guard P4: 위 규칙을 위반으로 감사한다. 그때 돌린 명령을 적은 당시 기록과 특정 과거 실행을 재현하는 테스트는 해당하지 않는다
- git.md PR 절·핸드오프: 작업 브랜치에 push하기 전에 `gh pr list --head <브랜치> --state merged`로 병합 여부를 보고, 병합됐으면 새 브랜치로 옮긴다. 훅 대신 절차 한 줄로 둔다(두 번 다 핸드오프·STATUS 커밋에서 생겨 확인할 시점이 정해져 있다)

## 결과

`CLAUDE.md`(금지 절), `docs/CLAUDE.md`(DECISIONS 절, EXP 절), `.claude/skills/meet-rag/SKILL.md`(B6), `.claude/skills/meet-rag/references/gen-exp.md`(B1), `.claude/skills/protocol-guard/SKILL.md`(P4), `.claude/rules/git.md`(PR 절, 핸드오프). 대기 목록의 wrap_up 보고 훅 오판(ADR-0061로 훅을 없앰)과 Git Bash `time`·`bc` 부재(slice-verifier 정의에 반영됨)는 이미 반영돼 상태만 고쳤다.

## 삭제 조건

기준을 별칭 config 대신 다른 방식(예: config 기본값)으로 관리하게 되면 금지 절과 P4를 그 방식에 맞춘다. 병합된 브랜치 push가 절차만으로 또 생기면 PreToolUse 훅으로 막는다.
