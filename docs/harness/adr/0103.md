# ADR-0103 생성 test를 마친 상태로 점검표를 맞추고, 위임 프롬프트에서 worktree 검색을 막는다

- 상태: 채택
- 날짜: 2026-11-05

## 맥락

- 생성 test 1회를 마쳤는데(S46, D-90) `protocol-guard`와 `meet-rag`가 앞으로 할 일로 적는다(S46 결과 PR 감사). 감사가 "남은 1회"로 읽으면 두 번째 실행을 위반으로 보지 못할 수 있다
- `.claude/worktrees/deploy/data`는 원본 `data/`의 junction이다. 2026-11-05 `protocol-auditor`가 `grep -rn`으로 `.claude`를 검색해 이 링크로 들어갔을 수 있고, 120초 안에 끝나지 않아 자기 프로세스를 멈췄다. 일치는 0건이고 test 파일을 열었는지는 확인하지 못했다. 이 경로는 `.gitignore` 대상이라 Grep 도구(ripgrep)는 들어가지 않고 셸 `grep`만 들어간다(`git check-ignore`로 확인, ripgrep 동작은 문서 기준)

## 결정

1. `protocol-guard` P1의 생성 단계 줄을 마친 상태로 고친다. 끝난 단계의 진행 방식은 지우고 D-90을 가리킨다. 같은 단계의 두 번째 실행은 그대로 위반이다
2. test 경로(`search.allow_test`, `gen_eval.allow_test`, `rag.eval.score --allow-test`)는 지우지 않는다. 지우려면 코드와 합성 입력 테스트를 함께 고쳐야 하는데, 막는 일은 허용 플래그와 위반 규칙이 이미 한다. 입력→동작: 코드에 경로가 그대로 있는 것은 위반이 아니고, 그 경로를 실행하는 diff나 명령은 위반이다
3. `meet-rag` E절에서 생성 test의 Colab 처리를 뺀다. 생성 test는 S13 산출물로 Colab 없이 끝났다(D-87 결정 6)
4. 위임 프롬프트에 재귀 검색 범위를 적는다(`meet-rag` "공유 `data/`와 위임"). 훅을 두지 않는다. 한 번 있었고 일치도 없었으며, 막는 방법을 지시로 줄 수 있기 때문이다. 반복되면 그때 만든다

감수하는 것: 지시를 빠뜨린 위임은 여전히 링크로 들어갈 수 있다. 관찰만 하던 test 1회 대조 범위 밖 override와 `rag.gen_eval.review`의 test 읽기(대기 목록)는 test를 마쳐 고치지 않고 닫는다.

## 결과

`.claude/skills/protocol-guard/SKILL.md`, `.claude/skills/meet-rag/SKILL.md`. 입력→동작: 서브에이전트에 넘기는 프롬프트에 "재귀 검색은 `src`, `tests`, `configs`, `docs`로 한정하고 `.claude/worktrees/`는 열지 않는다"를 넣는다.

## 삭제 조건

결정 1은 프로젝트를 마쳐 평가 프로토콜 점검을 하지 않으면 지운다. 결정 4는 worktree에 `data` 링크를 두지 않게 되면 지운다.
