# ADR-0101 사용자 수작업의 반복을 착수 전에 알리고, 생성 변경이 없으면 답변으로 검증하지 않는다

- 상태: 채택
- 날짜: 2026-11-05

## 맥락

S47 지시서와 확인 요청은 production까지의 토큰 입력만 보였고, 브랜치 주소마다 반복된다는 점은 구현과 확인이 끝난 뒤에 알렸다. 사용자는 "처음부터 토큰 입력이 반복된다고 안내했으면 이번 슬라이스 작업 자체가 없었을거야"라고 했다. 줄이는 안(북마크, production 한 번)을 권해도 사용자 작업이 남아 다시 지적받았다.

S48 완료 기준은 생성을 바꾸지 않았는데 미리보기와 production에 지어낸 질의를 하나씩 보내도록 잡았다. 사용자는 "생성 변경이 없으면 답변 출력으로 검증할 필요없을 것 같아"라고 했다.

`meet-rag` "화면 검증" 절에는 S48에서 없앤 Gradio 선택 칸 사례가 남아 있었다.

## 결정

- A1과 `docs/CLAUDE.md` SLICE 절: 사용자 수작업이 들어가는 조각은 지시서에 "사용자 작업"을 두어 언제, 몇 번, 무엇을 반복하는지 적고 확인 요청에도 적는다. 뒤 조각까지 반복되는 일도 센다
- "화면 검증" 대상 주소: 사용자에게 토큰 입력을 다시 요청하지 않는다. 다른 주소에 토큰이 필요하면 메인이 `aside repl` 스크립트로 옮기고, 값은 출력하지 않는다(사용자 허용 2026-11-05). 이 일 말고는 Aside가 브라우저 저장소를 읽지 않는다
- "화면 검증" 비용: 답변을 만들거나 보여 주는 경로가 바뀌지 않았으면 답변으로 검증하지 않고 연결과 질의 없는 API로 본다. 페이지의 답변 표시를 고치면 답변이 있어야 볼 수 있어 이 경로에 넣는다(메인 판단)
- "화면 검증" 자동화의 한계: Gradio 칸 이름을 빼고 한글 입력이 다를 수 있다는 규칙만 남긴다

훅으로 막지 않는다. 수작업 횟수와 경로 해당 여부는 코드로 판정할 수 없다. 빠진 정보는 사용자 확인에서 드러나지 않으므로(S47) 지시서 절로 두어 쓸 때 빠지지 않게 한다.

감수하는 것: 답변 경로를 바꾸지 않는 PR에서는 답변 문제가 잡히지 않는다. Aside 스크립트가 토큰 값을 다루므로 스크립트가 값을 출력하지 않는지는 메인이 지키고, 변수의 값이 Aside 쪽에 저장되는지는 확인하지 못했다.

## 결과

`.claude/skills/meet-rag/SKILL.md`의 A1과 "화면 검증" 절을 고쳤다. 입력→동작: S40 지시서는 사용자 작업 횟수를 적고, 화면 코드만 고친 PR은 질의 없이 연결과 문서 열람을 본다.

## 삭제 조건

토큰 코드를 지우는 S41에서 토큰 옮기기 문장을 지운다. 나머지는 사용자 작업 방식이 바뀌면 새 ADR로 바꾼다.
