# ADR-0036 Colab 연결 장애에 시간 제한·재시도와 복구 순서를 둔다

- 상태: 채택
- 날짜: 2026-10-13

## 맥락

EXP-009(L4)에서 `colab exec`(커널 웹소켓)가 응답 없이 40분 멈추고, "Connection was lost"가 반복됐다. `colab_job.py`는 호출에 시간 제한이 없어 멈춘 명령이 오류 없이 대기했다. 같은 시각 `colab console`(터미널)과 `colab upload`는 동작했다. 세션 하나는 404/401로 회수됐고, 새 VM에서는 실패한 `setup`을 확인하지 않고 업로드·실행으로 넘어가 다시 실패했다. colab-operator Recovery 절의 `colab restart-kernel`(커널만 재시작)과 `colab log`(회수 원인)도 쓰지 않았다. L4 약 115분 중 GPU를 쓴 시간은 약 20분이었다.

## 결정

- `colab_job.py`: colab 호출마다 시간 제한(기본 120초, 파일 전송 1,800초)을 두고, 시간 초과·연결 끊김이면 2번까지 다시 시도한다. VM 안 nohup 실행(`start_bg`), 결과 압축(`fetch`의 tar), `upload`의 gunzip처럼 두 번 실행하면 겹치거나 실패하는 명령은 재시도하지 않는다. `launch`가 실패하면 다시 띄우기 전에 `poll`로 이미 떴는지 확인한다. 실패 메시지에 다음 복구 순서를 적는다
- meet-rag 오류 처리: 재시도해도 실패하면 기다리지 않고 `colab restart-kernel` → 다시 시도 → `colab console`로 같은 셸 명령 순으로 복구한다. 파일 전송은 console로 하지 않는다(업로드 검사가 없다). `launch` 뒤 확인은 로그 첫 줄 `date` 시각으로 한다(`setup`과 로그 파일이 같다). `fetch`의 tar는 재시도하지 않는 대신 전송 시간 제한(1,800초)을 쓴다. 단계마다 성공 표시(`setup` 버전 줄, `upload` `wc` 줄, `launch` 진행 표시)를 확인한 뒤 다음 단계로 간다. `setup`은 저장소 폴더를 지우므로 실패한 `setup` 뒤 업로드를 먼저 하지 않는다. 세션이 회수되면 `colab sessions`와 `colab log`로 확인해 보고하고, `[?]`로 남은 할당은 사용자에게 웹 화면 종료를 요청한다

colab CLI 0.6.0 → 0.7.4 업데이트는 하지 않았다. 연결 문제가 고쳐졌는지 모르고, 스킬 본문(0.6.0 기준)을 함께 바꿔야 해 따로 검토한다.

## 결과

`.claude/skills/meet-rag/scripts/colab_job.py`, `test_colab_job.py`, `.claude/skills/meet-rag/SKILL.md` 오류 처리 절.

## 삭제 조건

colab CLI가 자체로 시간 제한·재연결을 하게 되거나, Colab 작업을 다른 실행 방식으로 옮길 때.
