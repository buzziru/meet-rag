# ADR-0020 multi-doc 검사 에이전트 multidoc-checker와 작업자 풀·중단·재개

- 상태: 채택
- 날짜: 2026-10-07
- 커밋: (PR 병합 후 기록)

## 맥락

S8 검사는 `rag.multidoc.check`가 OpenRouter `openai/gpt-6-luna`를 부르는 스크립트였다. PR #31 코멘트(D-14에 기록)에서 사용자는 생성·검사가 같은 계열일 때의 self-evaluation bias보다 검사 성능을 택해 검사를 Claude Code Sonnet 에이전트로 바꾸기로 했다. G3 갈린 5건 사람 검수에서 Sonnet이 3건, luna가 2건 맞았다. 코드 쪽 변경(검사 입력 준비, 에이전트 출력 판정, luna 경로 삭제)은 `docs/slices/08c-checker-agent.md`(`feat/s08-checker-agent` 브랜치)가 맡는다.

본 생성 검사는 약 740개 후보 집합에 동시 3개로 약 10시간 걸릴 것으로 본다(파일럿 비교에서 1개에 약 2.5분). 사용자는 생성·검사를 백그라운드로 돌리고, 중단을 지시하면 메인이 실행 중인 작업을 마무리한 뒤 멈추고, 새 세션에서 진행 상황을 확인해 이어 가기를 요구했다. 대기 항목 20(`_workspace/00_main_harness-pending.md`, 로컬 전용. 동시 실행 3개·최대 4개, 메인이 큐로 칸을 채움, 같은 에이전트 재사용 금지)도 이 운영 방식과 같은 내용이다. 파일럿 Sonnet 비교 때 6건을 묶은 에이전트가 conf-0012를 conf-0017로 오판했다.

## 결정

- 검사 에이전트 `multidoc-checker`(Sonnet, Read·Write, `omitClaudeMd`)를 둔다. 정의에는 읽기·쓰기 범위, 인용 원문 유지, 덮어쓰기 금지, 반환 형식만 두고, 할 일과 출력 형식은 검사 입력 안의 검사 지시(`check_vN`)가 정한다(ADR-0018과 같은 이유)
- 읽기는 `check_in`, 쓰기는 `check_out`만 훅으로 허용한다. 생성 출력(`gen_out`)을 보면 검사가 생성 쪽 답에 맞춰져 생성·검사를 나눈 의미가 없어진다. 훅(`multidoc_read_guard.py`)은 두 에이전트가 같이 쓰고, 에이전트 이름을 정의의 훅 명령 인자로 받는다. `agent_type`이 비면 인자의 에이전트로 본다(ADR-0019의 동작과 같다)
- 작업 단위는 검사 후보 집합 2개, 생성 10개다(사용자 결정). 생성은 개요만 읽고 원문은 정답 후보만 읽어 검사보다 가볍다
- 생성·검사는 작업자 풀로 돌린다. 백그라운드로 동시 3개(최대 4개), 메인이 큐를 들고 끝날 때마다 새 에이전트로 칸을 채우며 끝난 에이전트를 다시 쓰지 않는다. 팀으로 소통시키지 않는다. 일관성은 고정된 지시 파일과 코드 판정이 맡고, 소통하면 후보 집합 사이에 판단이 섞인다
- 메인은 작업 배정을 `_workspace/{작업}_queue.jsonl`에 남긴다. 남은 작업의 기준은 파일 상태(`check --dry-run`)이고 둘이 다르면 파일 상태를 따른다(사용자 결정). 큐만 믿으면 출력을 쓴 뒤 큐 갱신 전에 멈춘 작업이 다시 돌거나 빠진다
- 중단 지시를 받으면 새 작업을 띄우지 않고 실행 중인 작업이 끝나기를 기다린다. 에이전트를 강제로 멈추지 않는다(사용자 결정). 그다음 큐·진행 기록·STATUS "실행 중 작업"에 남은 수와 재개 절차를 적는다. 새 세션은 0단계에서 이를 보고 이어 간다. 세션이 비정상으로 끊긴 경우에만 큐의 `running`을 파일 상태로 정리하고, 쓰다 만 검사 출력은 판정 단계가 `rejected/`로 옮긴다

## 결과

`.claude/agents/multidoc-checker.md`(신규), `.claude/agents/multidoc-writer.md`(훅 명령 인자, 검사 모델·인용 대조 설명, description), `.claude/hooks/multidoc_read_guard.py`(두 에이전트 규칙), `.claude/skills/meet-rag/SKILL.md`(실행 모드, 에이전트 표, 작업자 풀·큐·중단·재개, 0단계, 테스트 시나리오), 이 ADR과 목록, 대기 항목 20 반영.

- 검증: 훅을 합성 입력 15건(검사 에이전트 허용 3·거부 6·다른 에이전트 통과 1, 생성 에이전트 허용 2·거부 2, 인자 누락 거부 1)과 손상된 입력 1건(거부)으로 시험했다. 두 에이전트 description은 서브에이전트로 트리거를 검증했다
- 에이전트 정의는 실행 중인 세션에 적용되지 않는다. 검사 에이전트는 병합 뒤 새 세션에서 처음 실행되고, S8c 파일럿 재검사가 그 실행이다
- 허용 경로는 `configs/config.yaml`의 `paths.multidoc_*`와 같아야 한다. `multidoc_check_in`·`multidoc_check_out`은 S8c 브랜치가 config에 더한다
- 중단은 실행 중인 작업을 마무리하므로 다시 하는 작업이 없다. 대신 중단 지시 뒤 멈추기까지 실행 중인 작업 시간(검사 2개 약 5분, 생성 10개 약 6.5\~19분)만큼 기다린다. 세션이 비정상으로 끊기면 끝내지 못한 후보 집합만 다시 맡긴다

## 삭제 조건

ADR-0017과 같다(G3 동결로 multi-doc 생성·검사를 끝낼 때).
