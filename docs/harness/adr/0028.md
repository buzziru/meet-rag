# ADR-0028 multi-doc 채점 모듈을 보호 경로에 추가

- 상태: 채택
- 날짜: 2026-10-08

## 맥락

S9 지시서와 PLAN은 S9 완료 뒤 `src/rag/eval_multi/`와 `multidoc.eval`(k 등 지표 설정)을 고치지 않는다고 적었지만, CLAUDE.md 금지 절과 `protocol-guard`·`protocol-auditor`·`pr-briefer`에는 들어 있지 않아 감사가 이 경로의 변경을 잡지 못했다(PR #45 리뷰 가이드, 사용자 코멘트).

## 결정

`src/rag/eval_multi/`와 `configs/config.yaml`의 `multidoc.eval` 키를 S9 완료 후 보호 경로로 둔다. CLAUDE.md 금지 절, `protocol-guard` P3과 description, `pr-briefer` R3에 넣고, `exp-judge`와 `exp-judgment`는 multi-doc 관찰도 저장소 모듈로 계산하고 고치지 않는다고 적고, meet-rag D5의 보호 경로 예시에 더한다. 이유는 채점이 바뀌면 EXP마다 보고하는 multi-doc 관찰을 기준선(D-16)과 비교할 수 없기 때문이다. `multidoc.eval`은 `configs/eval/` 밖에 있어 경로가 아니라 키 단위로 보호한다.

## 결과

CLAUDE.md, `.claude/skills/protocol-guard/SKILL.md`, `.claude/agents/pr-briefer.md`, `.claude/agents/exp-judge.md`, `.claude/skills/exp-judgment/SKILL.md`, `.claude/skills/meet-rag/SKILL.md` D5. S9 PR #45에 함께 들어간다(사용자 코멘트로 요청된 변경이라 F 흐름의 별도 브랜치로 나누지 않았다).

## 삭제 조건

multi-doc 관찰을 그만두거나, 채점 규칙을 바꾸기로 사용자가 정해 DECISIONS에 기록할 때.
