# ADR-0070 Orca worktree 삭제 뒤 남는 브랜치와 반영으로 지운 줄의 판단할 곳 표기

- 상태: 채택
- 날짜: 2026-10-28

## 맥락

이슈 #172(PR 일일 종합 2026-10-28)의 범위 밖 항목 두 개다.

- `git.md` main 맞추기 6은 `orca worktree rm`이 "폴더와 브랜치를 함께 지운다"고 적었다(2026-10-27 시험, ADR-0064). 2026-10-28 #170·#171 worktree를 `orca worktree rm`으로 지운 뒤에는 두 번 모두 규약 브랜치(`docs/gen-exp-order`, `chore/harness-gen-eval`)와 `buzziru/<이름>` 브랜치가 남아 `git branch -d`로 지웠다. 문구대로면 규약 브랜치가 남는 경우를 다루지 않는다
- PR 리뷰 반영 때 판단할 곳의 `file:line`은 반영 뒤 diff에 맞추는데(ADR-0066), 반영 커밋이 그 줄을 지운 경우 링크를 어디로 둘지 정하지 않았다(#165)

## 결정

- main 맞추기 6: `orca worktree rm`은 폴더를 지우고, 지운 뒤 규약 브랜치와 `buzziru/<이름>` 브랜치가 남아 있으면 둘 다 `git branch -d`로 지운다. 브랜치를 지우는지가 시험마다 달라 "남아 있으면"으로 적었다
- PR 절 5: 반영 커밋이 판단할 곳의 줄을 지웠으면 원래 `file:line`에 `(반영으로 삭제)`를 붙인다. 지운 줄은 머리에 적은 커밋의 diff에서 본다(사용자 결정 2026-10-28)

## 결과

`.claude/rules/git.md` main 맞추기 6, PR 절 5.

## 삭제 조건

Orca가 worktree 삭제 때 브랜치를 일관되게 지우거나 남기는 것이 확인되면 main 맞추기 6을 그 동작으로 고친다.
