# ADR-0042 착수 지시 전 구현 금지, D-31에 맞춘 전송 점검, 다운로드 중 세션 유지, wrap_up 뒤 반복 방지 훅

- 상태: 채택
- 날짜: 2026-10-15

## 맥락

- EXP-012에서 B1 초안의 결정 사항(BM25 함께 변경, Colab CLI 업데이트 선행)에만 답을 받고 이를 B2 승인으로 보아 구현과 로컬 확인을 시작했다(사용자 지적 2026-10-14). B2는 "승인 전에는 dev-small까지만 실행한다"여서 착수 전 구현을 막지 못했다
- D-31(2026-10-14)로 재배포 제한은 공개 금지로 좁혀졌고, 처리 목적의 외부 API·Colab 전송은 허용됐다. 하네스의 전송 점검(protocol-guard P6 "dev 질의만", D-07·D-10 인용)은 그 이전 기준이었다
- EXP-012 Colab에서 `colab download`(커널을 거치지 않음) 24분 동안 커널이 놀아 세션이 회수되고 full 인덱스를 잃었다(약 2.0 CU). 같은 회수에서 gzip 압축이 인덱스에 이득이 없고, worktree의 `data/` junction에 `tarfile` `filter='data'`가 풀기를 막았다
- wrap_up(next-step 상자) 뒤에 앞의 보고를 다시 쓰는 일이 한 세션에서 세 번 있었다(2026-10-15). 메모리로 막히지 않았고, 사용자는 하네스로 막기로 했다
- PR #77\~#85 사용자 코멘트: 예외 채택 EXP의 결론이 DECISIONS와 충돌(#83), 보고한 Colab 비용 초과는 허용(#78), 재지 않은 지연 추정으로 판단을 물음(#79)
- LangSmith 추적 규약(2026-10-15 사용자 지시)이 메모리에만 있었다

## 결정

- meet-rag B1·B2: 착수 지시를 받기 전에는 구현·dev-small도 하지 않는다. 결정 사항 답변은 착수 지시가 아니고, 끊긴 흐름을 이어 갈 때 진행 기록에서 착수 지시를 확인한다. 옛 "승인 전에는 dev-small까지만"을 대신한다
- D-31 정렬: protocol-guard P6을 "평가 질의의 외부 전송"으로 바꿔 test 질의 전송과 승인 없는 대량 전송만 본다. protocol-guard·protocol-auditor description, pr-briefer·slice-verifier·meet-rag E6의 근거 인용을 D-31로 고친다. `colab_job.py upload`의 dev 검사는 test를 막는 장치라 그대로 둔다
- `colab_job.py fetch`: 내려받는 동안 1분마다 짧은 exec로 커널을 깨운다(압축 exec와 겹치지 않게 다운로드 중에만). 무압축 tar, `--exclude`, `data/`의 실제 위치(junction 해석)에 풀기. 동작 테스트를 스크립트 옆에 둔다
- wrap_up 직후 PostToolUse 훅(`.claude/hooks/wrap_up_reminder.py`)이 맥락에 규칙을 넣는다. 질문이 있으면 턴을 끝내고 텍스트를 쓰지 않는다, 없으면 상자와 앞 메시지에 없는 내용만 쓴다. Stop 훅은 이미 출력한 텍스트를 되돌리지 못하고 차단하면 텍스트가 더 나와 쓰지 않는다(사용자 선택)
- meet-rag B6: 예외 채택 여부는 판정 뒤 사용자가 정하고, 예외 채택한 EXP의 결론은 SPEC 판정·예외 근거·사용자 결정을 순서대로 적는다. E3: 예상을 넘을 것 같으면 그 시점에 알리고, 알린 초과는 PR에서 다시 묻지 않는다. "질문과 해석": 영향 주장에는 잰 값을 붙인다
- 구현 원칙에 LangSmith 추적 규약을 옮기고 메모리에서 지운다

넣지 않은 것: 새 세션 직후 setup 시간 초과에 restart-kernel 기본화, 1GB 넘는 산출물의 Drive 경유. 한 번 관찰된 문제라 장치를 더하지 않고 관찰한다. PR #80(BM25 청크 방침)·#84(B안 변형 지시) 코멘트는 그 PR의 내용 판단이라 넣지 않았다.
