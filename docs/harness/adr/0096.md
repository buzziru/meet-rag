# ADR-0096 새 결정 번호는 쓰기 직전에 origin/main에서 정한다

- 상태: 채택
- 날짜: 2026-11-05

## 맥락

생성 실험과 배포를 병행하자 D 번호가 두 번 겹쳤다.

- PR #221(S39): 결정을 쓸 때는 main에 같은 번호가 없었다. PR #220이 먼저 병합되어 main을 병합할 때 D-84로 옮겼다(b94be2f, 14:37)
- PR #222(S44): PR #221이 14:40에 D-84를 병합했는데 14:51에 같은 번호를 썼다(57cab8c). 브랜치의 DECISIONS만 봤고, `protocol-auditor`에서야 찾아 D-85·D-86으로 옮겼다(ce81806)

두 경우가 다르다. S44는 쓸 때 origin/main을 봤으면 겹치지 않았다. S39는 상대가 아직 병합되지 않아 봐도 몰랐고, main을 병합하는 단계에서 알았다.

## 결정

`docs/CLAUDE.md` DECISIONS 절에 한 줄을 둔다. 새 번호는 쓰기 직전에 fetch한 origin/main의 마지막 번호 다음으로 정하고, 겹치면 나중에 병합하는 PR이 번호와 자기 참조를 옮긴다.

번호를 미리 잡는 예약 기록이나 훅은 두지 않는다. 미병합 PR끼리 겹치는 경우는 main을 병합하는 단계와 감사에서 드러나고, 옮기는 일은 그 PR의 참조만 바꾸면 끝나 예약 장치의 운영 비용보다 작다.

감수하는 것: 미병합 PR끼리는 계속 겹칠 수 있다.

## 결과

입력→동작: 브랜치의 마지막 결정이 D-83이고 origin/main에는 D-84까지 있으면 새 결정은 D-85로 쓴다. 다른 세션의 열린 PR도 D-85를 쓰고 있으면 그쪽이 먼저 병합된 뒤 main을 병합하는 쪽이 D-86으로 옮긴다.

## 삭제 조건

세션을 병행하지 않게 되면 그 줄을 지운다.
