# ADR-0065 메타데이터 가설 판정을 S18 함수 결과로 하고 D-35 예외 검토 대상을 보고

- 상태: 채택
- 날짜: 2026-10-27

## 맥락

S18(PR #129, D-43)이 SPEC "메타데이터 가설의 판정"을 함수(`rag.eval.bootstrap.metadata_verdict`)로 두고, `rag.eval_multi.compare --single <single-doc 비교 결과 JSON>`이 `metadata_verdict`를 내게 했다. 명령은 single-doc 결과의 형식·같은 실험의 짝·지금 `min_gain`으로 다시 판정한 값을 확인하고 어긋나면 멈춘다(`check_single`, `metadata_result`). S18 범위 밖으로 하네스 반영을 미뤘고, 그 전까지 exp-judge는 3절 표를 손으로 적용했다. 손으로 적용하면 다른 실험의 결과나 옛 기준의 결과를 넣어도 판정이 나온다(S18 `--single` 짝 미확인 지적).

D-35는 +1.0%p를 사람 판단 없이 채택하는 선으로 해석했고, 메타데이터 가설의 multi-doc 단계에도 같게 적용했다(사용자 결정 2026-10-21, 이슈 #120). 판정 함수는 채택·기각·보류만 내고, +1.0%p 미만이고 하한 > 0인 보류는 판정 보고에서 예외 검토 대상으로 적기로 했다. `exp-judgment`에는 이 해석이 없었다.

PLAN "하네스 반영" 항목은 이 둘을 생성 EXP 판정 갈래와 함께 묶었다. 생성 갈래는 SPEC 생성 평가 개정 뒤로 남기고 이 둘만 먼저 반영한다(메인 세션 지시 2026-10-27).

## 결정

- `exp-judgment` 2절: 메타데이터 가설이면 메인이 준 single-doc 비교 결과 JSON으로 `rag.eval_multi.compare --single`을 돌리고 `metadata_verdict`를 판정으로 쓴다. 명령이 멈추면 판정하지 않고 보고한다. `metadata_result`를 직접 부르면 `check_single`을 먼저 부른다(PR #129, 사용자 결정 2026-10-21). 표를 손으로 적용해 판정을 대신하지 않는다
- `exp-judgment` 3절: 표는 함수 판정의 요약으로 둔다. multi-doc 단계 보류 중 Recall@5 +1.0%p 미만이고 하한 > 0이면 결론에 "예외 검토 대상(D-35)"으로 적고, 예외 여부는 사용자가 정한다
- `exp-judge`: 위 두 원칙을 작업 원칙에 한 줄로 두고, 입력에 single-doc 비교 결과 JSON을 더한다(없으면 판정하지 않고 보고). judge는 파일을 쓰지 않으므로 JSON은 메인이 만든다
- meet-rag B4: 메타데이터 가설이면 judge 프롬프트에 single-doc 비교 결과 JSON 경로를 넣는다

## 결과

`.claude/skills/exp-judgment/SKILL.md`(2·3절), `.claude/agents/exp-judge.md`, `.claude/skills/meet-rag/SKILL.md`(B4). ADR-0029의 메타데이터 판정 표와 SPEC 우선 원칙은 그대로다. 생성 EXP 판정 갈래는 이 ADR에 없다.

## 삭제 조건

SPEC "메타데이터 가설의 판정" 절이나 D-35 해석이 바뀌거나, `rag.eval_multi.compare --single`의 인자·출력이 바뀌면 세 곳을 함께 고친다.
