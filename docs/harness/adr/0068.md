# ADR-0068 비밀 값을 `.env` 대신 Doppler에서 받고 노트북 커널을 `doppler run`으로 띄움

- 상태: 채택
- 날짜: 2026-10-27

## 맥락

사용자가 `.env`의 값을 Doppler(project `meet-rag`, config `dev`)로 옮겼고, 이제부터 `.env` 대신 Doppler를 쓰기로 했다(2026-10-27). 실행 코드는 `rag.index`가 import될 때 `load_dotenv(ROOT / ".env")`로 API 키와 `HF_HOME`을 읽었다. 노트북 지속 커널(`nb_kernel.py`)은 `start`를 띄운 프로세스의 환경을 물려받으므로, 커널을 Doppler 없이 띄우면 노트북 셀에 키와 `HF_HOME`이 없다.

## 결정

- 실행은 `doppler run -- uv run python -m …`으로 한다. 저장소 디렉터리는 `doppler setup`으로 `meet-rag`/`dev`에 연결해 두었고(사용자 홈의 Doppler 설정, 저장소에 남지 않음), 하위 worktree에도 적용된다
- 노트북 규약 §8과 `nb_kernel.py` 사용법: `start`를 `doppler run --`으로 띄운다. `run`·`stop`은 커널과 통신만 하므로 붙이지 않는다
- `rag.index`의 `load_dotenv`를 지운다. `.env` 파일은 남기지만 실행 코드가 읽지 않는다
- `doppler run`을 빠뜨려 환경 변수가 없으면 원인과 조치를 적고 멈춘다(사용자 결정 2026-10-27, PR #168 리뷰). API 키는 `rag.index.require_env`로 읽고(생성, judge, 재작성, Jev), `HF_HOME`은 모델을 받는 단일 경로인 `pinned`에서 확인한다. `HF_HOME`이 없으면 오류 없이 기본 캐시에 모델을 다시 받기 때문이다. Claude는 이 오류를 보면 사용자에게 알리고 `doppler run --`으로 다시 실행한다(CLAUDE.md 비밀 값 줄). Colab VM은 Doppler를 쓰지 않으므로 `colab_job.py launch`가 `HF_HOME`을 HF 기본 캐시 위치로 넘겨 전과 같은 곳에 받는다
- Colab VM에는 키를 보내지 않는다. API 호출은 로컬에서 하고 VM은 GPU 계산만 하며, `colab_job.py`는 `doppler run` 없이 띄운다(로컬 `colab` CLI에 환경 변수 전체가 넘어감). 키가 필요해지면 Colab 보안 비밀(`google.colab.userdata`)로 시도하되, CLI로 만든 세션에서 되는지 먼저 웹 자료와 실험으로 확인한다. 실행 코드에 키를 넣는 방식은 쓰지 않는다(실행 기록에 남고 `outputs/`는 공개된다). 서비스 토큰·임시 파일 업로드는 고르지 않았다(사용자 결정 2026-10-27, PR #168 대화)
- 기존 `.env`를 쓰던 다른 코드(`rag.multidoc.check`, 지난 노트북)는 고치지 않고 감사 대상도 아니다(사용자 지시). 그래서 `python-dotenv` 의존성은 남긴다

## 결과

`.claude/rules/notebook.md`(§8), `.claude/skills/meet-rag/scripts/nb_kernel.py`(사용법 docstring), `.claude/skills/meet-rag/references/colab.md`(비밀 값), `.claude/skills/meet-rag/scripts/colab_job.py`(launch의 HF_HOME), CLAUDE.md "명령"의 비밀 값 줄, `src/rag/index.py`(`require_env`, `pinned`), `src/rag/generate.py`·`gen_eval/judge.py`·`rewrite.py`·`rerank.py`. `.env` 커밋 금지와 `colab_job.py`의 `.env` 업로드 차단은 `.env`가 남아 있어 그대로 둔다.

## 삭제 조건

비밀 값 관리를 Doppler에서 다른 방식으로 바꾸면 함께 고친다.
