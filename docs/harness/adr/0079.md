# ADR-0079 정합 점검에 SPEC을 넣고 SPEC에는 현재 규칙만 둔다

- 상태: 채택
- 날짜: 2026-11-03

## 맥락

- 생성 단계 test 전에 SPEC을 결정·코드와 대조하니 끝난 절차가 남은 일로 읽히거나 검색 규칙이 생성에도 걸리는 것으로 읽히는 줄이 30곳 넘게 나왔다(D-65). 정합 점검(ADR-0071)은 `DECISIONS.md`만 훑고 SPEC은 대조 상대로만 썼다
- D-63은 SPEC을 고치는 범위를 줄로 적지 않아 `:82`, `:99`가 지난 채 남았다(PR #190에서 고침)

## 결정

`docs/CLAUDE.md`에 세 가지를 더한다(사용자 동의 2026-11-03).

- 정합 점검: 같은 때 `SPEC.md`도 줄마다 결정·코드와 대조한다. 읽기 전용 에이전트 둘에 맡긴다
- DECISIONS "바뀌는 것": SPEC 규칙이나 SPEC이 적은 상태가 바뀌면 SPEC의 해당 절도 적는다
- SPEC 절: 현재 규칙만 쓰고, 끝난 절차는 지우고 결정 번호로 가리킨다

감사 항목(P12)과 훅은 더하지 않는다. 표현이 다른 충돌은 grep으로 잡히지 않아 점검이 맡는다.

## 결과

`docs/CLAUDE.md`(DECISIONS 절, SPEC 절, 정합 점검 절)에 반영했다. 생성 단계 test 전과 프로젝트 마무리 전에 에이전트 둘, 각 약 5분이 더 든다.

## 삭제 조건

점검에서 지적이 이어서 나오지 않거나, SPEC을 더 고치지 않게 되면(프로젝트 마무리) 지운다.
