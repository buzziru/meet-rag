# ADR-0053 병합 뒤 코멘트 확인, PR 답글 범위, PR 범위 유지, 판단 근거, 검수 출처

- 상태: 채택
- 날짜: 2026-10-20

## 맥락

마지막 하네스 PR(#86) 뒤 병합된 PR #87\~#114의 사용자 코멘트와 대기 목록에서 모은 작업 방식 지적이다.

- 사용자는 병합 직전에 단 코멘트를 후속 PR에서 반영할 것으로 보고 병합한다(사용자 설명 2026-10-20). 그런 코멘트가 6번 있었고 #89·#94·#101·#102·#111은 후속 PR에서 처리됐지만, #92("SPEC 문서를 결정에 맞춰 수정")는 처리되지 않았다
- #106 부분 거부 코멘트를 STATUS로만 미루고 PR 답글을 달지 않았다. git.md PR 절 4는 코멘트를 반영한 커밋만 다뤘다
- #106이 리뷰 중 judge 실험·사람 검수로 커져 31커밋·30파일·약 22시간 열렸다
- #106 판단할 곳에서 경계값을 근거 없이 물었고 사례를 요청받았다. #99에서는 SPEC에 초안을 두지 말고 별도 문서에 두라고 했다
- 사용자가 앱 설정 "풀 리퀘스트 자동 수정"을 켰다(2026-10-20). 하네스에는 감시가 켜졌는지 확인하는 단계만 둔다(사용자 결정)
- S14 검수에서 Claude가 사용자 기준으로 채운 행을 사람 판정과 구분해야 했다
- Bash heredoc 안 Python으로 이스케이프가 든 문자열을 넣다 파일이 깨졌다(S14 2회, 이번 작업 1회)

## 결정

- git.md "main 맞추기" 5: 지운 브랜치의 PR마다 답글·반영이 없는 사용자 코멘트를 후속 작업으로 기록하고 알린다. 병합 전에 코멘트를 확인하는 단계는 두지 않는다
- git.md PR 4: PR을 만든 뒤 `ccd_pr get_status`로 연결과 `auto_fix`를 확인한다. PR 5: 코멘트·대화 지시로 커밋했거나 미룬 것은 모두 PR 답글로 남긴다
- 스킬 "결정과 PR의 순서": 리뷰 중 새 설계·실험은 후속 PR로 나누고 Draft PR은 쓰지 않는다. 승인 문서는 `docs/drafts/`에서 고친 뒤 옮긴다
- 스킬 "질문과 해석": 사용자에게 묻는 판단에는 선택지별 차이와 사례를 붙인다
- 스킬 D3: Claude가 채운 검수 행은 출처 열을 두고 사람 판정에서 뺀다
- 스킬 오류 처리: 이스케이프가 든 문자열은 Edit 도구로 넣는다
