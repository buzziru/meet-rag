# ADR-0064 실행 환경 Orca에 맞춰 PR 연결 확인, 하위 세션 띄우기, worktree 정리, 브랜치 이름을 고침

- 상태: 일부 대체(→ 0070, Orca worktree 삭제 뒤 브랜치)
- 날짜: 2026-10-27

## 맥락

실행 환경이 Claude 앱 Code 탭에서 Orca(stablyai/orca 1.4.242 안의 Claude Code)로 바뀌었다(2026-10-27). 하네스 네 곳이 데스크톱 앱 도구나 앱의 worktree 방식을 전제했다.

- git.md PR 절 4: PR을 만든 뒤 `ccd_pr get_status`·`bind_pr`로 세션 연결과 `auto_fix`를 확인한다(ADR-0053). Orca 세션에는 이 도구가 없고 PR 연결·CI 알림 기능도 없다(확인함)
- meet-rag 스킬 "공유 `data/`와 위임": 하위 세션을 띄우는 도구로 `start_session`만 적었다. Orca에서는 `orca orchestration worker-start --worktree new-child --agent claude`로 띄운다
- git.md main 맞추기 6: Orca가 만든 worktree는 `.claude/worktrees/<이름>`에 생기고 브랜치는 `buzziru/<이름>`이다(사용자 설정 2026-10-27: Worktree Location `.claude/worktrees`, Nest Workspaces 끔). `orca worktree rm --worktree path:<경로> --json`은 폴더와 브랜치를 함께 지우고 몇 초 뒤 반영된다(시험 확인함).
- git.md 브랜치 규약: Orca가 붙이는 `buzziru/<이름>`은 규약 접두사(`feat/`·`exp/`·`docs/`·`fix/`·`chore/`)가 없는 이름이다(사용자 지적 2026-10-27)

## 결정

- git.md PR 4: `ccd_pr` 확인은 Claude 앱에서 PR을 만든 경우에만 한다. Orca에서는 이 단계를 하지 않고 사용자 리뷰는 PR 5처럼 대화로 받는다. 새 알림 장치는 만들지 않는다
- 스킬 위임 문구에 Orca의 하위 세션 띄우기 명령을 더한다. 위임 지시에 `data/` 규칙을 넣는다는 기존 문구는 그대로 둔다
- git.md main 맞추기 6: Orca가 만든 worktree는 기존 확인(미커밋 변경, 링크 먼저 확인·링크만 삭제, `_workspace/` 기록을 옮긴 뒤 다른 명령에서 삭제)을 마친 뒤 `orca worktree rm`으로 지운다. 확인 순서는 바꾸지 않는다. 지운 뒤 `buzziru/<이름>` 브랜치가 남아 있으면 `git branch -d`로 지운다
- git.md 세션 시작: Orca가 만든 worktree에서는 작업 전에 최신 `main`에서 규약 이름의 브랜치를 새로 만들어 옮긴다. 이 PR의 작업(`buzziru/harness-orca-meta` → `chore/harness-orca-meta`)이 그 예다

## 결과

`.claude/rules/git.md`(세션 시작, PR 4, main 맞추기 6), `.claude/skills/meet-rag/SKILL.md`(공유 `data/`와 위임). ADR-0053의 git.md PR 4 항목은 Claude 앱에서만 적용하도록 이 ADR로 일부 대체된다.

`data_delete_guard` 훅은 `git worktree remove`와 재귀 삭제만 검사해, `orca worktree rm`은 링크 검사(ADR-0058)와 `_workspace/` 검사(ADR-0062)가 둘 다 걸리지 않았다(감사에서 코드로 확인). 사용자 지시로 실험했다(2026-10-27, 가짜 대상, PR #163 댓글): 시험 worktree 안에 scratchpad 폴더로 가는 junction을 두고 `orca worktree rm --worktree path:<경로>`를 실행하면 git이 링크 너머 파일을 추적하지 않는 파일로 보고 거부했고, `--force`를 붙이면 대상 폴더 안의 파일까지 지웠다. 2026-10-22 사고와 같은 동작이라, 사용자 결정(PR #163 리뷰)으로 훅이 `orca worktree rm`을 `git worktree remove`와 같이 검사하게 했다(`--force`와 관계없이 링크·`_workspace/` 기록이 있으면 막음, 대상이 `path:`가 아닌 선택자면 확인을 띄움). 사이드바의 Force Delete는 훅이 볼 수 없어 git.md 6에 링크를 지우기 전에는 쓰지 않는다고 적었다. 바뀐 파일에 `.claude/hooks/data_delete_guard.py`·`test_data_delete_guard.py`를 더한다.

## 삭제 조건

실행 환경을 Orca에서 다른 도구로 바꾸면 이 ADR의 네 곳을 그 환경에 맞춰 다시 고친다. Orca가 PR 연결이나 CI 알림 기능을 제공하면 PR 4를 다시 정한다.
